# 2026-08-29 — A stacked PR now tells its child where it stops

- **Every planned PR carries a PRD and a changeset.** A `pr-stack` child was handed its node's title and description and nothing else — not the code-discovery map, not the shape of the stack, and not where its PR ends and its neighbours' begin. A fourth goal, `write-stack-docs`, now authors a document pair per node into `artifacts/prs/<node_id>/` between planning and the operator loop. See [pr-stack-docs.md](../pr-stack-docs.md).
- **The changeset is what prevents duplicate work.** `## Dependencies` names, per parent, *what that PR delivers that this one consumes*, so a child knows which surfaces are somebody else's to create; `## Draft PR contract` names the API surface plus its failing tests, enough to open a draft PR against so dependents need not wait for the whole implementation. All four sections are required as headings and a submit missing one is refused, writing nothing — whether the boundaries are *correct* stays prompt-carried, since judging that needs the diff the node has yet to produce.
- **A child is spawned holding them.** Both the agent's `pr_spawn_child` and the web Start-session dialog attach the node's pair plus the shared plan and exploration map **by reference** to the orchestrator's session and host, so a cross-host stack copies nothing up front; the dialog shows them as ordinary removable rows. A document that does not exist yet is skipped rather than failing the spawn, because starting a node early is sometimes correct.
- ⚠️ **Behaviour change: `StackPlanned` now routes to `write-stack-docs`**, and a new `StackDocsWritten` routes on to `orchestrate`. A **seeded** stack starts at `StackDocsWritten` — its node is bound to a session whose work already exists, so a retroactive PRD would document a decision nobody is about to make.
- **`stack-plan.yaml` and `pr-stack-plan.md` moved under `artifacts/`.** They were written to the session root, where no wire reader looks: both reported `exists: false` in `context_docs` and could not be referenced as host documents at all. Older sessions keep working through the context header's existing root fallback, so nothing needs migrating.
- **`write-stack-docs` is a registered goal, and its prompt is pinned to its schema.** It shipped with no schema and a prompt asking the agent for YAML, while `tddy-tools submit` parses JSON — so an agent following it was refused before the hook ran, and every test drove the hook directly and never the CLI. Following the pattern [#411] set for `write-stack-plan`, it now has a proto, a schema and a `goals.json` entry, and a contract test pushes the prompt's own fenced example through the real `submit`, so prompt and contract cannot drift apart again.
