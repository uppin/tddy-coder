# 2026-08-30 — A planned PR started on another host stops disappearing from its own stack

- **Starting a planned PR's session on a different daemon than its orchestrator no longer loses the node.** The row went back to offering **Start session** for work already running, every descendant became unspawnable, and the node's GitHub PR never appeared. Three independent false negatives produced that one symptom.
- **The node link is now an RPC, routed to the daemon that owns the orchestrator.** It used to be a local disk write on the *spawning* daemon's sessions tree, where an orchestrator one host over simply does not exist — so the write was skipped, the node kept no branch, and `Stack::base_ref_for_spawn` refused everything below it. `LinkStackNode` is the write half of `ResolveStackBase` and routes the same way. A failed link is logged rather than failing a spawn whose worktree, branch and session already exist.
- **The link is keyed on the planned node's id, never re-derived from the branch.** The operator can rename the branch in the create dialog before confirming, and a daemon that does not hold the orchestrator cannot look the node up at all — so `StartSession` and `ResolveStackBase` both carry `stack_node_id` now.
- **The node records the branch that exists.** A name collision makes git's worktree helper append `-1`, so the requested name is not always the child's; the branch is read back from the session's changeset before it reaches the node or the metadata block. Without that, a node could record `feature/x` while its child worked `feature/x-1`, leaving every descendant based on a ref that does not exist.
- **A session's participant metadata carries its stack association** — its orchestrator, its planned node and its branch — and a `claude-cli` session publishes that block at all now, re-sent every 30 seconds so one failed publish cannot cost it the association. Presence is the only signal that crosses a host boundary: `ListSessions` answers for one daemon's own sessions tree.
- **A planned PR with no session shows its PR.** A node that owns no branch is polled on its planned name, and **only** that answer's PR leg is read — a suggestion is a planned name, not a ref, so nothing else it returns may reach the base line, the blockers or the branch line.
- ⚠️ **Both hosts must be upgraded.** A peer running an older daemon has no `LinkStackNode`; the call fails, the failure is logged, and the result is the pre-fix behaviour rather than a crash.
- ⚠️ **Cursor-cli children were never linked to their planned node at all**, on any host. They are now. A *sandboxed* cursor-cli child still is not — logged under Future Enhancements in `docs/dev/TODO.md`.
