# 2026-09-05 — Sandboxed codebase mode: the jail holds the code, the agent runs on the host

- **`tddy-sandbox-app --codebase-mode sandboxed`** inverts the placement the other two modes share. Claude Code runs on the host as an ordinary child — real terminal, the user's own `~/.claude`, real network — while the checkout and every build, test and tool call against it run inside a Seatbelt jail. Feature [sandboxed-codebase-mode.md](../sandboxed-codebase-mode.md).
- **The agent keeps its jailed tool surface and loses every native route to the checkout.** `Read`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `Grep`, `Glob`, `Bash`, `BashOutput` and `KillShell` are withdrawn; the `mcp__tddy-tools__*` forms are the only way in, and each call is executed inside the jail.
- **The untrusted checkout cannot make the host run anything.** `--strict-mcp-config` ignores a repository's own `.mcp.json`, and `--setting-sources user` stops its `.claude/settings.json` — and the hooks it can declare — from loading. Neither is a tool, so neither is reachable by withdrawing tools. What remains is `CLAUDE.md` reaching the model as instructions, stated plainly in the feature doc rather than claimed away.
- **A jailed build has network, through the host.** The jail's CONNECT shim relays outbound connections while TLS stays end-to-end, so `cargo` and `bun` fetch without the jail holding a route of its own.
- **Dependency caches survive the session.** Each repository gets a persistent jail `$HOME` at `~/.tddy/sandbox-codebase-home/<repo-key>`, keyed per repository so one repository's build cannot leave a `~/.cargo/config.toml` for the next repository's build to execute. `--codebase-home-dir` / `TDDY_SANDBOX_CODEBASE_HOME` moves the base.
- **Combinations that cannot hold are refused by name**, not silently dropped: `--agent-kind cursor` (its tool surface is not withdrawable), specialized agents (their roster is seeded into an in-jail MCP server this mode does not run), `--cwd`, `--codebase-home-dir` in any other mode, and Linux, where the app cannot provision the jail itself.
- **macOS only.** The Linux daemon-assisted path refuses the mode rather than half-serving it.
