# 2026-08-30 — Force start, and a planned PR that keeps track of its session across hosts

- **A blocked planned PR can be started anyway.** The Start-session button is no longer disabled; it takes a warning colour with an alert icon and a tooltip naming every blocker, and the row keeps its warning box. Two of the three blockers are derived from facts only the queried daemon can see — a branch pushed from another host reads as absent from `origin` until this clone fetches — so a gate that cannot see half the fleet must advise, not refuse. The daemon still enforces its own gate, and fails an impossible spawn with the real reason.
- **A blocked node sends no base branch.** The dialog used to pre-select the project default and submit it, which outranks the daemon's own chain resolution — so a force start could cut a child from the default branch for a node whose parent owns no branch. It now sends nothing and names nothing, leaving the decision where it belongs.
- **The PR-Stack view finds a child session on any host.** It joins a planned node to its session over common-room presence rather than one host's session list, adopting a live cross-host child's branch and session id onto a node whose own host never got to record them — which also unblocks that node's descendants.
- **A node whose child is alive elsewhere is no longer reported as orphaned.** Only the identity evidence — the node id a participant publishes, or the session the plan records — suppresses that verdict; "some session owns this branch" does not, because it would mask a genuinely deleted child whose branch another session picked up.
- **A planned PR shows its GitHub PR even with no session and no branch**, resolved from its planned branch name. Only the PR is read from that answer, and only when the poll actually asked as a planned name — so a suggestion colliding with another node's real branch cannot render that node's PR as this row's.
- **A cross-host session row in the drawer now carries its branch and its orchestrator**, so it files under its orchestrator in the stack grouping and can promote an idle orchestrator into the **Active** partition.
