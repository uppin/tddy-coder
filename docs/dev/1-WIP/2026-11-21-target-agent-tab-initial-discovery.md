## Exploration 2 — draft-PR contract (pass 2, 2026-11-21)

Read on top of n6's contract (`3845d5f75`) and n7's (`3c6bde258`), after rebasing onto `sandbox-agent-tab`.

- **n6's surface takes an agent variant without a signature change.** `TargetTab { shell, worktree, session_dir }` already says everything a launch needs about *where*; what an agent tab runs is a new value of n8's, `TargetAgentTab { kind, argv, env }`, so the agent launch is a sibling function, `launch_agent_tab_on_target(manager, session_id, terminal_id, TargetTab, &TargetAgentTab)`, not a widened `launch_tab_on_target`. Its green shares n6's private `client_command` and n6's `spawn_rendered_client_tab` (`ClientTab.kind` already carries the tab's kind, so an agent tab registers under its harness); the remote command is `target_agent_one_shot(worktree, argv, env)` (`cd '<wt>' && <target_login_exec>`), no pid file.
- **Each n8 path sits ahead of n6's todo instead of inside it**, as n7 did over n5: `from_wrapped_request` sends `target` around an `Agent` kind to `on_target_agent` (n8 todo) before n6's `on_target`; `restore_plan` matches `TARGET_KIND if wraps_an_agent(entry)` → `target_agent_plan` (n8 todo) ahead of `target_plan`; `TerminalRoster::start` routes `TargetAgent` to `start_target_agent_tab` (n8 todo) beside n6's `TargetShell` branch. So every n8 test fails on n8's own todo today; the acceptance tests then need n6's `spawn_rendered_client_tab` and menu groups green (recorded in the changeset's `## Dependencies`).
- **The bare command comes from the registry, not from `resolve`.** `HostCodingAgents::resolve` searches this host and refuses what it does not find (that is the todo's whole problem). The tab reads the spec's `binary.command` from `coding_agents.registry()` and the base set from `coding_agents.agents().agent_env_base()`; `ConversationStart` takes the spec, `binary` (meaningless when `target` is set) and `ConversationTarget { shell, command }`. Unit tests prove the argv on a `ToolHost` where nothing resolves.
- **A tab's environment is not a host tab's.** A host agent tab inherits the daemon's environment; on a target, `target_login_exec` starts from `env -i`, so the tab must carry its spec's `run.env` (claude's `CLAUDE_CODE_NO_FLICKER=1`) and its `pass_env` values in the command. Pinned by `a_target_agent_tab_carries_its_specs_run_environment`.
- **`write_rendered_session_files` is the main's.** It is `pub(super)` over `RemoteLaunch`, the main's struct; a tab's argv (rendered from `session_id` / `chat_id` only) names no session file today, but the rule "no host path reaches the target" is the tab's too. Sharing it (over `shell` + `worktree` + `session_dir`) is left to the green; `a_target_agent_tab_hands_the_target_no_host_path` pins the outcome — the one interactive command names neither the session directory nor the host's agent, and every file written is under the worktree's `.tddy/`.
- **Three n6 tests assert the opposite of n8, and n8 deletes them**: `terminal_kind_target_wrapper_unit::an_agent_wrapped_in_target_is_refused_naming_the_agent`, `restore_tabs_target_tests::an_agent_recorded_on_a_target_is_dropped_naming_the_agent`, and lifecycle `target_shell_tab_acceptance::a_target_wrapper_around_an_agent_is_refused` (replaced by a new lifecycle suite, `target_agent_tab_acceptance`, whose one test records `[target, agent]`).
- **n6's lifecycle fake target needed an agent.** Its login shell answered only `-l` (`exit 64` otherwise); an agent tab's launch runs `$SHELL -lc '<command>'`. The fixture's login shell now answers `-lc` with the machine's own `opt/agents` first on `PATH`, and `installs_the_agent` / `agent_run` put and read a recording stand-in there — additive, n6's tests unaffected. The tddy-agent-launch suite uses the shared `remote_target::StandInSshTarget` (no new fixture copy, todo 2026-11-16), wrapping its `SshShell` in a recording `RemoteShell` to read the command and the files handed to the target.
- **The participant arm is implemented, not left as a todo**: `TerminalKind::TargetAgent` forced it in tddy-coder's participant roster; it refuses `FAILED_PRECONDITION` naming the agent, as n6 and n7 did for their kinds.
- **Cursor's `--trust` on a target tab is not pinned.** The main renders `on_target` (Cursor's workspace-trust dialog on a fresh clone); a tab runs on a clone its main has already opened. The cursor tests assert the argv's first three words only; whether a tab binds `on_target` is the green's call.
