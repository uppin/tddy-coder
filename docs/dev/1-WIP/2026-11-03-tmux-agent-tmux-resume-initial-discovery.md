Exploration 1 below is the full whole-work discovery of the `#tmux-agent` stack, copied at planning time. Node-specific passes are appended as later `## Exploration N` sections.

## Combined conclusions

1. **Create options** flow `StartSessionRequest` (session.proto :496, highest field 46, reserved 19–23) → `start_session_on_request` (tddy-agent-launch `svc_start_session_core.rs:64`), dispatching claude-cli (:380), cursor-cli (:417), generic harness (:458 → `start_cli_harness`). `sandbox` is the model for a per-type boolean: web `useCreateSessionPlacement.ts:32`, `CreateSessionPermissionFields.tsx:89-93`, `createSessionRequest.ts` per-type branches (opencode/muse/warp clear it).
2. **Persistence:** `SessionMetadata` is `deny_unknown_fields` (an older binary refuses a file with a new field); ~12 production struct literals; base `starting_session_metadata` (tddy-session-split `service_util.rs:79`).
3. **Launch:** claude `spawn_claude_cli_session_inner` (claude_cli_spawn.rs:53) → `start_with_options(.., Some(os_user))`, records main capture + pid + LiveKit exposure; cursor `start_cursor` spawns as the DAEMON user (os_user None); generic `launch_cli_harness` with exit hook (warp resume token) as os_user. All reach `spawn_tool` → `PtySpawnSpec{argv, env, os_user}` → `pty_runtime` (setpriv drop).
4. **Resume:** `resume_session_at_session_coordinate` dispatches per type; no "already running" guard; claude resume runs as the daemon user (os_user None); warp resume needs `harness_resume_token` parsed from the terminal at exit.
5. **Terminate:** SignalSession/DeleteSession act on `metadata.pid` via `kill`; task cancel signals the PTY child; daemon shutdown `kill_all` SIGTERM→SIGKILL every PTY child.
6. **Liveness** = `metadata.pid` alive (`session_reader.rs:83`); pid is always the PTY child — with tmux it would be the tmux CLIENT, so is_active/Signal/Delete would act on the client, not the agent.
7. **Reusable tmux code** (`svc_terminal_ports/tmux_host.rs`) is `pub(super)` in tddy-session-lifecycle, which depends on tddy-agent-launch → agent-launch cannot use it without moving it down (tddy-cli-sessions / tddy-terminal-rpc are already agent-launch deps).
8. **Hooks that assume harness == PTY child:** exit hook + warp token (fires on client exit; pane output may be gone), main capture recording (ends at client exit; must re-register on re-attach), main-exit cleanup drops the managed-workflow toolcall socket + LiveKit exposure (wrong on a mere client exit), per-spawn env reaches the client not the tmux pane (needs `new-session -e`). Claude activity hooks (file-based) and the control lease are unaffected.
9. No doc/todo covers a tmux-run agent; `terminal-sessions.md` § tmux terminals and the per-harness session docs are the docs to extend.
