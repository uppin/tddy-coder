## Summary

A daemon waker turns watched events into a turn for an idle orchestrator: a bus subscriber notes
which owner to look at and returns; a task waits 2 s to coalesce, checks the orchestrator is idle and
30 s past its last wake, takes the delivery committed only if the paste into its main terminal
succeeds, and submits one `[tddy watch]` message. The idle reaper leaves a main session holding a
live watch running.

## Background

See the PRD. The predecessor's delivery rides on tool answers, so an orchestrator at its prompt never
receives anything; and the reaper would stop the main session that was meant to be woken.

## Responsibility

This PR owns **waking an idle orchestrator and keeping a watching main session up**:

- `SessionWatchStore::deliver_with(owner, log, now, deliver)` — the delivery committed only when
  `deliver` succeeds;
- `tddy_daemon_rpc::exec_tool::watch_wake` — `WatchWaker`, `WakeTrigger` (the bus subscriber),
  `WakeTimings { settle, min_gap }` (defaults 2 s / 30 s), `orchestrator_is_idle`, `wake_text`;
- `IdleObservation.holds_live_watch` and the reaper consulting the store;
- the daemon's wiring of all three.

## Boundaries

- **No change to watches** — their tools, filters, kinds, endings, persistence and the `watchEvents`
  key are `feature/activity-wake/session-watches`' (#930). This node adds one store method and calls
  two (`deliver_with`, `has_live_watches`); it changes none.
- **No session-ended change** — #929's.
- **Never starts a stopped orchestrator.** A wake goes only into a live main terminal.
- **`SendSessionMessage` is untouched** — the waker reuses the paste path beneath it, not the tool.
- **No change to the reaper's busy rule** (`Running`) or to which roles it stops.
- **No web, no Telegram, nothing published.**

## Technical Changes

### State A (Current) — with #929 and #930 in

- Matched events reach an orchestrator only in `watchEvents` of a tool answer (#930).
- `SendSessionMessage` (`project_home/turn.rs:28-45`) refuses no-`turn_input`, inactive, and
  waiting-on-an-answer sessions, then `paste_and_submit` (`:154-175`) writes a bracketed paste plus
  the submit key into `MAIN_TERMINAL_ID` from `DaemonTerminalSessionStore`. It has no mid-turn check.
- The bus publishes sequentially inside the hook RPC (`session_notifications.rs:109-124`); a slow
  subscriber delays the agent's hook.
- An orchestrator's own status notifications are on the bus (Done, WaitingForInput) but excluded
  from its log scope.
- The reaper (`tddy-agent-launch/src/project_home_idle.rs`) stops a `project-home` session idle for
  `idle_stop_secs` (default 600) unless `Running`.

### State B (Target)

- **Trigger.** `WakeTrigger` is a bus subscriber that wants attention notifications and every
  status notification; `deliver` only sends `(project_id?, session_id)` on an unbounded-free bounded
  channel (`try_send`; a full channel drops the trigger with a `debug` log, since the next event or
  the gap timer re-checks) and returns.
- **Waker task.** Per trigger: resolve which owners it concerns — owners with live watches in that
  project, or the session itself if it owns watches (its own status changed). For each, arm a settle
  timer (2 s) unless one is armed. On fire: if less than `min_gap` since the owner's last wake, re-arm
  for the gap's end; else if `orchestrator_is_idle` and something is waiting,
  `deliver_with(owner, log, now, |delivery| paste_and_submit(owner, wake_text(&delivery)))`; record the
  wake time on success.
- **Idle.** `orchestrator_is_idle(metadata, pending_question, main_terminal_live)`: live main
  terminal, no pending question, status in `Done | WaitingForInput | Started | Ended` (absent status
  counts as `Started`).
- **Commit on success.** `deliver_with` computes the delivery under the project lock, awaits
  `deliver`, and advances positions / removes ended watches only on `Ok`; on `Err` it logs at `warn`
  and changes nothing.
- **Reaper.** `IdleObservation { busy, idle_since, holds_live_watch }`; `should_stop` is `false` when
  `holds_live_watch`. `LaunchSessions` gets the store (`with_session_watches`); a reaper without one
  reads `false`.

## Testing Plan

### Testing Strategy

The wake is a terminal write, so it is acceptance-tested with the `RecordingAgent` of
`tddy-daemon-rpc/tests/project_home_turn_control_acceptance.rs` — a raw-mode shell that records the
bytes typed into it — as the orchestrator's main terminal, with `WakeTimings` shortened
(settle 50 ms, gap 500 ms) through a constructor, never a test-only branch. Statuses and questions are
reported through the same hook-report path the real agent uses. The timing logic is unit-tested with
tokio's paused clock.

## Decisions & Trade-offs

- **A live watch holds auto-stop off** (developer's choice, 2026-11-16) — over resuming a stopped
  orchestrator to wake it, or holding events until a human restarts it. The TTL (≤ 24 h) bounds how
  long a main session stays up for it.
- **Trigger-and-return subscriber.** The bus awaits each subscriber inside the hook RPC; the waker's
  work (a settle, a paste) must never be on that path.
- **Paste path, not the `SendSessionMessage` tool** — the tool's refusals are written for an operator
  caller; the waker applies its own idle rule first and needs the delivery committed by the paste's
  result.
- **Busy is `Running | ExecutingTool`** here, deliberately unlike the reaper's `Running` — a paste
  into a turn mid-tool would be read as the user interrupting.
