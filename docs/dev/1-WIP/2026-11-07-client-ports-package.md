## Summary

Move generated RPC code into `tddy-client-web` and give component packages three ports — clients, navigation, auth — with the existing hook names, so no component package needs `tddy-web`.

## Background

See the PRD. Package rules shared by every `#web-split` package node: the package imports nothing from
`tddy-web` and nothing from `livekit-client` (only `tddy-livekit-web` / `tddy-livekit-rpc-web` may);
it consumes the outside world only through `tddy-client-web` (generated clients and ports),
`tddy-ui-web` and `tddy-react-commons`; its Cypress component specs, page objects and drivers live in
the package and run from its own `cypress.config.ts` (React Compiler switch identical to `tddy-web`'s);
it has its own `web-<package>.yml` PR check; files move with `git mv` so history follows; code-issue
records move with their files.

## Responsibility

- `tddy-client-web/gen/*` — every generated `*_pb.ts` (moved from `tddy-web/src/gen`, regenerated by the drift gate at the new path).
- `ClientsPort` (`tddy-client-web/ports`): `{ httpTransport(): Transport; connections: ConnectionProviderRegistry; selectedDaemon: SelectedDaemonSource }`, declared with `tddy-react-commons/ports`; the moved provider-agnostic connection model — `HostConnection`, `SessionConnection`, `ConnectionProvider`, `ConnectionCapability`, `ConnectionStatus`, `ConnectionProviderRegistry`, `ConnectionProviders`, `HostReadiness`.
- Hooks backed by it: `useHttpTransport`, `useHttpClient`, `useConnectionProviders`, `useHostConnector`, `useHostConnection`, `useHostClient`, `useSelectedDaemon`, `useDaemons`, `useHostLabel`, `useDaemonClient`, `useDaemonClientFor`, `useHostFanOut`.
- `NavigationPort` + `useAppLocation`, `AppLocation` (moved model from `routing/appLocation`).
- `AuthPort` + `useAuth` (state and actions, as `hooks/useAuth` returns today).
- `ClientsProvider` (mounts the three ports for a subtree) and `tddy-client-web/testkit`: `aClientsPortDouble(backend)`, `mountWithClients(jsx, backend, overrides?)` for Cypress.
- The boundary rule test and `web-tddy-client-web.yml`.

## Boundaries

- Does not move `LiveKitConnectionProvider`, presence, common room or anything importing `livekit-client` — `feature/web-split/livekit` owns that. `tddy-web` keeps implementing the LiveKit factory for now.
- Does not move any component, nor the URL-sync implementation of navigation or the sign-in implementation of auth (those stay as `tddy-web`'s port implementations).
- Does not rename protos or change any RPC (`2026-09-09-versioned-proto-package-names.md` stays open).

## Technical Changes

### State A (Current)

`tddy-web/src/gen` (26.4k lines generated, `buf.gen.yaml` in `tddy-web`). `rpc/connections/types.ts` defines `HostConnection` (hostId, providerId, status, error, capabilities `rpc|media|presence`, `clientFor`, `transport`, `openSession`) and `ConnectionProvider`; `registry.tsx` the registry and hooks (`useHostConnection` ×29, `useHostClient` ×25, `useHostConnector` ×10). `rpc/transportProvider.tsx` (`RpcTransportProvider{httpTransport, liveKitFactory}`, `useHttpClient` ×36, `useHttpTransport` ×17, LiveKit factory hooks) and `rpc/selectedDaemon.tsx` (`useDaemonClient` ×59, `useSelectedDaemon` ×38, `useDaemonClientFor` ×24, `useDaemons` ×14) import `livekit-client` (`Room` type, LiveKit URL/enabled). `routing/useAppLocation` used by sessions (5), tasks (2), worktrees (1). `useAuth` used by ~19 components.

### State B (Target)

`tddy-client-web` owns generated code, the connection model and the three ports; hooks read the ports from context (`ClientsProvider`). `tddy-web`'s root mounts `ClientsProvider` with its HTTP/Tauri transport, its registry (IPC + LiveKit providers registered by `tddy-web`), its selected-daemon source (LiveKit specifics remain in `tddy-web` until n6), its URL-backed navigation and its auth provider.

### Delta

- `git mv packages/tddy-web/src/gen packages/tddy-client-web/src/gen` (+ buf configs); `rpc/connections/{types,registry}.ts(x)` and the provider-agnostic halves of `transportProvider`/`selectedDaemon`/`useHostFanOut`/`routing/appLocation`/`hooks/useAuth` move; `tddy-web` keeps the implementations.
- ~300 `gen/` and ~250 hook import rewrites in `tddy-web` (and `cypress/`).

## Green progress and deviations

Green (2026-11-07): 54 package `bun test` cases, `MountWithClients.cy.tsx`, drift gate, `tddy-web` build,
727 `tddy-web` unit tests (`src/lib src/rpc src/hooks src/routing`) and ~30 `tddy-web` Cypress specs pass.

Moved by `git mv`: `ConnectionProviderRegistry` (`connections/registry.ts`, with its test), `useHostFanOut`
(`hostFanOut.ts`), `hostLabel` (+ test), `routing/appLocation` (+ test, `appLocation.ts`). The hooks keep their
names; `tddy-web` call sites import them from `tddy-client-web` (~80 files).

Deviations from the plan:

- **Ports are plain React contexts**, not `tddy-react-commons/ports` `withPorts` — a package states its
  needs as a context per port and a missing provider throws naming it; no default exists in the package.
- **`ConnectionProviders` / `useConnectionProviders` / `HostReadiness` stay in `tddy-web`**
  (`rpc/connections/registry.tsx`): they are the source side of the registry. Only the registry class moved.
  `ClientsPort.connections` is the class itself; `ClientsPort.httpTransport` is a value, not a function.
- **`AppClientsPorts`** (`tddy-web/src/rpc/appClientsPorts.tsx`) builds the three ports from `tddy-web`'s sources
  (serving-daemon transport, registry, selected-daemon directory, hash navigation). `RpcTransportProvider`,
  `ConnectionProviders`, `HostReadiness`, `AuthProvider` and `SelectedDaemonProvider` mount it, so the port in
  scope is always built from the nearest source of each kind and every existing fixture keeps working. With no
  `SelectedDaemonProvider` the directory source reports "no daemons" — what `useSelectedDaemon`'s
  no-provider defaults used to say, now owned by the app's source, not the package. `cy.mount` in `tddy-web`
  also mounts it (callers that relied on the old defaults get a provider, not a fallback).
- **`tddy-web` components keep `useAppLocation` (hash store) and `useAuthContext`**; the app supplies
  `hashNavigationPort` and `AuthProvider` additionally mounts `AuthPortProvider`. Rewriting those call
  sites belongs to the nodes that move the components.
- **Test fixes in the red suites**: `clientsPort.test.tsx` asserted `isAuthenticated` on `GetAuthStatusResponse`
  (the field is `authenticated`); handlers return `create(...)` messages so `tsc` accepts them.
- **`testkit/spy.ts`** returns bun's `mock` under `bun test` (the auth double's actions must satisfy
  `toHaveBeenCalledTimes`) and a recording function elsewhere (Cypress bundle).
- `mountWithRpc` mounts `withClients(<RpcTransportProvider …/>, backend)`.
- Not run locally: the full Cypress suite and Storybook stories (CI); other bare-mount specs that used the old
  no-provider defaults are covered by `cy.mount` mounting `AppClientsPorts`.

## Decisions & Trade-offs

- **Hook names kept**, so the move is an import-path rewrite at ~250 sites, not an API change.
- **Ports over providers-as-components**: a package states its needs as a port map; the app (and a spec) supplies them.
- **Auth and navigation are ports here**, not packages: they are app concerns components read, and the implementations stay wiring.
