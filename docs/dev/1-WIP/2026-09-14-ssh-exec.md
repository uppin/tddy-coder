## Summary

A co-located managed session can execute its catalog on an SSH Host alias of the session host.
Empty selection is today's local tools.

## Background

Files on a machine with no tddy-daemon cannot use LiveKit `ExecuteTool`. The code-managing
daemon is the SSH client; makers-lt LocalShell/RemoteShell is the shape.

## Technical Changes

### State A (Current)

`execute_tool(worktree_root: &Path, …)` on the host FS. No session SSH field. Create-session
has Host + optional codebase host, no SSH alias. Worktrees created locally under `.worktrees/`.

### State B (Target)

Session with `ssh_config_host` set: worktree on T, exec catalog via `ssh -o BatchMode=yes
<alias>`. Unset: LocalShell. Dropdown lists Host A's aliases. Native FS tools off when set.
No fallback to local on SSH failure.

### Delta (What's Changing)

#### tddy-tool-engine
- **Architecture**: `Shell` trait; LocalShell vs RemoteShell; `contain_path` against remote root.

#### tddy-core / tddy-service
- **API**: `ssh_config_host` (+ remote worktree path) on metadata and start/list protos.

#### tddy-session-lifecycle
- **Implementation**: start materializes via RemoteShell when the field is set; implies managed.

#### tddy-web
- **Implementation**: `create-session-ssh-config-select` from `ListSshConfigHosts` on session host.

## Decisions & Trade-offs

- **SSH in the daemon, not tddy-tools.** Jail cannot see the operator agent socket.
- **OpenSSH CLI, not russh.** Config + agent fall out of `ssh <alias>`.
- **No fallback.** BatchMode failure is the result.
- **All exec tools in this node**, not Shell-only — same backend.
