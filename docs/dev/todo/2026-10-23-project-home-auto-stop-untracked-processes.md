# Project-home auto-stop cannot stop an untracked session process

**Raised:** 2026-10-23 by `/pr-wrap` on #701 (`#project-home` 6/7); narrowed 2026-11-20 by `#session-liveness` 1/4 (PR #958)
**What remains:** the reaper stops through `CliSessionManager::stop_session`, which only knows terminals this daemon process started. An idle project-home session whose process is alive but untracked (started by a previous daemon process, or re-parented) is **not active** — liveness is what the daemon holds, not the recorded pid — so the reaper skips it up front: no 5 s wait, no repeated warning, and its process keeps running. Signalling a bare pid from metadata is not done because pids are reused and the daemon cannot prove the pid is still that agent.
**What to do:** give the reaper a pid-verified stop for untracked sessions (match the pid's start time or command line against the session before signalling), or make such a session held again by re-attaching it (`#session-liveness` 2/4 does so for tmux-wrapped agents). Test: an acceptance case with a session whose process is alive but absent from the manager.
