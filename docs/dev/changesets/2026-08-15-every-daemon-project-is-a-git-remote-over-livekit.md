# 2026-08-15 — every daemon project is a git remote, over LiveKit

**Type:** Feature

`git clone udoo-1:my-app` against a host you cannot SSH into. Git already knows how to run an external transport command, so `tddy-remote-git-repo` is that command, carrying `git-upload-pack`/`git-receive-pack` over a bidi RPC stream to `remote_git.RemoteGitService`. **Reusing the terminal RPC was the plan and it does not work** — the bridge prepends a mouse-tracking prologue, replays through a `broadcast::Receiver` that drops on `Lagged`, and runs over a PTY that rewrites `
` → `
`; each corrupts a packfile *silently*, and the proto carries neither an exit code nor a separate stderr, both of which git needs. So the wire format is new and the child runs on pipes. Two properties keep it a git shell rather than a shell, both enforced server-side and both pinned by tests that fail when the property is removed: a closed pack-verb whitelist, and a repository path that comes only from the project registry. A pre-PR review then found seven criticals, and the two most interesting were invisible — **the `setpriv` privilege drop and the child's `cwd` had no test at all**, proven by deleting each and watching all 93 tests stay green. Also fixed: the client required `LIVEKIT_API_SECRET`, which is the fleet's session-token **signing key**, so a git credential was fleet-admin-equivalent — the daemon now mints a room JWT with a server-chosen room and a `remote-git-<uuid>` identity, and `token.TokenService`, an unauthenticated mint that took room and identity from the request, was authenticated and taught to refuse any `daemon-*` identity; `--help` printed the secret and the 7-day refresh token, because clap's `env` shows current values; and an unbounded output channel would have turned a 2 GB clone into 2 GB of RSS. The LiveKit connect sequence, duplicated three ways with a shared silent-degrade bug (a closed event channel read as "participant appeared"), now exists once. **Measured, not estimated:** 150 MiB clones in 59 s (2.54 MiB/s) byte-identical, and it is wire-bound — 8× the frame-channel capacity moves it not at all.
