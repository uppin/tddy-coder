# 2026-07-22 — **reusable-lsp

**Type:** Feature

a reusable language server exposed to agents via one MCP interface** — a language server (rust-analyzer first; any LSP pluggable, chosen by build-target `config.type` and gated by an allow-list) runs as a long-running `tddy-task`, reused across build targets keyed by (workspace root, language), with lazy get-or-spawn, per-server idle teardown, and respawn-after-crash. New crate **`tddy-lsp`** (allow-list + `language_for_target_type`; JSON-RPC `LspClient` over task channels incl. `workspace/diagnostic` and server→client request replies; long-running `LspServerBody`; `LspRegistry`) and **`tddy-lsp-executor`** (binds `tddy-build` target discovery to the registry; `register(task_registry, allow, idle_timeout)`). `tddy-core` gains the `LspExecutor` trait + `OnceLock` registry (mirrors `BuildExecutor`); `tddy-tool-engine` dispatches the five language-agnostic tools `Lsp{Diagnostics,Definition,References,Hover,Symbols}` + workspace-level `ReadLints` to `lsp_executor()` (single site serving daemon HTTP, daemon sandbox-IPC, and sandbox-app hosts); `tddy-tools` merges the gated catalog into `PermissionServer::new` behind `TDDY_LSP_TOOLS`; the **daemon** and **sandbox-app** register the executor (+ 60s idle reaper) and set `TDDY_LSP_TOOLS` when a server is available; `IdleTimeoutTracker` lifted from `tddy-daemon::relay_idle` into `tddy-task` (daemon re-exports). New dep `lsp-types` (types only; framing hand-rolled). Tests against a deterministic `fake_lsp` server: `tddy-lsp` 20, `tddy-lsp-executor` availability + e2e (two targets → one reused server), `tddy-tool-engine` dispatch + ReadLints routing/fallback, `tddy-tools` gate/merge, `tddy-core` registry, `tddy-task` idle.
