# 2026-08-13 — **a test suite that reported how busy the machine was

**Type:** Fix

five causes closed, and two production bugs it was hiding** — two back-to-back `cargo test --workspace` runs produced 12 and 15 failures with only **6 in common**; every failure was a fixture defect, and `--test-threads=1` did not help because it is *per test binary* while cargo still runs many at once. **tddy-testing-commons** gains three modules that replace the copy-pasted sleep/poll loops: `wait.rs` (`eventually`/`eventually_awaiting`/`eventually_blocking`, 25 ms cadence, panic carrying the condition, ceiling, poll count and **last observed state**), `stub_scripts.rs` (`a_stub_agent_script` writes `"$f.tmp.$$"` + `mv -f` and appends through one `printf` — measured 526,770 torn argv observations for the old stub under injected preemption, **0** for this one, which no timeout increase would have fixed), and `stub_http.rs` (a `:0` loopback endpoint that drains headers **and** the declared `Content-Length` body before replying, since a stub answering mid-write resets the client and warm-up classifies a connection error as *transient* and retries it to the deadline). Where a test needed different behaviour, **production grew a config knob whose default is today's value** rather than a test-only branch (`defaults ← daemon.yaml ← TDDY_*`): `spawn_startup_grace_period_ms`/`spawn_startup_poll_interval_ms` (threaded as `spawner::StartupWatch`, carried across the pre-env-override fork as `SpawnRequest` fields) and the `agent_warmup` section, pinned by a test asserting `agent_warmup_options() == WarmupOptions::default()`. The two tests that required an **SGLang server on `localhost:30000`** — 242 s of an 863 s suite, spent waiting out a 120 s timeout before failing — are hermetic (a `fastcontext` def in `<tddyhome>/agents` pointing at the stub endpoint, a 10 s budget through the new config) and now run in **12.1 s and 6.8 s, passing**. Also: the supervisor fixture's `await_socket` → `await_ready` (a dropped `UnixListener` leaves its inode, so "the socket exists" was never "the server is up"); a reverse-RPC readiness handshake in the `tddy-tools` stdio fixture, splitting a 900 ms budget that silently covered fork/exec and tokio boot into `FIXTURE_READY: 5s` + `CALL_TIMEOUT: 1s`; a port fixture probing *outside* the kernel's ephemeral range; fail-fast asserted by **counting probes** instead of the clock; and `/tmp` vs `/private/tmp` comparisons fixed on the canonicalized side. Two production bugs surfaced on the way: **`relaunch_sandboxed_runner` never warmed up at all**, so resume handed the agent subagents both start paths gated on (now gated, no fallback — and the two docs claiming resume "reuses this start path" were never true); and **`resolve_supplementary_groups` truncated the group list to `getgrouplist`'s return value**, which Darwin sets to `0` for "they fit", handing the child an *empty* supplementary list — the silent privilege downgrade the adjacent `bail` exists to refuse. Every fix carries a red-first proof (the argv-tearing count, a `:0`-binding port helper, a socket-outlives-process demo, a `503`-instead-of-`404` probe count of 23 vs 1, an injected 1500 ms fixture sleep).
