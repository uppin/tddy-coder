# 2026-09-05 — sandboxed codebase mode: the jail holds the code, the agent runs on the host

**Type:** Feature

`tddy-sandbox-app`'s two existing codebase modes are one placement with a variable: the agent sits in the Seatbelt jail, and `mounted`/`managed` only decide whether the repo came with it. Both cost the agent the host — no real `~/.claude`, no host toolchain, a terminal that is a proxy of a proxy — to confine the thing you *chose* to run, while `managed` relays `Shell` back out so the **build** you did not write runs unconfined. **`--codebase-mode sandboxed`** inverts it: Claude Code runs on the host as an ordinary child with the real tty, real credentials and real network, while the checkout and every build, test and tool call against it run inside a **`--workspace-tools` jail** — the no-agent runner mode the daemon already had and the standalone app had never driven. The agent keeps the full `mcp__tddy-tools__*` surface and loses every native route to it (`Read`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `Grep`, `Glob`, `Bash`, `BashOutput`, `KillShell`); each call crosses as `in_jail_tool_request` over a Unix socket the app serves, dispatched by a new **`InJailToolDispatcher`** on the host relay — one call outstanding at a time, because `in_jail_tool_response` carries no request id, bounded by the daemon's own `IN_JAIL_TOOL_TIMEOUT` (600s), now **one shared constant** rather than two. The jail gains a CONNECT egress shim so a build can fetch, and a **persistent per-repository `$HOME`** under `~/.tddy/sandbox-codebase-home/<repo-key>` so it does not refetch every session — keyed per repo because one shared home is a cross-repo `~/.cargo/config.toml` poisoning channel. Path lookup for the checkout needed a new **`ReadKind::Metadata`** (`(allow file-read-metadata …)`): the ancestors must be *traversable*, not *listable*, and the previous `literal` grants let a jail enumerate its neighbours — the daemon's own workspace jail is switched over too, which on Linux replaces a read-only bind of `/` onto `/` with no mount at all. **Four confinement holes were found in pre-PR review and fixed before this shipped**: the egress shim was dead wiring (no proxy env inside the jail, so a jailed build had no network); Ctrl-C during provisioning orphaned the jail (`SandboxHandle` has no killing `Drop`, then `exit(130)`); the untrusted checkout's `.claude/settings.json` hooks and `.mcp.json` executed unconfined on the host (now `--strict-mcp-config` + `--setting-sources user`); and the jail could rewrite the host agent's MCP config, whose `command`/`env` the unconfined host executes (moved to `<session_dir>/host/`, outside every grant). A fifth was found by a test the review demanded: the per-repo build home landed under a base **no grant named**, so the jail could not resolve its own `$HOME` and the cache was unreachable in production — every earlier test had hidden it by placing the home in the same temp tree as the checkout. Refusals over silent degradation throughout: `--agent-kind cursor`, specialized agents, `--cwd`, `--codebase-home-dir` outside this mode, Linux, and a jail with no transport are each refused by name. ⚠️ **macOS only** — the Linux path refuses the mode rather than half-wiring it. ⚠️ **`./test` never built `tddy-sandbox-runner`**, which the jail acceptance suites spawn as a binary from `target/debug`; a runner change was tested against whatever build was on disk, weakening every jail acceptance test in the repo, not just this feature's — fixed. ⚠️ Five tests in this suite passed while proving nothing and were repaired; every confinement assertion now carries an in-test control or an explicit premise.
