# 2026-11-17 — A session whose agent ends says so

**Type:** Feature

`#activity-wake` 1/3, PR [#929](https://github.com/uppin/tddy-coder/pull/929). When the agent of a
session's main terminal ends, the daemon publishes one `ATTENTION_REQUIRED` notification with
source `SESSION_ENDED`, text `⏹ Session {label} ended: {outcome}` and a structured
`ended { outcome, exit_code }`. It reaches the project notification log, so
`ReadProjectNotifications` / `WaitProjectNotifications` return it to an orchestrator that can
see the session. Neither `/clear` nor a tab raises it, Telegram does not send it, and the
session drawer's dot does not light for it.

## What changed

- `tddy-cli-sessions`: `CliSessionManager::agent_ends()` announces every agent end on a
  broadcast channel (`AgentEnd { session_id, os_user, outcome, exit_code }`,
  `cli_session_manager/agent_end.rs`), from the immediate `AgentEnded` classification in
  `spawn_terminal_cleanup` and from the detach watcher when a detached agent's tmux session is
  gone. A PTY-run main announces `outcome_of(status)` with its exit code; a tmux-run main —
  whose status is its client's, not its agent's — announces `exit code unknown` with no code.
  At wrap, `AgentEnd::for_ended_main` took that construction into `agent_end.rs`, and
  `spawn_terminal_cleanup` (59 → 83 lines as the announcement landed) was brought back to 54
  lines by extracting `await_terminal_status` and `deregister_terminal` beside it.
- `tddy-daemon-kernel` / `tddy-service`: `SessionNotificationSource::SessionEnded`,
  `SessionEndNotice`, `SessionNotification.ended`, and in `activity.proto`
  `SESSION_NOTIFICATION_SOURCE_SESSION_ENDED = 6`, `message SessionEndNotice` and
  `SessionNotificationEvent.ended = 13`, with the generated web clients regenerated.
- `tddy-session-activity`: the wire conversion carries the new source and `ended`; the project
  notification log stores it as `source: "session_ended"` with an `ended` object (omitted when
  `None`), read back on replay.
- `tddy-session-lifecycle`: `session_notifications::{notification_for_agent_end,
  forward_agent_ends}` turns an announced end into a labelled, owned bus notification; an end
  whose owner has no sessions base is logged at `warn` and dropped, and a lagging forwarder
  logs how many ends it missed. At wrap, the per-end publishing moved into `publish_agent_end`,
  leaving `forward_agent_ends` at 32 lines.
- `tddy-daemon`: `BuildContext::forward_agent_ends` starts the forwarder once the bus is
  assembled, in its own function beside `open_shared`'s caller, not inline in
  `build_session_host`.
- `tddy-telegram-control`: the source match declines `SessionEnded`; `tddy-session-web`:
  `lib/sessionNotificationDot.ts`'s `dotForNotification` lights no dot for it.

State B lives in [session-notifications.md](../../ft/daemon/session-notifications.md) (*What is
notified*), `packages/tddy-cli-sessions/docs/module-layout.md`,
`packages/tddy-daemon-kernel/docs/daemon-kernel.md`,
`packages/tddy-session-activity/docs/session-notifications.md`,
`packages/tddy-session-lifecycle/README.md` and `packages/tddy-session-web/README.md`.
