# 2026-07-11 — **linux-sandbox-app-daemon-client

**Type:** Feature

Linux `tddy-sandbox-app` via `tddy-daemon` over tonic UDS** — on Linux the standalone app can't spawn the cgroups jail in-process (cgroup v2 delegation containment), so it delegates to a running daemon: connect the daemon's Unix socket over tonic gRPC, `MintLocalToken` (SO_PEERCRED peer-trust → mapped os_user → signed access token), `StartSession` with new `repo_path`/`claude_args` (+ existing `model`/`permission_mode`/`managed_codebase`), and PTY-proxy over `StreamSessionTerminalIO`; macOS keeps the in-process Seatbelt path. Adds `MintLocalToken` RPC; a wired tonic codegen pass + hand-written adapter serve the existing `ConnectionServiceImpl` over a UDS `tonic::transport::Server` (native `UdsConnectInfo` peer creds); `repo_path` used directly as the worktree (never auto-removed — `.worktrees` guard); codegen `from_arc` shares one impl across transports. Also fixed pre-existing fmt drift + a `type_complexity` lint. **Unverified: never run end-to-end (host-touching; also exercises the still-open #290 daemon-sandbox issues); macOS unbuilt; stacks on unmerged #290.** Architecture [tddy-sandbox architecture § Standalone tddy-sandbox-app on Linux](../../../packages/tddy-sandbox/docs/architecture.md).
