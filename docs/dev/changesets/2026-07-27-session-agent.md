# 2026-07-27 — **session-agent

**Type:** Feature

peer agent sessions sharing the current session's worktree, spawned from the session detail view** — a tddy-web-only feature that reuses `stack_parent`/`orchestratorSessionId` with **no proto/daemon changes**. `SessionMainPane` gains an "Add agent" header button opening `CreateSessionPane` in **peer mode**: pre-filled `stackParent` = current session, same `projectId`/`daemonInstanceId`, and `repoPath` = current session's `repoPath` → `StartSession.repo_path` (per the daemon contract a non-empty `repo_path` makes the session's worktree BE that path — no git worktree, no branch checkout), with a separate `sessionType`/`agent`/`model` pick. Branch selectors, the PR-stack parent picker, and the **Project**/**Host** selectors are hidden in peer mode (irrelevant/locked when reusing the orchestrator's worktree); submit sends the frozen orchestrator `projectId`/`daemonInstanceId`. New `SessionAgentsSection` lists peers (children via `orchestratorSessionId`, derived by pure `sessionPeers(sessions, currentSessionId)`) with `agent`/`model`/`status` and a switch action; empty state when there are none. `SessionsDrawerScreen` wires the spawn through the existing `onChildSessionStarted` optimistic overlay; a capture ref survives a mid-flight drawer selection change so the overlay always fires, and a keyed remount resets pane state on a peer→standalone transition. Also fixes a latent `cursor-cli` `stackParent` hardcode.
