# 2026-07-23 — **bsp-build-server

**Type:** Feature

BSP-shaped build-target RPC service (new tddy-bsp crate)** — a new **`tddy-bsp`** crate exposes **`bsp.BspService`** — a BSP (Build Server Protocol)–*shaped* RPC service over the existing protobuf/Connect (`/rpc`) + LiveKit transports (**not JSON-RPC 2.0**; external BSP clients like Metals/IntelliJ are out of scope) — with methods `WorkspaceBuildTargets`/`BuildTargetSources`/`BuildTargetOutputPaths`/`WorkspaceReload`/`BuildTarget{Compile,Test,Run}`. `tddy-build` gains author-declarable `tags`/`languages`/`capabilities` on `BuildTarget` (type-derived when omitted, via new `capabilities.rs` `resolve_target_metadata` + `TargetCapabilities`) and a `BuildMode {Compile,Test,Run}` threaded through `plugin`/`lower`/`execute_target`/`service::build_json` (capability-gated; rust emits `cargo test`/`run`, typescript emits bun test/start, other plugins return unsupported). `tddy-core` adds a dedicated typed **`build_targets`** table + `BuildTargetSummary` + `list_build_targets`/`_for_package`, written in the same populate transaction as the JSON catalog, plus enriched `BuildTargetCatalogEntry`/`CatalogCapabilities`. The enriched `BuildCatalogProvider` (derives `sources`/`outputs`/`deps`/`type`/`base_dir`/capabilities by lowering each target) + `plugin_registry` move out of `tddy-coder` into `tddy-bsp`; the coder serves `bsp.BspService` per-session on its participant (`run.rs`), and the daemon serves it session-addressed (`DaemonBspService`, resolving `(session_token, session_id)` → worktree + catalog) in `rpc_entries`. Reflection advertises the surface automatically. Tests: tddy-bsp lib 4 + acceptance 5, tddy-daemon bsp_service 2, tddy-build capabilities 4 + rust modes 2, tddy-core build_targets 2.
