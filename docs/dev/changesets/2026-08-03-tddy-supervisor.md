# 2026-08-03 — **tddy-supervisor

**Type:** Feature

one root process brokers what the daemon may no longer do itself** — `./install --systemd` used to offer two wrong deployments: root, where multi-user isolation worked but the whole network-facing daemon ran as uid 0 (~65 modules, axum, LiveKit, GitHub, Telegram, LSP, BSP, VM); or `User=tddy`, safe but with `same_user` true so the privilege drop was skipped and every session ran as one account. **tddy-supervisor** (new, lib+bin, owns `proto/supervisor.proto` and its own codegen) becomes the single root unit and starts the daemon as a declared unprivileged child. **tddy-daemon**: session and clone spawning route through it, fail-closed, via a shared `plan_session_child` so the argv lives in one place; config gains `supervisor: { socket_path }`. **repo root**: `install` writes the supervisor unit/socket/config and masks inherited daemon units socket-first, renders every generated file atomically through awk substitution (`sed` would corrupt on `&`/`#`), verifies the unit is actually `is-active` before reporting success, and `--user` installs a per-user daemon and no supervisor because rootless it could broker nothing. Four validations found what 174 passing tests had not: `LD_PRELOAD` in a caller's env defeated the tool allowlist entirely; `AttachPid` had no ownership check so `CreateScope(memory_max: 1)` + attach PID 1 OOM-killed systemd; the privileged listener leaked into every child because systemd passes activation fds with `FD_CLOEXEC` clear (measured — a service declaring no socket held the same inode); and `initgroups` in `pre_exec` allocates and enters NSS, which with one forking thread would freeze every later spawn while the supervisor still answered `ListServices`. Deliberately not closed and recorded in `docs/dev/TODO.md`: sandbox and PTY session types still spawn from the daemon, `SignalSession` will `EPERM`, and a VM-backed test of real cross-user setuid and enforced cgroup limits.
