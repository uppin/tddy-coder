# 2026-07-25 — **agent-activity-persist-lazy-count

**Type:** Feature

the Agent Activity overlay persists per session, loads lazily via a count-first stream, and adds a color-highlighted JSON detail dialog** — the read-only ACP-transcript overlay no longer resets on session switch or eagerly downloads its transcript. **tddy-web**: a module-level `AgentActivityRegistry` (per-session `{count, messages, seenCount, snapshotOpened}`, `useSyncExternalStore`, LRU-capped) survives session switches; `useAcpReplay` is two-phase — a cheap `COUNT_THEN_LIVE` feed drives the icon/unread badge, the full `SNAPSHOT_THEN_LIVE` transcript is pulled only on first open and cached (no re-pull on switch-back) — and carries the tool `raw_input`/`raw_output` onto the `ChatMessage`; a new `AgentActivityDetailDialog` shows a clicked tool call's input/output as Prism-highlighted JSON (`AgentChatView` gains `onToolClick`, tool rows only). **tddy-service**: `proto/connection.proto` adds `StreamMode.COUNT_THEN_LIVE` + `AcpReplayFrame.activity_count` (regen Rust + `connection_pb.ts`); `acp_replay` gains `count_activity_entries`/`tool_call_ids` and `frame_for_agent_activity` now sets `raw_output` from the record result. **tddy-daemon** + **tddy-coder**: both `StreamAcpReplay` hosts serve `COUNT_THEN_LIVE` — emit the coalesced entry count (agent-text frames + distinct tool `call_id`s, so a running+terminal pair counts once) then a fresh count per newly-seen entry, no transcript payload.
