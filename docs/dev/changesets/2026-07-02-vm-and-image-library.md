# 2026-07-02 — VM & Image Library

**Type:** Feature

organizes base images, prepared bases, and per-VM state under a single library rooted at the existing tddy data dir (`images/01-base/`, `images/02-prepared-base/` — both read-only chmod `0o444` — and `vm/<name>/` with a YAML manifest + mutable overlay + SSH keys). New `tddy_vm::library::VmLibrary` and `tddy_vm::vm_manifest::VmManifest`; `VmManager` gains a library-backed `from_library` constructor (per-VM manifests become the source of truth, the pre-existing JSON-backed path is untouched); `cloud_init_library_paths` routes cloud-init build outputs into the library; `tddy-vm-build cloud-init` wired to place its results there (via a per-image scratch subdirectory for the seed ISO/SSH keypair/boot log, keeping `02-prepared-base/` image-only); `tddy-daemon`'s VM service repointed at `VmManager::from_library`. Design mirrors `~/Code/makers-lt`'s `maker-vm` qcow2-backing-file chaining; no image ever downloaded by this feature. 65 unit/acceptance tests pass in `tddy-vm` (3 correctly-gated `#[ignore]`d, one run for real against a real prepared base and `qemu-img`), `clippy -D warnings` clean across all three packages.
