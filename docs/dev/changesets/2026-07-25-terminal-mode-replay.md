# 2026-07-25 — **terminal-mode-replay

**Type:** Fix

mouse works in every terminal session, not just the newest one** — older sessions in `tddy-web` dropped every click, drag and scroll while keyboard input kept working. `GhosttyTerminal` forwards mouse events only while its own VT handle has observed a mouse-tracking DECSET (`hasMouseTracking()`), and **two independent gaps** kept those bytes from a late-attaching browser: (1) the daemon's 64 KiB capture ring trims from the front, so the DECSETs an agent TUI emits **once at startup** are evicted and nothing re-issues them — `trigger_redraw()` is SIGWINCH only, and SIGWINCH does not re-emit private modes; (2) `stream_terminal_output` gated the replay on `!has_initial_dims`, and a browser always measures its grid first, so on the exact path the web terminal uses **no capture was sent at all**. **tddy-task**: new `terminal_capture` module — `TerminalCapture` is a mode-aware ring that sniffs DECSET/DECRST through a byte-at-a-time `EscapeParser` (a sequence split across PTY reads is still recognised), keeps the mouse family (1000/1002/1003/1006/1015/1016) as sticky state costing no ring space, re-issues it via `mode_prologue()`/`replay()`, exposes prologue-free output as `buffered_bytes()`, and stops eviction at an escape-sequence boundary so a cut can't leave an orphan fragment (a bare `1m`) to be rendered as text; `TaskChannel.capture` is retyped and `write()` delegates to `append`, while `replay_capture()` stays byte-exact and prologue-free so the non-terminal consumers (`tddy-actions`, `tddy-build`, `tddy-core` session actions, `WatchTask`, `tddy-tool-engine`) that read it as command output are unaffected. **tddy-daemon**: the prologue is sent as its **own first frame**, independent of the replay gate (order: prologue → legacy replay → initial ACK → live bridge); LiveKit bidi replays `cap.replay()`. **tddy-coder**: session participant + `terminal_manager` do the same for bash tabs. Non-mouse sticky modes (cursor 25, alt-screen 1049, bracketed paste) are deliberately not replayed — the application redraws them and re-issuing them out of context would fight its state. Known gaps carried forward: `sandbox_session.rs` keeps a separate unbounded raw capture and gets no prologue; no RIS (`ESC c`) handling, so mode state survives a hard reset; a cut inside an unterminated OSC/DCS can transiently empty the ring. Tests: tddy-task `terminal_capture_replay` 10, tddy-daemon `terminal_mode_replay_acceptance` 1 (end-to-end over `StreamTerminalOutput`, premise asserted by polling until the DECSETs are provably gone from `buffered_bytes()`); `cargo fmt` + `clippy --workspace --all-targets -D warnings` clean.
