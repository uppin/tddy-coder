# 2026-07-26 — **versionless-claude-aliases

**Type:** Feature

Claude defaults to the moving `opus` alias, and one Rust catalog feeds every model picker** — a Claude session used to be pinned at start to whatever full id was current (`claude-opus-4-8`), so it never followed a newer release; `tddy_core::backend` now leads its catalog with the versionless aliases `opus`/`sonnet`/`haiku` behind `CLAUDE_DEFAULT_MODEL = "opus"`, keeps the version-pinned ids (refreshed to `claude-opus-5`/`claude-sonnet-5`/`claude-haiku-4-5-20251001`) selectable after them, and labels the two apart ("Claude Opus (latest)" vs "Claude Opus 5 (pinned)"). The catalog had been copied into five places; the copies are gone — `tddy-web` deletes its hardcoded `CLAUDE_CLI_MODELS` constant and renders `ListAgentModels` only, the Telegram Claude/Cursor keyboards read `claude_cli_models()`/`cursor_cli_models()` (fixing stale Claude labels, growing Cursor 3→5) and reject an out-of-range index, and the `--model` defaults in `tddy-tools pty-relay` and `tddy-sandbox-app` reference `CLAUDE_DEFAULT_MODEL` instead of a literal.
