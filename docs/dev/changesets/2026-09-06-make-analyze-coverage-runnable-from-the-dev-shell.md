# 2026-09-06 — Make `analyze coverage` runnable from the dev shell

**Type:** Fix

`tddy-tools analyze coverage` could not run in the nix dev shell on macOS, so the `analyze-code-issues` skill was blocked at its first tool step. Three gaps, all in the plumbing rather than the analysis itself. **(1)** The toolchain carries `llvm-tools-preview`, but its binaries live in the rustlib tree, which is not on `PATH` — `llvm-cov` and `llvm-profdata` were unresolvable even though `analyze coverage` looks them up by name; the dev shell now exports that directory (derived from `rustc --print target-libdir`, guarded so a toolchain without the extension is a no-op). **(2)** The instrumented build hardcoded `-C link-arg=-fuse-ld=lld`, which aborted the whole capture with `clang: error: invalid linker name in argument '-fuse-ld=lld'` on any host without lld; lld is a link-time speedup, not a requirement, so it is now added only when a driver (`lld`, `ld.lld`, `ld64.lld`) actually resolves. The flag selection is a pure function with unit tests over both branches. **(3)** Instrumented test binaries drop `.profraw` files into the repo root and package directories and none were ignored — a capture run left several hundred untracked files behind; `*.profraw` and `/coverage/` are now gitignored. Feature [rust-code-analysis.md](../../ft/coder/rust-code-analysis.md). (tddy-code-analysis, repo root)
