# 2026-07-03 — **pr-stack-free-prompting-loop

**Type:** Feature

operator-driven PR-stack + PR-management tools + internal statuses** — replaces the `pr-stack` recipe's automatic `assess → spawn/merge/repoint` agentic loop with a terminal `orchestrate` free-prompting goal (no successor edge; pauses for input each turn like `free-prompting`): after planning, the same orchestrator session drops into an interactive chat where the developer drives the stack via new `tddy-tools` MCP tools rather than an autopilot. `StackNode` gains `internal_status: Option<PrInternalStatus>` (`{kind,note,source}`, serde-default for back-compat) — the action-needed signal (`needs-repoint`/`has-conflicts`/`ready-to-merge`/`merged`/`blocked`/`up-to-date`) orthogonal to `pr_status`, auto-derived from git+GitHub views (`derive_internal_status`) with an agent-override-wins rule (`reconcile_internal_status`); surfaced as a colored badge on planned-PR rows (`PlannedPrRow.tsx`, `stackPlan.ts`). Eight `mcp__tddy-tools__pr_*` tools (`pr_stack_status`/`pr_merge`/`pr_repoint`/`pr_close`/`pr_resolve_conflicts`/`pr_set_status`/`pr_add_planned`/`pr_spawn_child`) delegate to reused helpers (`assemble_views`, `effective_base_ref`, `execute_stack_merge`/`_repoint`, `RealGithubPrApi` + new `close_pr`) and new `pr_actions.rs` (`pr_merge_action`/`pr_close_action`/`pr_resolve_conflicts_action`). `pr_spawn_child` spawns a stack child via a new `TDDY_SOCKET` `spawn-child` toolcall verb → a per-session `ChildSpawnHandler` (bound only to `pr-stack` orchestrators) that calls the shared `spawn_claude_cli_session_inner` (extracted from `start_claude_cli_session`, RPC path unchanged) with `stack_parent` set, inheriting the orchestrator's model. Fixed a latent runtime bug: `prepare_managed_workflow` now also exports `TDDY_SESSION_DIR`+`TDDY_REPO_DIR` (previously only `TDDY_SOCKET`+`PATH`), which all `pr_*` tools read. Legacy `OrchestratePrStackRecipe` retained as documented-inert (all CLI names resolve to `PrStackRecipe`; kept for reused-helper test coverage). Rust: `tddy-core`/`tddy-workflow-recipes`/`tddy-tools` tests green; `tddy-daemon` 217 pass (only pre-existing `sandbox_session`/`spawner` env failures); `clippy --all-targets -D warnings` + `fmt` clean. **Needs live-daemon runtime verification** of the end-to-end `pr_spawn_child` spawn, and the web `tsc`/Cypress badge spec (`PlannedPrRowInternalStatusAcceptance.cy.tsx`) run in a networked env.
