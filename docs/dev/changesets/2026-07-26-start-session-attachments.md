# 2026-07-26 — **start-session-attachments

**Type:** Feature

the wire contract for attaching documents at session start, with the host that owns them named in every reference** — attaching a document to a session had no representation before the session existed: the only upload RPC (`UploadSessionFileChunk`) is keyed on a `session_id`, so a Start-Session form had nowhere to put a picked file, and a document already sitting on another connected host had no way to be named at all. `connection.proto` now carries `StartSessionRequest.attachments = 29` — a `basename` (separate from the locator, so the UI can rename without touching the stored file; duplicates within one request are to be rejected, not silently renamed) plus a `oneof source`: `StagedAttachmentRef` for bytes uploaded ahead of time by the three new staging RPCs (`UploadStagedAttachmentChunk` / `ListStagedAttachments` / `DeleteStagedAttachment`, deliberately `UploadSessionFileChunk` with `session_id`→`daemon_instance_id` and `upload_id`→`staging_id` so `tddy-web`'s existing 48 KiB `chunkFile()` loop is reusable unchanged and each chunk still fits one LiveKit data packet), or `HostDocumentRef` for a document that already exists on a connected host. **Host authority is part of both variants** (`daemon_instance_id`): a staged batch belongs to one host, and a ref naming a host other than the one `StartSession` runs on is specified as a request **error** rather than a cross-host fetch — no fallback that uploads to A, starts on B, and yields an empty attachment; a `HostDocumentRef` read is performed by the **owning** daemon under **its own** os_user mapping. `HostDocumentScope` (`SESSION_ARTIFACT`/`SESSION_UPLOAD`/`SESSION_WORKTREE`/`PROJECT_REPO`) is a scope + validated `relative_path` and there is **no absolute-host-path variant** — a raw path field would let any caller name any file the daemon's user can read, so a new document source costs a reviewed scope. **This slice is proto + generated stubs only and ships no behavior**: all three RPCs return `UNIMPLEMENTED` (`connection_service.rs` stubs marked `TODO(start-session-attachments)`, mirrored as delegation in `connection_tonic_adapter.rs` — required, since a new RPC makes both `ConnectionService` impls incomplete), `start_session` ignores `attachments`, and no web code calls anything. Known limitations carried forward: staging root + chunked writer, staging GC (consumed batches + TTL for abandoned ones), materialization into `{session_dir}/attachments/` with the cross-host refusal, `HostDocumentRef` scope resolution + a unary cross-host fetch, the web picker and host-document browser, and a product PRD + acceptance tests. Verified: `cargo build` and `clippy -D warnings` on tddy-service + tddy-daemon clean; `bun run build` clean; `buf lint --path proto/connection.proto` reports 22 findings, none on the new lines; `./test -p tddy-service -p tddy-daemon --no-fail-fast` 88 targets / 821 passed / 8 failed — all 8 pre-existing sandbox failures (`Operation not permitted (os error 1)`, unprivileged user namespaces; not A/B'd against master since the cause is a kernel EPERM and this diff touches no sandbox path). `packages/tddy-rust-typescript-tests/gen/connection_pb.ts` deliberately **not** regenerated: it is ~4000 lines behind the proto and nothing imports it.
