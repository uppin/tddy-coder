# 2026-11-25 — A target tmux session stays live when its transport drops and re-attaches on view (node 2/3)

**Type:** Feature

Node 2 of the `#target-reconnect` stack (node 1, the `TmuxLocation` port, merged as #1040; node 3, startup re-attach of target chains, follows). `tddy-agent-launch` gains `TargetTmux` (`remote_agent_launch/target_tmux_location.rs`), implementing node 1's port over `TabTargetShell` resolved per call as the session record's `owner_subject`; its attach client runs `tmux -T clipboard attach-session` through the target login shell, never `new-session -A`, so a re-attach never relaunches an agent (Resume keeps `new-session -A`). `tmux_location_of` resolves `HostTmux` for a host record and `TargetTmux` for a target record, skipping `NoOwnerSubject` when the record names no owner (never guessed from the OS user) and `TargetUnreachable(reason)` when the owner's target cannot be resolved. The target probe `target_tmux_session_lives` is tri-state: an ssh 255, a missing tmux (127) or any other non-gone answer is unreachable, never gone.

A target main and a `[target, tmux, agent]` tab are spawned with a `TmuxRun` naming their `TargetTmux` (`ClientMain` replaces `spawn_rendered_client_main`'s positional arguments; `ClientTab` gains the run), so node 1's watcher holds them while the tmux session lives on the target and ends them when it is gone. `reattach_recorded_main` resolves a target record's location and attaches there; `TmuxMainReattach` hands it the daemon's `TabTargetShell`. `.session.yaml` records `owner_subject` at target start, and at resume when absent and a caller is present. The hook-log follower needs no restart on re-attach: it is its own streamed exec on the target and outlives the client with the tmux session. Resolves `docs/dev/todo/2026-11-23-target-tmux-auto-reconnect.md`; narrows `docs/dev/todo/2026-11-22-coder-target-stop-reads-exit-code-1.md` to non-tmux target runs.
