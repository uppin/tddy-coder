# 2026-07-26 — **pr-stack-ux-recovery

**Type:** Fix

no dead-end planned PRs, honest branch/PR state, Planned PRs as a right-side panel** — four defects made the PR-Stack Chat Screen unusable once a stack had been partly worked, all reproduced against a live stack: deleting a child session **wedged its planned PR forever** (the node kept the dead `session_id` and `PlannedPrRow` keyed its mode on `Boolean(node.sessionId)`, so the CTA never came back); a node whose base branch was absent from `origin` **still offered "Start session"**, with the failure landing inside `git fetch` after the session dir and changeset were written; a live PR (#351) **never appeared** because the daemon held no GitHub token and `get_pr_by_head` returned `Ok(None)` — indistinguishable from "no PR" — while the branch name was never rendered at all and `head` was passed unqualified, which GitHub *ignores* (30 PRs returned instead of 1, so `arr.first()` was arbitrary — latent in display, live in `get_open_pr`, which repoints and merges); and the planned-PR list was a hardcoded `w-1/2` column with no toggle and no mobile handling. Now: an **orphaned** node (recorded `session_id`, resolution arrived, `session.exists = false`) offers Start session again pre-filled to **resume the branch it owns**, and the daemon's node link keys on the spawn's **effective branch** so the recovery sticks; `BranchResolution.remote` makes `origin/<branch>` existence a server fact, and an unstartable node shows a blocked **"Missing branch: `<base>`"** indicator in place of the button; PR lookups authenticate with the **operator's own retained GitHub token** (`auth_storage` finally has a reader), `head` is qualified `owner:branch`, and a lookup that cannot be performed reads **"PR status unavailable"** instead of "no PR" — while a stub/demo login stays a clean "no PRs"; and Planned PRs becomes an always-mounted `data-state` **panel** (360px docked on desktop, full-screen overlay on mobile). Review hardening removed the **double PR poll** (`usePrStatus` deleted — two RPCs onto the same `GET /pulls` was ≈1440 req/hour/branch against a 5000/hour limit) and made token retention durable (mutexed read-modify-write, temp+`rename` publish, boot-time `auth_storage` probe). **Breaking for deployments: every signed-in operator must re-login** (scope `read:user` → `read:user repo`) and a configured `auth_storage` must be writable or the daemon refuses to start.
