# 2026-07-21 — **acp-over-livekit

**Type:** Feature

reusable Agent Chat + tddy-coder as an ACP agent + `AcpService` protobuf mirror on the LiveKit session connection** — two stacked deltas on `feat/acp-chat-1`. (1) Extracted the PR-Stack chat into a recipe-agnostic `AgentChat`/`useAgentChat` (frontend, `agent-chat-*` ids) and exposed the TDD workflow as a JSON-RPC ACP agent `tddy-coder --acp` (`acp_agent.rs` over `WorkflowEngine`) with an additive opt-in host bridge `acp_host.rs` (ACP `session/update` → `PresenterEvent`); `tddy-acp` crate holds the shared `mapping` (forward + inverse). (2) Mapped ACP 1:1 onto a protobuf RPC — `tddy-service` `proto/tddy/acp/v1/acp.proto` + codegen → `AcpServiceServer`; `TddyAcpService` (Presenter view-adapter) mounted beside `TddyRemoteServer` in `session_view_adapter_surface`, so `AcpService.Session` rides the same LiveKit connection the browser already uses (no stdio hop). `convert_acp` + `service_acp::OutboundState` cover the full view-adapter signal set (message chunks, stable-id tool-call lifecycle, synthesized `Plan`, agent-initiated `request_permission`, per-turn `EndTurn`). `tddy-core` surfaces `ModeChangedDetails.awaiting_open_answer` (internal-only; TUI/`TddyRemote` unaffected) to signal the free-prompting turn boundary. Web `useAcpSession` mirrors `useAgentChat` (identical `UseAgentChatResult`, shared `AgentChatView`); `AgentChat` gains an `acp` prop and **`PrStackChat` uses ACP** at behavior parity via documented tddy conventions on ACP fields. New "Export" button (`chatTranscript.ts`) downloads a timestamped transcript merging messages + clarification points. The stdio JSON-RPC `--acp` agent is intentionally **not** collapsed onto `TddyAcpService` (different execution context — external host drives a fresh `WorkflowEngine`, no Presenter); only the mapping is kept in lockstep across `tddy_acp::mapping` (acp:: types) and `tddy-service::convert_acp` (prost). Tests: `tddy-acp` mapping 8/8; `tddy_coder_acp_agent_acceptance` + `acp_host_bridge_acceptance`; `tddy-service` `convert_acp` units + `AcpService/Session` runtime acceptance; **`tddy-livekit` `acp_session_livekit.rs` drives `AcpService.Session` over a real LiveKit hop** (passes against the testkit server); Cypress chat suite 44/44. Runtime fix folded in: the daemon `--grpc` session's LiveKit surface was assembled inline in `run.rs` and omitted `AcpService` — consolidated onto `session_view_adapter_surface`. Deferred/superseded: the "drive the per-session host fully via ACP by default" rewire (host-default flip / `backend_is_agent_driven` default / `AcpClient` dedup) is **superseded** by the `AcpService`-over-LiveKit path and is not owed as a stdio-bridge rewire (`acp_host.rs` stays an opt-in external-interop component).
