# 2026-07-26 — **pr-stack-branch-gated-spawn

**Type:** Fix

a PR stack progresses on branches, not on child sessions** — `Stack::base_ref_for_spawn` gated every spawn on the parent node's `session_id` and refused with *"non-merged parent '<id>' has not been started yet"*, so a child session that was closed, cleaned up, or never linked **wedged the whole stack below it** even though the parent's branch existed and was a fine base; `effective_base_refs` compounded it by fabricating `origin/<node_id>` for a branchless parent, a ref nothing ever created. The gate was keyed on the wrong fact: what a child worktree needs is the parent's **branch**. New contract — a spawn is gated on the parent's branch; a child **session** is only a *fallback* route to resolving a node's branch; a `branch_suggestion` is a planned name that never satisfies the gate, so planning leaves `branch = None`. **tddy-core**: `base_ref_for_spawn` refuses on a non-merged parent with no `branch`; `effective_base_refs` counts only branch-bearing non-merged parents; new `resolve_stack_node_branch` (node's `branch`, else its child session's changeset `branch`; missing session dir → `None`, never an error) and `read_stack_with_resolved_branches` (stack hydrated through the resolver, read-only). **tddy-workflow-recipes**: `planned_prs_into_stack_nodes` + `add_planned_pr_node` leave `branch = None`; `reseed_stack_from_plan_if_unspawned` refuses once a node owns a branch **or** a session; `assess::assemble_views` keys the PR lookup on the branch and resolves it via `resolve_stack_node_branch` instead of inventing `feature/<node_id>`. **tddy-daemon**: `link_stack_parent_node_to_child` → `link_stack_node_to_spawned_branch` (repoints last-writer-wins instead of `FAILED_PRECONDITION`); `pr_stack_node_for_spawn` matches by `branch` else `branch_suggestion` and reads the hydrated stack so the fallback reaches the gate; both spawn paths push before linking; `StackChildSpawnHandler`'s duplicate guard keys on the node owning a branch. **tddy-web**: `deriveStackBaseBranch` drops the `?? branchSuggestion` preview. Three pre-existing Rust tests and one web test asserted the *old* "definitive branch at creation" contract and were **inverted** with the implementation (they cannot both hold): `plan_pr_stack::tests::parser_happy_path_three_node_dag`, `tests/plan_pr_stack_acceptance.rs::planned_prs_into_stack_nodes_maps_three_pr_dag`, both cases in `tests/pr_stack_branch_link_acceptance.rs` (retitled "a planned PR owns no branch until a child worktree creates one"), and the suggestion case in `deriveStackBaseBranch.test.ts`. Tests: new `tddy-core/tests/pr_stack_branch_resolution_acceptance.rs` 9 + rewritten `pr_stack_spawn_base_acceptance.rs` 7, `tddy-daemon` `connection_service::stack_child_link_tests` 7, bun `deriveStackBaseBranch` 7; `./test` 2263 passed / 1 failed (pre-existing, unrelated: `tddy-sandbox-recipes` `cursor_cli::tests::cursor_agent_prerequisite_reads_include_install_dir_and_share_root` asserts a macOS-only `/Users` traversal root and cannot pass on Linux); `clippy --all-targets -D warnings` + fmt clean.
