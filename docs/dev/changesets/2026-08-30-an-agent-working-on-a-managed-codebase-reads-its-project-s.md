# 2026-08-30 — an agent working on a managed codebase reads its project's own rules

**Type:** Feature

a managed session's agent works in a *context directory* rather than a repository, and that directory was built from a hardcoded, backend-agnostic list (`CLAUDE.md`, `AGENTS.md`, `.claude`, `.agents`, `skills`, `docs`) that was this project's own layout rather than an agent convention: in an arbitrary target repo it dragged in a thousand files of unrelated prose while omitting `.cursor/` entirely, and on the split path — where the worktree lives on another daemon — it copied nothing at all, so the agent saw a managed-codebase notice and none of the project's guidance. Each backend now declares worktree-root-relative globs for what it actually reads (`context_globs_for_agent` in tddy-core), one predicate (`matches_context_globs` in tddy-sandbox) decides every question of what may be copied, listed, read or deleted, and three streaming RPCs (`StreamContextManifest`, `StreamReadContextFile`, `StreamReadContextFileBatch`) serve the split half — manifest first, then one batched read, so a split start costs 2 peer round trips rather than 1 + N. The managed-codebase notice moves to the **top** of `CLAUDE.md`/`AGENTS.md` and names the paths the sync owns. Replacing git's `.gitignore` gate with an allow-list is the risk this feature turns on, since agent config is routinely gitignored, and it took three properties to make safe: no caller supplies globs, no caller chooses the row (the serving daemon derives it from the session it resolved, or a token for one session type reads another agent's `.mcp.json`), and a resolved symlink's target must itself be allow-listed, or `.claude/creds -> ../.env` ships a secret to another host under an allow-listed name. Four validation passes found 48 issues including that one, and two defects survived their first fix by being repaired on one of two duplicated decision paths — recorded because the lesson generalises: a fix applied to one caller of a duplicated decision is not a fix. ⚠️ **The re-sync trigger is not wired**: the setup sync landed, the continuous half did not, `ContextSyncer::tick` has no production caller, and both blockers are in [docs/dev/TODO.md](../TODO.md). ⚠️ **Both halves of a split placement must be upgraded together.** Feature [agent-context-sync.md](../../ft/daemon/agent-context-sync.md); modules [connection-service.md](../../../packages/tddy-daemon/docs/connection-service.md), [architecture.md](../../../packages/tddy-sandbox/docs/architecture.md).
