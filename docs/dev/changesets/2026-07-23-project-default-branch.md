# 2026-07-23 — **project-default-branch

**Type:** Feature

the git default branch (origin/master vs origin/main) becomes a settable property of the project, with unified resolution** — the remote-tracking integration base ref is now a first-class, UI-settable property of the **project** (`main_branch_ref`), and one resolver backs every default-base path. **`tddy-service`** proto adds `ProjectEntry.main_branch_ref` (field 6) and a `SetProjectDefaultBranch` RPC (regen Rust + `connection_pb.ts`). **`tddy-daemon`** `project_storage::effective_integration_base_ref_for_project` now returns a stored ref verbatim, or — for a legacy row — resolves the default **live** via `tddy_core::resolve_default_integration_base_ref` (`origin/master` → `origin/main` → `origin/HEAD`) instead of the hardcoded `DOCUMENTED_DEFAULT_INTEGRATION_BASE_REF`; the probe is legacy-only and loses effect once a default is set. Project-default validation relaxes to `validate_chain_pr_integration_base_ref` (any `origin/<path>`, incl. slash-containing names; shell-metacharacters still rejected). New `set_project_default_branch` mutator (validate-before-write) + a `SetProjectDefaultBranch` handler that maps `INVALID_ARGUMENT`/`NOT_FOUND` before any write and peer-forwards via `forward_set_project_default_branch_via_livekit` (`classify_peer_route`, like `AddProjectToHost`) so the default is a property of the logical project across hosts; `main_branch_ref` is populated in all `ProjectEntry` mappings, and `StartSession` uses the project's stored default when the client sends no `selected_integration_base_ref` (claude-cli + both sandboxed helpers), legacy falling through to live resolution. **`tddy-web`** adds a per-project default-branch dropdown listing the project's remote branches (via `listProjectBranches`), showing the stored default or pre-selecting `origin/master` → `origin/main`, and calling `setProjectDefaultBranch` on change. Tests: `tddy-daemon` `project_default_branch_resolution_acceptance` 4 + `set_project_default_branch_acceptance` 4 + `project_storage` unit 4, Cypress `ProjectsScreenAcceptance` 12 (7 existing + 5 new); `clippy -D warnings` clean. Known limitation: cross-host peer-forward is wired but acceptance-tested only on the local path (multi-daemon stub-peer forward test is a follow-up).
