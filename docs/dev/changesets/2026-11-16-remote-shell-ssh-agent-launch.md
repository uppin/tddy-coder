# 2026-11-16 — A session's agent runs on its SSH host

**Type:** Feature · `#remote-shell` 3/7, PR [#917](https://github.com/uppin/tddy-coder/pull/917), base `feature/remote-shell/coder-account`, wave 2 of 4

A session can name a **target**: a machine the daemon reaches through the remote-shell port,
with no tddy software on it. The daemon creates the worktree there, starts the coding agent
there in an interactive shell, and serves its terminal as it serves a local one. SSH hosts are
the first kind of target.

## What changed

- **tddy-service**: `SessionTarget { oneof kind { SshTarget ssh = 1; } }`, `StartSessionRequest.target`,
  `SessionEntry.target`; the TypeScript is regenerated in both gen directories.
- **tddy-changeset**: `SessionMetadata.target` in its `.session.yaml` form
  (`target: { kind: ssh, config_host: … }`); a target session reads no host paths.
- **tddy-agent-launch**: `remote_agent_launch` — `shell_for_target`, `remote_agent_command`
  (`cd`, write `$$` to `.tddy/agent.pid`, `exec env -i …`), and `launch_on_target`, which runs
  the transport's interactive command in a local PTY, fails the start on an exit inside the
  startup window with the agent's last output, and records the remote agent as the session
  pointer's owner through `record_remote_owner`. The harness launch gains its remote branch;
  a target combined with a managed codebase, a sandbox, a split placement or the project-home
  main is refused, as is a target named with `ssh_config_host`.
- **tddy-session-lifecycle**: start validation, and stop, exit, delete and resume of a target
  session.

## Verification

Scoped `./test -p tddy-agent-launch` 309 passed, 0 failed after the wrap fix below;
`-p tddy-changeset -p tddy-session-lifecycle` in the same scoped run passed the remote suites
(`remote_agent_launch_acceptance` 6/6, `remote_target_session_acceptance` 9/9). Scoped clippy
(`-D warnings`) and `cargo fmt` clean on the touched packages. The remaining failures in that
local run are macOS platform failures in the sandboxed-codebase and session-sync suites
(BSD `cat`, `/tmp` symlink resolution), untouched by this PR; whole-workspace health is CI's.

A startup-window failure now waits for the PTY capture to settle before quoting it:
`pty_done` is signalled from the exit status, which the PTY reader can lag under load, so
reading the capture at that moment raced the reader and could quote nothing. The flagged test
`an_agent_that_exits_in_the_startup_window_fails_the_start_with_its_last_output` passes 15/15
repeated runs plus three full-suite runs with the fix.
