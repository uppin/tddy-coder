# 2026-07-02 — Specialized subagents (YAML-defined) + session-creation picker

**Type:** Feature

generalizes the single hardcoded FastContext discovery subagent (`docs/ft/coder/discovery-agent.md`, `managed-codebase-subagents.md`) into **specialized subagents**: `tddy_discovery::agent_def::{SpecializedAgentDef, SubagentTool, load_agent_defs, builtin_fastcontext_def, resolve_agent_defs}` loads named configs (model, endpoint, system prompt, bound tools, turn budget) from `<tddyhome>/agents/*.yaml`, with a user-defined def overriding the builtin `fastcontext` def of the same name. `SubagentRegistry::from_defs` resolves any number of registered defs into a new `SpecializedSubagentSession` (system-prompt seeding, tool-gating with unbound-call rejection, EndTurn-on-plain-prose termination) sharing a `send_turn_and_check_final_answer` turn-loop helper with the legacy `FastContextSession` (removed a ~30-line duplication). `tddy-tools` reads `TDDY_SUBAGENTS_JSON` alongside the existing `TDDY_SUBAGENT` gate (back-compat preserved for `TDDY_SUBAGENT=fastcontext` alone); `tddy-coder`'s `create_backend` recognizes any resolved specialized-agent name, not only the `"fastcontext"` literal (explicit `--fastcontext-*` CLI flags still win). New `connection.proto` `ListSubagents` RPC + `StartSessionRequest.managed_codebase`/`.specialized_agents` fields; `tddy-daemon`'s `ConnectionServiceImpl::specialized_subagent_env` resolves named agents into the sandboxed jail's env (an unresolvable name is `INVALID_ARGUMENT`) — the sandboxed claude-cli path already never mounts the repo, so `managed_codebase` is accepted for request-shape clarity rather than toggling mounts. `tddy-web`'s new-session form gains a collapsible "Managed codebase" multi-select. **Deferred** (tracked in `docs/dev/TODO.md`): the standalone `tddy-sandbox-app` CLI was not migrated off its #254 `--discovery-subagent`/`--fastcontext-*` flags; `--agent`'s clap allowlist doesn't yet recognize custom specialized-agent names.
