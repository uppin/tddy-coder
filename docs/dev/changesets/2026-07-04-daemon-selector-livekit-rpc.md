# 2026-07-04 — **daemon-selector-livekit-rpc

**Type:** Feature

top-right daemon selector + LiveKit-only daemon-level RPC** — a `DaemonSelector` on every daemon-mode `tddy-web` screen lists the common-room daemon-role LiveKit participants and re-targets daemon-level RPC (`ConnectionService`, `TaskService`, `ActionService`, `VmService`, `ScreenSharingService`) at the selected daemon's RPC-server identity (`daemon-{instanceId}`) over LiveKit, rather than same-origin HTTP — which only ever reaches the serving daemon. `SelectedDaemonProvider`/`useDaemonClient` (`tddy-web/src/rpc/selectedDaemon.tsx`) own the shared common-room connection and default the selection to the serving daemon via a new `daemon_instance_id` field on `GET /api/config` (`tddy-coder::web_server::ClientConfig`, threaded through `tddy-daemon::server::run_server`). Required no new backend RPC service registration — the daemon already served this full service set over LiveKit in the common room. Migrated all daemon-mode screens (Projects, Worktrees, VMs, Tasks, RPC Playground, the legacy session view, and the new sessions drawer) off `useHttpClient`; per-session terminal/presenter communication is untouched. Surfaced and fixed two latent bugs in the process: a zero-delay reconnect storm in `useTaskListStream.ts` and a missing `App`-level test-injection seam for component tests mounting the full app. `bun test` 422/422, Cypress component suite 400/400, `cargo test -p tddy-coder -p tddy-daemon` clean modulo one pre-existing environmental flake (`livekit_peer_daemons_acceptance.rs`, reproduced identically on the pre-branch base commit).
