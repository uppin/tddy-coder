# 2026-07-03 — Manually add a planned PR + choose ancestors (PR-Stack Chat Screen)

**Type:** Feature

new `AddPlannedPr` RPC (`connection.proto`) lets the operator append a single planned PR to a `"pr-stack"` orchestrator's `Changeset.stack` directly from the web UI, without the existing chat/LLM plan-refinement round trip; ancestors are chosen via a multi-select checkbox picker over the orchestrator's existing planned-PR nodes (`StackNode.parents`). `tddy_workflow_recipes::pr_stack::add_planned_pr_node` is additive-only (never rewrites existing nodes, unlike the chat-driven `reseed_stack_from_plan_if_unspawned`), server-assigns the node id, and validates ancestors/cycles before writing. New `AddPlannedPrForm.tsx` wired into `PrStackScreen.tsx`. Guarded server-side by `require_pr_stack_orchestrator` (rejects non-pr-stack sessions, legacy aliases included). 68 Rust unit tests (`tddy-workflow-recipes`) + 4 Rust unit tests (`tddy-daemon`) + 23 Cypress component tests passing, no regressions.
