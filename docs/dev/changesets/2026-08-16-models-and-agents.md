# 2026-08-16 — **Models & Agents

**Type:** Feature

a provider registry, model lifecycle and assistants** — a per-daemon SQLite registry of providers/models/assistants (`tddy-daemon`), a provider-backed ACP agent (`tddy-acp`), a widened tool vocabulary and credential-carrying agent defs (`tddy-discovery`, `tddy-coder`), a new `models.proto` and an optional ACP session target (`tddy-service`), and a cross-daemon `#/models` screen (`tddy-web`). Two integration seams shipped unwired and were caught in review — `assistant_to_agent_def` had no production caller, so an assistant was listed and then started a Claude session; and the daemon registered no ACP surface, so the chat passed only against its in-memory fake. Both are now closed **with integration tests that fail when the seam is unwired**, which the original unit and component tests could not do. A second review found four more of the same shape, every one of which passed all 6667 CI tests: the tool engine ran unconfined as the daemon uid at a client-chosen path, the provider credential never crossed the assistant→agent boundary, a hung provider wedged the chat forever while `cancel` returned `Ok(())`, and no cloud model was ever offered Chat.
