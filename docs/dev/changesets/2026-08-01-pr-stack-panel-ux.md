# 2026-08-01 — **pr-stack-panel-ux

**Type:** Feature

the Planned PRs panel becomes a control surface: expandable rows, session links, persisted order, live base status, pull-from-base** — the panel told the operator what each planned PR *is*, not what state it is in, and offered no way to act on it. **tddy-core**: `StackNode.display_order` (additive, `Default` derived, ~60 exhaustive literals) separates reading order from the DAG so a merge/repoint no longer moves a row; `Stack::display_order()` never fails (render path — a cycle degrades to declaration order, nothing dropped); new `base_sync` module probes behind/ahead and conflicts via `git rev-list --left-right --count` + `git merge-tree --write-tree`, touching no index, worktree, ref or network, because the existing `pr_resolve_conflicts_action` runs a real `git merge --no-commit` and cannot sit on a 5s poll against a live agent's worktree; it never fetches, and every failure is `Err` rather than a zeroed success since a failed comparison is byte-identical to a healthy one. **tddy-workflow-recipes**: `assign_missing_display_order` on every stack write (topological, declaration-order tie-break, matching what the web rendered); `move_planned_pr_node`; `pull_base_into_node_branch` merging (default) or rebasing in the node's own worktree then pushing, with cleanliness checked before the fetch, a checked-out-branch precondition (the worktree resolver also answers with one merely sharing the tip commit — which would land the base on a sibling's branch and report a push of a branch that never moved), conflicts aborted and reported, a failed abort itself reported, `commit_all_tracked` restoring the index via `write-tree`/`read-tree` on refusal, and a failed push returned as success with `pushed = false` since the local work landed; `force_push_with_lease` gained a `remote` parameter. **tddy-service**: additive `QueryBranchRequest.base_branch`, `BranchResolution.base_sync` → `BranchBaseSync` (with an explicit `unavailable` discriminator), `BranchWorktree.dirty`/`dirty_paths`, `ReorderPlannedPr`, `PullBaseIntoBranch`. **tddy-daemon**: two new non-erroring `query_branch` legs, every git subprocess moved to `spawn_blocking_with_timeout`, and a `base_sync_cache` keyed on the resolved refs *and* both commits (no TTL — the answer is a pure function of the commits; the ref names are in the key because the cached value carries them and two branches at one commit would otherwise swap identities). **tddy-web**: `PlannedPrRow` split into toggle header / always-mounted `display:none` detail / always-visible error footer, badges as a fragment so nothing nests inside the toggle; the status chip wrapped (not replaced) into a control that opens the bound child session; `orderStackNodes` falling back to topological order *wholesale* for a half-numbered plan; `useQueryBranch` keyed by branch+base with monotonic tickets so a poll cannot clobber a completed pull; one per-node guard across merge/rebase/repoint. Review after green caught four defects the suite missed — the wrong-worktree mutation, the missing repoint/pull guard, a failed push rendering as unqualified success (the web read neither `pushed` nor `push_error`), and two mutating RPC handlers with zero test reachability.
