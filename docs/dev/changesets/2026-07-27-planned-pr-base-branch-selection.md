# 2026-07-27 — **planned-pr-base-branch-selection

**Type:** Feature

a planned-PR child session's base branch is operator-selectable, and the daemon honors the explicit choice over the stack-parent resolution** — a planned PR with multiple non-merged parents (a diamond / merge node) used to base its child worktree off whichever parent the resolver walked first (`Stack::base_ref_for_spawn` / `resolveStackBase` iterate `node.parents` in list order), with no control to pick the other parent and a display-only label that never reached the daemon. **tddy-web**: `CreateSessionPane` gains a "Base branch" `<select>` (test id `create-session-base-branch-select`) shown when `initialValues.stackParent` is set and `peerMode` is false; the option list is computed by a new pure `prioritiseBaseBranchOptions(node, nodes)` — direct dependency branches first (non-merged parents that own a branch, ordered by the dependency's own DAG depth, deepest first, ties by `node.parents` order), then every other materialized stack branch that is neither the node itself nor one of its descendants, in stack node order. The selected value is sent on the existing `StartSessionRequest.selected_integration_base_ref`; the selector is hidden when the list is empty (a root node with no other materialized branches) and the field is sent empty, preserving the root → default-branch behavior. `CreateSessionInitialValues` gains `baseBranchOptions`/`selectedBaseBranch`; `PrStackScreen` computes them from the parsed stack. **tddy-daemon**: each of the four spawn paths (`spawn_claude_cli_session_inner`, `start_sandboxed_claude_cli_session`, `spawn_cursor_cli_session_inner`, `start_sandboxed_cursor_cli_session`) uses a non-empty `selected_integration_base_ref` as the worktree base handed to `setup_worktree_for_session_with_optional_chain_base`, overriding the stack-parent-resolved `chain_base_ref` (still computed for the no-choice case and node linking); an empty override preserves today's behavior. `resolve_chain_base_for_session_spawn` is **unchanged** — its `stack_parent → persisted → default` precedence stays for the Telegram / workflow-recipe callers that have no request field, completing the WIP `unified-worktree-base-resolution` PRD's proposed precedence at the spawn seam only. Tests: bun `prioritiseBaseBranchOptions` unit + Cypress `PrStackStartSessionBaseBranchSelectAcceptance`, tddy-daemon spawn-seam precedence unit; `cargo clippy --workspace --all-targets -- -D warnings` + `cargo fmt --check` clean.
