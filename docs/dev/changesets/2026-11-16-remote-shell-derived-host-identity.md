# 2026-11-16 — Derived hosts are offered under the daemon the web addresses

**Type:** Fix · `#remote-shell` 9/11, PR [#925](https://github.com/uppin/tddy-coder/pull/925), base `feature/remote-shell/sweep`, wave 1 of 2

A derived host names its parent by the id the web addresses that daemon with — the routing id, which differs from the durable one when the daemon appends its startup timestamp — and the New-session form lists each daemon's derived hosts on its own: one daemon that never answers withholds nothing, an earlier answer is kept until a newer one arrives, a parent is asked again when it connects, when an account is connected and when the vault opens, and a parent's failure is shown beside the Host field. The Hosts screen asks an online row's daemon through the routing id it carries.

## What changed

- **tddy-service**: `KnownHostEntry.routing_instance_id = 9` — the id an online host answers RPCs on, empty offline. Rust and TypeScript regenerated.
- **tddy-host-service**: `ListDerivedHosts` stamps the parent with the routing id (`local_instance_id_for_config`); `ListKnownHosts` fills `routing_instance_id` for online rows — this daemon's own routing id for the local row, a peer's from `EligibleDaemonSource::routing_instance_id_of`, which pairs `live_known_hosts()` with `list_eligible_daemons()` by position.
- **tddy-client-web**: per-parent derived listing — `askParentForDerivedHosts` (never rejects; bounded by `DERIVED_LISTING_DEADLINE_MS`, 20 s), `mergeParentAnswer` (one parent's answer replaces only its own), `parentsToAsk` (connected and unasked, or every connected parent on refresh); the `DerivedHostsRefresh` port (`DerivedHostsRefreshProvider`, `useRefreshDerivedHosts`, a no-op without a provider) and `useDerivedHostListingFailures`. The superseded all-at-once `listDerivedHosts` is removed; its tests drive the per-parent functions.
- **tddy-web**: `DerivedHostDirectorySources` keeps per-parent answers, asks a parent when it becomes connected, and provides the refresh that asks every connected parent again.
- **tddy-session-create-web**: a parent's listing failure is shown beside the Host field (`create-session-derived-hosts-failure-<parent>`); the daemon itself stays offered.
- **tddy-hosts-web**: an online row's derived hosts and tooling are asked through `routing_instance_id || instance_id`.
- **tddy-workspace-web**: connecting a Coder account (accepted only) and unlocking the vault each call the refresh once.
