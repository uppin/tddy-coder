# 2026-07-23 — **session-worktree-inspector

**Type:** Feature

Worktree tab in the Session Inspector (disk stats + clear/delete/restore)** — the web Session Inspector gains a **Worktree** tab scoped to the selected session's own git worktree: on-disk size + changed-file/±line summary, served cache-first from the existing `ListWorktreesForProject` and refreshed on a **10-minute** client-side poll (`useSessionWorktreeStats`, matched by `repoPath`; `missing` derived client-side), plus a Refresh button. Three lifecycle actions reuse the existing worktree infra: two-step **Clear** (new `CleanWorktree` RPC + `tddy-daemon::worktrees::clean_worktree_under_repo` — membership-gated `git clean -fdx`, refuses the primary worktree), two-step **Delete** (existing `RemoveWorktree`), and **Restore** (new `RestoreSessionWorktree` reusing `tddy_core::resolve_persisted_worktree_integration_base_for_session` + `setup_worktree_for_session_with_integration_base` to recreate a missing worktree from the session's persisted changeset). Handlers mirror `remove_worktree` (auth → validation → `spawn_blocking` under request timeout → stats-cache invalidation → typed error mapping) and are delegated through the tonic adapter. **`tddy-service`** proto adds the two unary RPCs + messages (regen Rust + `connection_pb.ts`); `formatDiskBytes` extracted to a shared `worktreeStatsFormat.ts`. Primary worktree is refused for both Clear and Delete; no backend refresh loop and no remote-host routing (local daemon only). Tests: `tddy-daemon` `worktree_session_actions_acceptance` 3 + `worktrees_rpc` +6 (13 total), Cypress `SessionWorktreeTabAcceptance` 5.
