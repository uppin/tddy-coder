# 2026-09-09 — `analyze coverage` exports real data: object file, harness selection, foreign-source filter

**Type:** Fix

[2026-09-06](2026-09-06-analyze-coverage-runnable-from-the-dev-shell.md) made `tddy-tools analyze coverage` *reach* its first llvm tool; it could still never produce an artifact. Three defects, all dating to the original feature commit (#432), sat behind it. **(1)** `llvm-cov export` was invoked without the instrumented binary. The object file is a required positional argument, so every capture died with `No filenames specified!` — surfaced as `cargo failed:` because each subprocess error in the module is wrapped in `AnalysisError::Cargo`. `export_args` now names the binary, and is unit-tested. **(2)** `build_instrumented_tests` returned the **first** artifact carrying an `executable`, which for any crate with a `[[bin]]` is the binary itself: capture on `tddy-daemon` ran `tddy-daemon --list`, got clap usage, and aborted. Selection is now `profile.test == true`, and **every** harness is captured rather than the first — `tddy-daemon` builds 167, so capturing one reported the other 166 suites' code as untested. Each harness contributes its target's `src_path` as the artifact `spec`, so same-named tests in different suites no longer collide onto one id. **(3)** `FOREIGN_SOURCES_REGEX` matched `/cargo/registry/`, but `$CARGO_HOME` defaults to `~/.cargo`, so the pattern never fired and every dependency's functions entered the CRAP denominator unmeasured — on `tddy-code-analysis`, 5,065 of 5,179. The markers lost their leading `/` and now back both the llvm-cov regex and a Rust-side predicate applied in `normalize_export`. Measured on `tddy-code-analysis`: join **1.1% → 58.3%**, denominator **5,179 → 127**. Feature [rust-code-analysis.md](../../ft/coder/rust-code-analysis.md). (tddy-code-analysis)

**Removed a fallback:** `build_instrumented_tests` used to fall back to "newest extension-less file in `manifest_dir/target/debug/deps`" when no artifact parsed. That path picked non-test binaries — the same failure mode as (2) — and looked in a per-package `target/` that does not exist in this workspace. It now errors instead.

**Not addressed:** 53 of 127 functions still fail the `(file, declaration line)` join, most likely closures, which the `syn` walker scores as independent functions at lines llvm-cov does not declare. Pre-existing and orthogonal.
