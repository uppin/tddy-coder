# 2026-08-14 — every agent session gets a LiveKit room of its own

**Type:** Feature

`session-{session_id}`, hosted by the session's *facilitating* daemon: the one running the agent, which is the only role that always exists (a codebase daemon is optional, appearing when the repo is remote). Getting those two roles the wrong way round inverts the design, so the feature doc states them before anything else uses the words. The room opens before the agent is spawned; a `workspace` session runs no agent and gets none. Three things happen in it, and all three are placement-blind: the daemon serves its whole RPC surface (forwarding to the codebase daemon when the checkout is remote), broadcasts worktree activity once on a new `worktree.activity` topic, and keeps room metadata as the current working-tree summary. Measuring a remote checkout needed a new `GetWorktreeSnapshot` RPC — one round trip per poll, routed by the same classifier a tool call uses. Two primitives were new to `tddy-livekit`: a room-wide broadcast (empty `destination_identities`, its own topic, oversized payloads refused rather than chunked because a fire-and-forget message has no reply to time out) and room metadata over the Twirp server API. Attachments stay on the facilitating daemon, where the agent that reads them runs.
