# 2026-07-03 — **multi-host-projects

**Type:** Feature

dedicated Projects screen + add a project to another host** — new `/projects` screen (`tddy-web`: `ProjectsAppPage`/`ProjectsScreen`, route + `DaemonNavMenu` item) lists projects grouped by logical `project_id` with a row per hosting daemon and a per-project "Add to host" selector sourced from `ListEligibleDaemons` (excluding hosts already hosting it). New `AddProjectToHost` RPC (`tddy-service` `connection.proto`; response reuses `ProjectEntry`) makes an existing project available on another host **reusing its `project_id`**: `tddy-daemon::add_project_to_host` routes local-or-forward (`classify_peer_route` + `forward_add_project_to_host_via_livekit`, same routing as `StartSession`), clones the repo and persists idempotently via new `project_storage::add_or_get_project`. `ListProjectsRequest` gains `local_only` so `LiveKitEligibleDaemonSource::peer_project_entries` can fan out to peers' `ListProjects` without recursion; the create-project form moved out of `ConnectionScreen` (its per-project session accordions stay). tddy-daemon 212/212, `ProjectsScreenAcceptance` 4/4 + `ConnectionScreen` 41/41 Cypress, clippy/fmt clean.
