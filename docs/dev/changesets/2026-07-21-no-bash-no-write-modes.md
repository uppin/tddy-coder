# 2026-07-21 — **no-bash-no-write-modes

**Type:** Feature

agent-driven tool replacement for sandboxed CLI sessions** — a subagent def's `replaces:` can bind ANY exec tool; the session's tool surface is shaped entirely by the agents config (array of `SpecializedAgentDef` coordinates — local Ollama or any OpenAI-compatible backend) with **no mode flags**, and the bindings are rendered into the in-jail CLAUDE.md/AGENTS.md appendix (`tddy-sandbox::sandbox_remote_appendix`). Replacing **`Shell`** makes that def the session's *action author*: `Shell` + native `Bash`/`BashOutput`/`KillShell` are hard-disabled (allowlist omission → `--disallowedTools` incl. `native_aliases` → MCP catalog filter derived from `TDDY_SUBAGENTS_JSON` → host-boundary `Shell`/`Await` reject) and commands run only through declarative session actions: `mcp__tddy-tools__request_action` (author subagent writes a bounded YAML manifest in a 3-attempt correction loop; the untrusted-jail output is re-validated authoritatively host-side by `tddy-sandbox-app::host_actions::establish_action` via shared `tddy_core::session_actions::validate_authored_manifest`, then auto-established under `<session_dir>/actions/` — idempotent re-establish, collision error on redefinition), plus `list_actions`/`invoke_action` host round-trips onto the existing `session_actions` machinery. Replacing **`Write`/`StrReplace`/`Delete`** makes a def the session's *coder*: native `Edit`/`MultiEdit`/`NotebookEdit` hard-disabled too; `tddy-discovery`'s `SubagentTool` gains Managed-only `WRITE`/`STR_REPLACE`/`DELETE` (Local access → typed error; `mutation_tool_definitions()` kept out of the unfiltered FastContext list), with the binding validated before spawn (`validate_tool_replacements`: also at most one Shell replacer). Host-side rejection is deliberately limited to `Shell`/`Await` — other replaced tools are dispatched by the replacing subagent itself through the same relay. Tests: recipes replaces-driven units, appendix rendering, app validation + establish→list→invoke round-trip, `request_action_mcp_acceptance.rs` over the real `--mcp` wire (wiremock author, retry, fake host relay), discovery write-tool units. Follow-ups: Linux/daemon path, non-HTTP backend kinds (e.g. Cursor) as a def-schema extension, async invoke via `session_action_jobs`, repo-catalog promotion.
