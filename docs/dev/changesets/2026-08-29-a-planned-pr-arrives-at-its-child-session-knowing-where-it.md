# 2026-08-29 — a planned PR arrives at its child session knowing where it stops

**Type:** Feature

a pr-stack orchestrator handed each child two strings, its node's title and description; everything it learned while planning stayed behind, and two children building the same abstraction is the result — not a planning failure, since the plan can be perfect and the duplication still happens. Every planned PR now owns a **PRD** and a **changeset** under `artifacts/prs/<node_id>/`, authored by a fourth goal, `write-stack-docs`, between planning and the operator loop; the changeset's `## Dependencies` is the mechanism, naming per parent *what that PR delivers that this one consumes*, and `## Draft PR contract` names the API surface plus failing tests that lets a dependent start early. Both spawn paths attach them **by reference** — a `SESSION_ARTIFACT` ref to the orchestrator's own session and host, so a cross-host stack copies nothing — with a nested source and a flat destination, and a missing document skipped rather than fatal. One daemon-side rule tells the child to read its changeset, applied at every seam that launches an agent and derived from what materialized, matching on the source path so an operator's own `changeset.md` is not mistaken for one. Two prerequisites fell out: `stack-plan.yaml` and `pr-stack-plan.md` were written to the session **root**, where no wire reader looks — both reported `exists: false` and were unreferenceable as host documents — and `write-stack-docs` shipped unregistered with a prompt asking for YAML while `submit` parses JSON, green in every test because none of them drove the CLI. Following #411 it is now a registered goal whose prompt's own example is pinned against its schema.
