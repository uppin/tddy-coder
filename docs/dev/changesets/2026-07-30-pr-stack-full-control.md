# 2026-07-30 — **pr-stack-full-control

**Type:** Feature

the orchestrator agent can update, delete and reparent stack nodes, and read, search and adopt pull requests** — the eight existing `pr_*` tools could only *grow* a stack, and because `reseed_stack_from_plan_if_unspawned` refuses once any node owns a `branch` or a `session_id`, the plan became immutable the moment the stack became real. **tddy-workflow-recipes**: `pr_stack` gains `update_planned_pr_node` (title/description editable any time, `branch_suggestion` only while the node owns no branch, an all-empty input rejected), `sync_node_to_github_pr` (title/body passed explicitly so an unchanged body is never restated over a GitHub edit; blank title refused, blank body allowed since GitHub's `body` is nullable), `delete_planned_pr_node` (reparents children onto the removed node's parents, deduplicated and with the removed id filtered out, refuses `phase == "open"`, reports the orphaned branch/session rather than deleting them), `set_stack_node_parents` (whole new parent list, empty = root, rejects unknown/self/repeated/cyclic before any write, realigns git+GitHub when the node owns a branch), `adopt_pr_as_stack_node` + `adopt_pr_into_stack` (refused when the head branch is bound *or* the pull number is already recorded on a node); the git+GitHub tail of `repoint_planned_pr_node` is extracted to `realign_node_to_effective_base(op, …)` and shared, shrinking repoint by 66 lines with its 9 tests as the guard; four shared validators (`validate_parents`, `reject_if_cyclic`) replace three copies of the dangling-parent loop and two token-identical cycle checks, preserving `add_planned_pr_node`'s deliberately unprefixed messages (a Cypress spec reads `"dangling parent ref"` verbatim). New sibling trait `GithubPrInsightApi` (`get_pr`, `list_pr_files`, `list_check_runs`, `list_reviews`, `list_review_comments`, `list_issue_comments`, `search_prs`, `patch_pr_title_body`) rather than widening `GithubPrApi`, whose eight hand-written fakes care only about lifecycle; new `orchestrate_pr_stack::pr_insight` shapes `read_pr` (one latest review state per reviewer, check runs, files only on request and not even fetched otherwise), `read_pr_comments` (reply-chain threads, bounded walk so a malformed remote response cannot hang the tool, no `resolved` field — GraphQL-only), `search_repository_prs` (repo scope injected; `text`/`author`/`base` refused if they carry `:` or whitespace, since GitHub ORs repeated `repo:` qualifiers and an unguarded value would read another repository with the operator's credential), `pull_number_for_node`; `pr_number_from_status_url` promoted to `pub` so `StackNode` needs no PR-number field and no migration; `github_rest_common` gains `curl_github_get_json_absolute_path` + `GITHUB_API_BASE` for `/search/issues`, which is not under `/repos/{repo}/`. **tddy-tools**: seven `#[tool]` methods + input structs + `call_tool_by_name` arms, delegating only (env resolution + `serde_json` shaping via `pr_read_json`/`pr_comments_json`/`pr_search_json`); `UNKNOWN_TOOL_REJECTION` named so the cross-crate reachability test binds to a contract, not prose; `to_wire` replaces eight copies of the result envelope. `PR_STACK_TOOL_NAMES` 8 → 15 and `PR_STACK_ORCHESTRATE_PROMPT` documents each, pinned by a test that parses the prompt and compares it to the allowlist. Tests: 637 across the two packages (417 + 220) — DAG invariants (no dangling reference survives a delete, rejected calls leave the stack byte-identical), read/search/comment shaping over a stateful in-memory fake, and a real-git test for the rebase-failure path that persists `phase = "error"` without re-targeting the PR; two fake/real divergences found and closed (an empty and a blank `patch_pr_title_body` payload, which the fake accepted and GitHub refuses). Review fixes: a partial write when `sync_pr` had nothing to push, and search-qualifier injection. Known gap: the `curl` request bodies have no coverage (hardcoded API base behind `Command::new("curl")`, same as the existing `GithubPrApi` methods) — recorded with a proposed seam in [TODO.md](../TODO.md).
