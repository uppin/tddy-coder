# 2026-09-05 — the desktop app is `tddy-daemon`, in one process, with no listening socket

**Type:** Architecture Change

Electrobun ran a Bun main process that spawned `tddy-daemon` as a child, resolved its binary from four candidate paths, waited for its HTTP port, and then sent every UI call over `127.0.0.1:8899` — a control plane any local process could reach, orchestrated by TypeScript standing in front of Rust behaviour it could not type-check. It is replaced by a **Tauri** app whose Rust process *is* the daemon. The bootstrap moved out of `main()` into **`tddy_daemon::runtime`** (959 → 183 lines), where `build` is **assembly rather than I/O** — it binds no socket, joins no room and spawns no task — which is what lets the binary and the app assemble the *same* 15-service roster in one process without competing for a port, a socket path or a LiveKit identity; `embedded_runtime.rs` pins that equality. UI↔daemon RPC crosses a **fourth `tddy-rpc` flavour**, webview IPC (**`tddy-tauri-rpc`**, which depends on `tddy-rpc` and never on `tauri`, so the whole flavour is tested without a webview): two commands carrying `rpc_envelope` frames as raw bytes over one duplex channel — deliberately the same shape the LiveKit flavour uses, so the browser-side engine was **extracted into `tddy-rpc-web`** and shared rather than written twice (`tddy-livekit-web`'s `transport.ts` 1067 → 462 lines, its five suites passing unedited). Because a request id restarts at 1 on every page reload while the host may still be streaming for ids the new page is about to reuse, each page connection is a distinct engine peer and reconnecting **abandons everything the previous page opened**. `tddy-web` picks its flavour at runtime and carries the *same* metering and auth-gate interceptor instances either way, so a desktop operator cannot silently lose the auth gate. A new **`DaemonConfigService`** makes the app configurable as what it now is — secrets redacted, validation before any write, atomic rename, `restart_required` for what cannot apply live, and a supervisor that tears the common-room connection down before bringing up the one the new block describes; an unjoinable block leaves the daemon **disconnected with a warning**, never silently on the old room while the UI reports the new one. `GetClientConfig` is **deliberately ungated** — it is what tells a page there is a daemon to sign in to, and is the same payload `/api/config` already serves unauthenticated. ⚠️ **Verified on macOS only**: the `.app` bundle builds and the running app dispatches RPC over the bridge with `lsof` showing no listening socket, but the `.dmg` step needs Finder Automation permission, and **Linux is entirely unverified**. ⚠️ Four gaps are recorded rather than closed: writing the config **loses the operator's YAML comments** (values round-trip), peer discovery does not follow a runtime reconnect, call cancellation never reaches the peer (`RpcRequest.abort` unused — pre-existing), and the desktop host sends no Telegram lifecycle messages.
