# 2026-11-03 — `#tmux-agent` 2/3: a tmux-run agent survives the daemon and is re-attached

**Type:** Feature

`tddy-cli-sessions`: `kill_all` cancels a tmux-run main's client only (n1's `kill_tmux_session_at_shutdown` and `TerminalEntry.os_user` removed; n1's shutdown test rewritten to the detach behaviour); a main's end is classified (`classify_main_exit`: `ClientOnly` while the recorded tmux session lives, else `AgentEnded`), and only `AgentEnded` drops the managed workflow and the exposure; a `ClientOnly` end starts a **detach watcher** (`DETACH_WATCH_INTERVAL`, 10 s) that runs that cleanup once the tmux session is gone; `reattach_main`, `has_managed_workflow`. `tddy-terminal-rpc`: the `MainReattach` port (`NoMainReattach`), consulted by the stream, input and history handlers for `main` only when the store has none running. `tddy-session-lifecycle`: `TmuxMainReattach`, single-flight per session. `tddy-agent-launch`: `reattach_claude_in_tmux`, `agent_tmux_session_is_alive`, `reattach_recorded_main`; `relaunch_claude_cli` re-attaches a live tmux session and starts a gone one fresh; a live same-daemon resume keeps the registered managed workflow (`resumed_recipe`), a restarted daemon binds a new one at the same socket path.

Decisions (developer, 2026-11-03): lazy re-attach as a port in the terminal service (the service has the token's OS user; the store has neither it nor the data dir); same-daemon live resume reuses the registered workflow; a 10 s detach watcher. At wrap: the watcher registry is closed by `kill_all` before the clients are cancelled, so a shutdown leaves no watcher behind; the per-session re-attach gate is forgotten by the last access out.
