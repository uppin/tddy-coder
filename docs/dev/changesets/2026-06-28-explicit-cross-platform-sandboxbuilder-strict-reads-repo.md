# 2026-06-28 — Explicit cross-platform SandboxBuilder + strict reads + repo mount

**Type:** Feature

replaced the implicit jail config (the blanket `(allow file-read*)` wildcard, ad-hoc copies/env, duplicated detectors) with an explicit `SandboxBuilder`→`SandboxPlan` shared by both backends: macOS Seatbelt (`render_plan`/`spawn_plan`, **no wildcard** — explicit reads incl. dyld root `/`, `/dev/*`, ICU, toolchain, `claude` `otool` deps) and Linux cgroups (`plan_to_bind_mounts`/`spawn_plan`, RO bind-mounts + `plan.limits`→cgroup v2). Adds typed `ReadSpec`/`MountSpec`/`CopySpec`/`SymlinkSpec`/`SecretSpec`/`PolicySpec`/`NetworkSpec`/`ResourceLimits`; an out-of-band `CLAUDE_CODE_OAUTH_TOKEN` secret channel (0600 scratch file, set on the inner `claude` child only — never in `sandbox-exec` argv); `CLAUDE_CODE_TMPDIR` redirect; a single-source Claude read/copy recipe (credentials-only seed — host `settings.json` hooks no longer leak); and a writable repo `MountSpec` + runner `--cwd` (`tddy-sandbox-app --repo` mounts the repo read-write and starts Claude in it). Old `render_profile`/template/`spawn`/`seed_claude_home_config` deleted. PRD [sandbox-builder.md](../../ft/coder/sandbox-builder.md); architecture [tddy-sandbox architecture](../../../packages/tddy-sandbox/docs/architecture.md). PR [#243](https://github.com/uppin/tddy-coder/pull/243). Follow-ups: Linux CI verification of the cgroups path (unverified on macOS host), `pivot_root` write-confinement, native-vs-`tddy-tools` tool routing.
