# 2026-07-03 — **claude-sandbox-launcher

**Type:** Feature

`./claude-sandbox` + `tddy-sandbox-app` YAML config + claude arg pass-through** — a one-command launcher for a sandboxed Claude Code session against the current directory as a managed (unmounted) repo, with specialized subagents wired in from a single YAML config. `./claude-sandbox` (repo root): symlink-safe root resolution, passes `$PWD` as `--repo`, resolves host `claude` to an absolute path (jail PATH is only `/usr/bin:/bin`; prefers `~/.local/bin/claude`, skips `*/.superset*/bin` wrapper shims; `--claude-binary` override), builds `tddy-sandbox-app`+`tddy-tools`+`tddy-sandbox-runner` via `nix develop` into one target dir, execs the built binary on the host. `sandbox-config.example.yaml` starter config (`codebase_mode: managed` + inline `fastcontext` re-pointed at Ollama). `tddy-sandbox-app`: new `--config <yaml>` (`SandboxAppConfig`, `deny_unknown_fields`), inline `subagents:` (declaring one both defines and activates it, overrides a same-named builtin), `config::resolve_session_agents` merges named + inline + `agents_dir` defs, `--model` optional, trailing `-- <args>` (`#[arg(last = true)]`) forward to in-jail `claude`; `SpawnParams` carries resolved `specialized_defs` + `claude_args`. `tddy-sandbox-runner`: new repeated `--claude-arg` appended after fixed flags + before MCP args (variadic `--mcp-config` would otherwise swallow a trailing positional prompt); egress shim gained a plain-HTTP forward proxy (`rewrite_http_proxy_request`/`handle_http_forward` sharing `open_relay_tunnel`/`pump_tunnel` with the CONNECT handler) so `base_url: http://localhost:11434` works as-is; persisted MCP/subagent logs via `TDDY_TOOLS_LOG_FILE` → `<session-dir>/egress/tddy-tools.mcp.log` + `RUST_LOG` (`mcp_log_level` config / `--mcp-log-level`), `<session-base>/sessions/latest` symlink; `tddy-tools` `init_logging()` honors `TDDY_TOOLS_LOG_FILE` (append; falls back to stderr). `tddy-discovery::subagent` per-turn logging (request/completion/errors at `tddy_discovery::subagent`). Replaced-tool hard-disable + server-side enforcement: `append_claude_mcp_args` emits `--disallowedTools <native>` + `--disallowedTools mcp__tddy-tools__<tool>` for each replaced tool; `PermissionServer::new()` filters the advertised exec catalog by `resolve_replaced_tools_for_defs(&subagents_from_env())` before merging into the tool router (defense-in-depth, independent of Claude's allow/disallow lists); builtin `fastcontext` `replaces` now includes `SemanticSearch`. 32K Ollama context via `fastcontext-tools-32k.Modelfile` (`PARAMETER num_ctx 32768`) — Ollama's `/v1` endpoint cannot set `num_ctx` per request (ollama/ollama#6137). Verified by a manual full-launch smoke test (config loads → `codebase_mode=managed` → inline `fastcontext` activated, end-to-end through a real macOS Seatbelt jail). **Deferred (Phase 2)**: integration/acceptance test for a full sandboxed launch with an inline Ollama def (interactive terminal-attach path not exercised in CI); a dedicated feature doc file is not split out — knowledge lives in [managed-codebase-subagents.md § Standalone launcher](../../ft/coder/managed-codebase-subagents.md#standalone-launcher-claude-sandbox).
