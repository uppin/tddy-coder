# 2026-07-25 — **worktree-disk-usage-streaming

**Type:** Feature

lazy, semaphore-bounded per-worktree disk usage with a streamed None/Calculating/Cached status** — replaces the eager project-wide size walk with a per-worktree lazy lifecycle bounded by a daemon-global semaphore (2). **tddy-service**: `WorktreeSizeStatus` enum + `WorktreeRow.{size_status, size_calculated_at_unix_ms}`, server-streaming `StreamWorktreeStats` (snapshot + per-worktree increments) + unary `CalculateWorktreeSize` (regen Rust + `connection_pb.ts`). **tddy-daemon**: `WorktreeSizeCalculator` (`tokio::sync::Semaphore`=2, per-project `broadcast`, de-dup, separate `worktree_sizes.json` persistence, permit acquired inside each spawned walk); `stream_worktree_stats` (auth → snapshot → lazy enqueue → forward `Calculating→Cached` broadcasts; `MpscWorktreeStatsStream`), membership-gated `calculate_worktree_size`, `list_worktrees_for_project` size overlay; the unary eager walk is retained as a cache fallback (fully migrating it off is a deferred option). **tddy-web**: `useWorktreeStatsStream` hook + `WorktreesAppPage`/`WorktreesScreen` status column + Recalculate-all / per-row Calculate; `SessionWorktreeTab` migrated off its 10-minute poll onto the stream; new `lib/worktreeSize.ts`.
