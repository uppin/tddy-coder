# 2026-08-14 — a session's worktree can live on a different daemon than its agent

**Type:** Feature

sessions had one host axis; `codebase_daemon_instance_id` adds a second, so an agent on a laptop can work a checkout that stays on a workstation, reaching it only through `mcp__tddy-tools__*` over LiveKit. This is not a new mechanism: `tddy-tools` already speaks `tddy-rpc` and `tddy_livekit::RpcClient` already implements its transport trait, so LiveKit becomes a third binding beside the sandbox's stdio socket and the relay's HTTP endpoint — what is new is the request envelope, because a remote daemon resolves the worktree from the *codebase* session's id against its own sessions base. Restricted to `claude-cli`: it is the only agent that can be *prevented* from touching a local filesystem, and cursor-agent has no allowlist to enforce it with. Two pre-existing bugs surfaced and were fixed on the way: `DeleteSession` removed worktrees only for `claude-cli`, so every `workspace` session leaked its checkout — contradicting a criterion `remote-codebase-mode.md` already claimed — and `tddy-coder --remote` has never completed a session bootstrap despite being documented as shipped. Four pre-PR review passes raised 30 findings across 3 criticals, all resolved.
