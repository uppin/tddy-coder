# 2026-07-01 — stdio RPC transport for gRPC-hosting binaries (partial)

**Type:** Feature

`--stdio` flag added to `tddy-coder`/`tddy-demo` (full remote-control surface, via a new dual-codegen'd `TddyRemote` `RpcService` in `tddy-service`, confirmed to run concurrently with `--grpc`) and `tddy-sandbox-runner` (`Echo`/`EchoStream`/`SessionChannel` incl. real PTY output, via unifying `sandbox.proto`'s message types across its tonic and RpcService codegen passes — mirrors the existing `terminal.proto` dual-codegen pattern). New `tddy_core::stdio_safety` module guarantees fd 1 carries only RPC frames (log-output override + stderr redirect) before any `--stdio` binary serves traffic. `tddy_sandbox_darwin::spawn_plan` pipes the jailed process's stdin/stdout (instead of an egress-log redirect) when `--stdio` is requested; `SandboxHandle::take_stdio()` + `tddy_daemon::sandbox_session::bridge_sandbox_stdio` + a new `StdioEndpoint::from_duplex` constructor bridge them into an async RPC endpoint. `run_host_relay` (the actual production host-side session relay) made transport-agnostic via a new `SessionChannelClient` trait — needed no changes to its PTY/tool/tunnel/egress logic, which already only touches transport-shared `SessionFrame` structs. Sandbox tool-IPC (`tddy-tools` ↔ `tddy-sandbox-runner`) migrated from an unframed single-`read()`/`write_all()` JSON protocol to the same `tddy-rpc` framing over the same socket — `ToolIpcRequest`/`ToolIpcResponse` deleted as dead code. Everything proven end-to-end through a real macOS Seatbelt jail, including a full tool-call round trip via `run_host_relay` + the new `StdioSandboxClient`. **Not done**: `tddy-daemon`'s actual session-lifecycle call sites (`connection_service.rs`/`dial_and_bridge`) still spawn with `--grpc-uds`/`--grpc-listen-port` and dial the tonic client for every real session (the primitives are proven but not wired in); Linux (`tddy-sandbox-cgroups`) jail-spawn stdio piping not attempted (unverifiable on the macOS dev environment that did this work) — both tracked in `docs/dev/TODO.md`.
