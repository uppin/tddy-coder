# 2026-11-17 — An idle orchestrator is woken by what it watches

**Type:** Feature · `#activity-wake` 3/5, PR [#931](https://github.com/uppin/tddy-coder/pull/931), base `feature/activity-wake/session-watches` (#930)

A daemon waker turns watched events into a turn for an idle orchestrator. A bus subscriber
(`WakeTrigger`) notes which session to look at and returns; a `WatchWaker` task waits 2 s to
coalesce a burst, keeps 30 s between wakes of one orchestrator, checks the orchestrator is idle,
and pastes one `[tddy watch]` message into its main terminal through a delivery committed only
when the paste succeeds. The idle reaper leaves a project-home main session holding a live watch
running.

## What changed

- **tddy-session-activity**: `SessionWatchStore::deliver_with` — the delivery computed as
  `take_delivery` computes it, committed (positions advanced, ended watches removed, persisted)
  only when the delivery closure succeeds; on failure nothing moves.
- **tddy-daemon-rpc**: new `exec_tool/watch_wake.rs` — `WakeTrigger` (a bus subscriber that only
  `try_send`s a cue and returns, so it never blocks the publishing hook RPC), `WatchWaker` /
  `ExecToolRpcHandler::start_watch_waker` (settle and minimum-gap scheduling per owner),
  `orchestrator_is_idle` (live main terminal, no pending question of its own, status `Done` /
  `WaitingForInput` / `Started` / `Ended`, absent counts as `Started`), and `wake_text`.
  `project_home/turn.rs` gains `paste_and_submit_to` over a terminal store alone, shared with
  `DaemonProjectHome::paste_and_submit` with no behaviour change. `RpcHandlers::start_watch_waker`
  forwards to the exec-tool handler.
- **tddy-agent-launch**: `IdleObservation.holds_live_watch`; `should_stop` never stops a session
  holding a live watch. `LaunchSessions.session_watches` carries the store and log to the reaper,
  which asks `has_live_watches` per candidate session.
- **tddy-session-lifecycle**: `handler_state.rs` fills `LaunchSessions.session_watches` from the
  host; test support gains `a_home_daemon_keeping_session_watches`.
- **tddy-daemon**: `open_shared` registers `WakeTrigger` on the bus after the project
  notification log, and `start_watch_waker` in `runtime/mount.rs` starts the waker once the RPC
  handlers exist, beside `attach_host_service`.
