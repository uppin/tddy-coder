# 2026-07-12 — **specialized-agent-warmup-gate

**Type:** Feature

wake + await specialized agents before starting the in-jail agent CLI** — new `tddy-discovery::warmup` (`warm_up_agents`, `WarmupOptions`, `AgentWarmupError`, `classify_probe_status`): a backend-agnostic readiness gate that wakes each resolved `SpecializedAgentDef`'s endpoint with a one-token `/v1/chat/completions` probe and waits until every one answers `200`, so a cold **Ollama** model or unreachable endpoint fails session creation/resume **hard** (naming the agent/endpoint/model) instead of stalling the main agent's first `subagent_prompt` — **no fallback** to starting anyway. `502`/`5xx`/`429`/connection-errors are retried to a 120s budget; a `404` (model not found) fails fast. On the 502 question: per Ollama's API docs a `502` means *a cloud model cannot be reached* (or a fronting proxy failed), **not** "model unloaded" — a local cold-load is a blocking `200` — so `502` is a transient, not the readiness signal. `tddy-sandbox-app` (macOS `run_macos`) gates before `spawn_claude_sandbox` with visible output + `ctrl_c` interrupt; `tddy-daemon` gates the sandboxed claude-cli **and** cursor-cli start paths (`FAILED_PRECONDITION`; covers resume, which reuses the start path). No new deps (reuses `reqwest`/`tokio`/`wiremock`). 8 wiremock acceptance + 5 unit tests, all green; `tddy-discovery` suite green, both consumers build, targeted clippy clean.
