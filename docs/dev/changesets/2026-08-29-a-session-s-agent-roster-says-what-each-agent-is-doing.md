# 2026-08-29 — a session's agent roster says what each agent is doing

**Type:** Feature

a roster entry said what an agent *is* and whether its checkout was ready, and nothing about whether it was working: an operator watching a session could not tell a dispatched agent from an idle one, and the main agent had no way to ask. `SessionAgentEntry` gains **`status`** (idle / running / executing_tool / waiting_for_input / connecting / error) and **`last_activity`** (a millisecond stamp plus one pre-truncated summary line), built entirely from signals the daemon already held and riding the existing whole-snapshot `StreamSessionAgents` — no status *read* RPC, because a reader that rebuilt its registry from a snapshot and then had to correlate a second stream could show a status for a row it no longer holds. Two rules carry the design: **the checkout outranks the conversation** (a provisioning clone refuses prompts, so reporting IDLE would offer an agent that cannot answer; an unmeasured clone is CONNECTING for the same reason `roster_entry` already refused to call it READY), and **nothing is persisted** — a status is a fact about a running turn loop, so a restarted daemon reports UNSPECIFIED, *"this daemon has nothing to say"*, never "idle". The daemon records at open / prompt / managed tool dispatch / turn end / cancel / detach and republishes on each, because a status does **not** move `rev`; a turn's end is guarded so a cancel or detach that already landed is not overwritten, and `relay_watching_for_the_turn_to_end` passes a forwarded turn's frames through verbatim so a remote agent's badge comes back down. One **write** RPC did turn out to be necessary — `ReportAgentConversationState` — because an agent the jail was seeded with runs its loop in the jail, where the daemon is never asked to open anything; it refuses an unattached `agent_id` and accepts only the four conversation states, since CONNECTING/ERROR belong to the checkout the daemon measures itself. The roster pane gains a status badge and a last-activity line that ages on its own (an idle agent produces no frames), and a new **`subagent_status`** MCP tool answers "what are my agents doing?" for the main agent — distinct from `subagent_list`, so an attached agent nothing has been asked of appears in one and not the other. ⚠️ Fixed en route: `LiveAgentRoster::apply_snapshot` discarded a frame at the revision already applied, on the once-true premise that one `rev` means one snapshot; `rev` moves only on attach/detach while a status moves every turn, so the in-jail registry would have reported what each agent was doing at the moment it was attached, for the life of the session. A same-rev frame now adopts `entries` and deliberately does not bump `tool_list_changes`. Known and deliberate: a remote or jail-run loop reports no tool calls (so RUNNING and IDLE but never EXECUTING_TOOL), `WAITING_FOR_INPUT` has no producer yet, the session activity hooks stay session-scoped because `ReportAgentActivity` carries no `agent_id`, and a status tick is not broadcast into the session room.
