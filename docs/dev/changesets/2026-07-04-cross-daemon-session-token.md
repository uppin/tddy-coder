# 2026-07-04 — **cross-daemon-session-token

**Type:** Feature

stateless HMAC-signed session tokens verifiable by any daemon** — replaces the per-daemon opaque `Uuid` session token (looked up in an in-memory `HashMap` persisted to `auth-sessions.json`) with a stateless HMAC-SHA256 token `v1.<base64url(claims)>.<base64url(tag)>` carrying the GitHub identity + `iat`/`exp`, signed with the shared `livekit.api_secret`. New `tddy_github::session_token::SessionTokenSigner` (`mint`/`verify`, constant-time tag compare via `subtle`); `AuthServiceImpl::new_signed` mints on `ExchangeCode`, verifies statelessly on `GetAuthStatus`, and the new `RefreshSession` RPC (`auth.proto`) re-mints a fresh token from a valid one. `tddy-daemon::auth::build_auth_entries` derives the signer from `livekit.api_secret` and makes the `SessionUserResolver` verify signatures, so a token minted by the serving daemon is accepted by every peer daemon — fixing `invalid or expired session` on daemon switch in the web UI and the silently-broken peer `ListProjects`/`StartSession`/`AddProjectToHost` forwarding. Web `useAuth` refreshes every 4 min ahead of the 5-min TTL and clears the session on failure; logout is client-side. No `livekit.api_secret` ⇒ auth fail-closed (minting errors, resolver rejects all tokens). Removed the now-dead opaque-UUID/map/persistence model (`new_with_sessions*`, `persist`, `get_user_login`, `sessions()`) and its 3 obsolete tests. `tddy-github` 19/19, `tddy-daemon` lib 236/236 + cross-daemon acceptance 2/2 + resolver 3/3, clippy `--lib -D warnings` + `fmt` clean (one pre-existing env-dependent claude-cli acceptance failure, reproduced identically on the branch baseline, unrelated).
