# 2026-08-16 — session files survive a full disk: swap file + rename

**Type:** Bug Fix

`std::fs::write` opens with `O_TRUNC`, so it discards the previous contents before the first replacement byte lands. A write that failed part-way — `ENOSPC` mid-write, or at writeback after a short `write` — left a **truncated or empty** file where session state used to be, and a 0-byte `.session.yaml` does not read as "write failed", it reads as "not a session": the daemon and `tddy-web` dropped sessions whose agent process was still running and healthy. Same shape for `changeset.yaml`, the workflow engine's `*.session.json` snapshot and the daemon's `projects.yaml`. New `tddy_core::atomic_file` — `write_atomic` writes a **per-call** swap file beside the target (`.<basename>.<pid>.<uuid>.swap`), `write_all` + `sync_all`, carries over the target's permission bits, renames over it, then best-effort `fsync`s the directory, cleaning up and reporting with the target untouched on any failure; `write_atomic_labelled` folds the path into the error, since a bare `ENOSPC` names no file. Everything that persists session or daemon state now goes through it, and three hand-rolled temp-then-rename implementations were folded in — two used a **fixed** temp name (`.changeset.yaml.tmp`, `job.json.tmp`), so two concurrent writers shared one scratch file and either could publish the other's half-written bytes. Deliberately excluded, each for its own reason: `/proc`, `/sys` and cgroup control files (kernel interfaces where a rename is meaningless), ready and completion markers (nothing reads them after a failed write), `tddy-build`'s action cache (deliberately standalone — no `tddy-*` deps — and already unique-temp-sync-rename), and `tddy-tool-engine`'s writes (arbitrary repository files, where replacing a symlink with a regular file would be a behaviour change). Atomic replacement changes the **inode**; nothing watches session files via inotify (`usage_watcher.rs` documents polling as deliberate), and swap files are dotfiles ending `.swap`, so `.md`-filtering directory scans never see one. Tests use a read-only directory to stand in for a full filesystem and no-op as root: `atomic_file` unit tests (fresh write, replacement without leftover bytes, parent creation, **failed write leaves the previous contents intact**, concurrent writers never publish a mixed file, `0600` preserved) plus `session_metadata::failed_metadata_rewrite_leaves_the_session_readable`, the regression at the level it was reported.
