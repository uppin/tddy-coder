# 2026-11-03 — `#tmux-agent` 3/3: every CLI harness session can run its agent in tmux

**Type:** Feature

`tddy-agent-launch`: `cli_harness_tmux` runs cursor-cli and the registered harnesses (opencode, muse, warp) in tmux as the session's OS user — start, resume (re-attach a running pane, else fresh with the harness's resume argv), the lazy re-attach after a restart (`reattach_recorded_main` dispatches by the recorded session type; the main keeps its kind), and `settle_unwatched_agent_exit` before a Resume reads Warp's token. `refuse_a_conflicting_tmux_run_start` covers `TMUX_RUN_SESSION_TYPES`. cursor-cli records `tmux_session` and runs as the session's OS user in tmux mode only. `tddy-cli-sessions`: `start_agent_tmux_session(…, remain_on_exit)`; `tmux/pane.rs` (`remain_on_exit_args`, `capture_final_screen`, `pane_state`); `tmux_exit_hook.rs` — a tmux-run main's exit hook runs on the **agent's** exit with the pane's final screen, never on a client's, and `kill_all` stops the watchers still polling. `tddy-web`: one `CreateSessionRunInTmuxToggle` for every CLI harness type; `createSessionRequest` sends `run_in_tmux` for cursor/opencode/muse/warp; a type switch clears a sandbox or jailed codebase the new type has no control for.

Decisions (developer, 2026-11-03): cursor as the session's OS user in tmux mode only; `remain-on-exit` + `capture-pane` as the exit-hook source; harness re-attach and exit-watch parity after a restart; placement reset on a type switch. Contract deviations kept: the toggle takes `unavailable`; pane commands target `=<name>:` (a bare session target fails on tmux 3.6a); empty `#{pane_dead}` output means the session is gone.
