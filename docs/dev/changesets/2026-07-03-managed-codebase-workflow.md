# 2026-07-03 — **managed-codebase-workflow

**Type:** Feature

workflow-aware, self-managing Claude CLI** — the new-session "Managed codebase" control becomes an explicit checkbox (`CreateSessionPane.tsx`) that gates both a workflow-recipe picker and the specialized-subagents multi-select, sending an explicit `managed_codebase` flag plus `recipe` (reusing existing proto fields — no proto change). When enabled, `tddy-daemon` launches the claude-cli session (sandboxed **or** non-sandboxed) workflow-aware: `ConnectionServiceImpl::prepare_managed_workflow` (shared by all four start/resume × sandbox sites) seeds `changeset.yaml` at `recipe.start_goal()`, builds a per-session `WorkflowController` + toolcall listener (new `session_toolcall.rs`: `set_up_managed_workflow`/`resume_managed_workflow`), injects the recipe's `orchestration_system_prompt` via `--append-system-prompt-file` (threaded through `tddy-sandbox-runner` for the jailed path), and injects a per-session `TDDY_SOCKET`+`PATH` so the agent's host-side `tddy-tools transition` (relayed via `tool_engine::tool_shell` extra_env for sandboxed, PTY env for non-sandboxed) advances the controller, which persists state to `changeset.yaml`. `tddy-core`'s `ToolcallRpcService` gained a per-instance `transition` handler (`with_transition_handler`) that takes precedence over the process-global registry, preventing cross-session bleed. Resume re-wires the workflow at the persisted goal; unknown recipe → `INVALID_ARGUMENT`. Applies to both sandbox modes; `TDDY_AGENT_DRIVEN` (the tddy-coder path) is unaffected.
