# 2026-07-22 — **session-catalog

**Type:** Feature

per-session SQLite catalog for actions + auto-discovered build targets (populate only; reads land later)** — a per-session SQLite DB `<session_dir>/catalog.db` (`tddy-core::session_catalog`, new `sqlx` dep) stores action-manifest and `BUILD.yaml` build-target entries as JSON blobs with a projected VIRTUAL `package` column + index (first index: list targets per package); populated by a `PopulateCatalogTask` (`tddy-task`) that unifies the existing YAML-glob manifest discovery with build targets supplied through a new `BuildCatalogProvider` port (`OnceLock`, mirrors `BuildExecutor`) — concrete `TddyBuildCatalogProvider` in `tddy-coder` over `tddy_build::discover_build_manifests`, registered in `run.rs` (both paths) + the daemon. The coder triggers a background populate on worktree-open; **reads are deferred** — `list_action_summaries` still globs, and the read-path cutover (cross-process `catalog.db` reads via a durable `populated_at` marker + `PopulateTimeout`) plus the daemon populate trigger are tracked in [docs/dev/TODO.md](../TODO.md).
