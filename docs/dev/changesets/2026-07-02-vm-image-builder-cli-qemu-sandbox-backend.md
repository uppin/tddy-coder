# 2026-07-02 — VM image builder CLI + QEMU sandbox backend

**Type:** Feature

new `tddy-vm-build` binary (spec → qcow2/raw image file, sharing `tddy_vm::build::build_image` with the existing `BuildVmImage` RPC); new `tddy-sandbox-qemu` crate (backend + CLI) implementing the `SandboxPlan`/`spawn_plan` contract over a QEMU VM — virtio-9p host-directory mounts, ephemeral qcow2 overlay, in-guest `tddy-sandbox-runner` (cross-compiled `x86_64-unknown-linux-musl`) reached over a forwarded TCP control port via the existing `run_host_relay`; `tddy-daemon` gains an opt-in `TDDY_SANDBOX_BACKEND=qemu` selector. macOS Buildroot builds route through a Docker toolchain (`tddy-vm/docker/buildroot-host/Dockerfile`) — required six sequential bugfixes to work end-to-end (empty bind mounts, `$TMPDIR` sharing, CA certs + stale image cache, a named-volume `/build` for a pkg-config permission bug, container-actual `nproc`, and injecting the written `.config` into that named volume before `olddefconfig`), verified against two real, non-mocked Buildroot builds (`#[ignore]`+`#[serial]`, ~62 min). Guest-side 9p + init-hook documented with real artifacts (`tddy-sandbox-qemu/docs/guest-image-9p-init.md`) but not yet exercised inside a real boot.
