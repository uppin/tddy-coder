# 2026-07-25 — **pr-stack-live-status

**Type:** Feature

the remote branch name becomes the durable link between a Planned PR, its worktree/session, and its GitHub PR, with live status in the web view and a Repoint control** — **tddy-core**: `Stack::base_ref_for_spawn(node_id, stack_bottom_base)` returns a planned node's spawn base (nearest non-merged ancestor's `origin/<branch>`, else the stack default) after refusing (`ChangesetInvalid`) when a non-merged parent is un-started. **tddy-workflow-recipes**: `StackNode.branch` is assigned at creation from `branch_suggestion` (both the agent plan and manual-add paths); `orchestrate_pr_stack::github` gains `PrState`/`PrView`/`pr_state_from_github` + `GithubPrApi::get_pr_by_head` (REST, `state=all`, token-gated); new `pr_stack::repoint_planned_pr_node` drops merged parents, rebases the local branch onto the effective base (skipped when not local) and re-targets the open PR base (`git_ops::local_branch_exists`). **tddy-service**: `proto/connection.proto` adds `SessionEntry.branch = 28`, `PrStatusView`, and the `GetPrStatus`/`RepointPlannedPr` RPCs (regenerated Rust + `connection_pb.ts`). **tddy-daemon**: `resolve_chain_base_ref` now bases a pr-stack child off its node's effective base via `base_ref_for_spawn` (both spawn paths — previously every child was based off the default branch, ignoring the DAG); `get_pr_status`/`repoint_planned_pr` handlers (network/git in `spawn_blocking`, no-token/no-PR → `exists=false`); `SessionEntry.branch` enrichment from `Changeset.branch`. **tddy-web**: `resolveNodeSession` resolves the in-progress child session by branch, `usePrStatus` polls `GetPrStatus` every 5 s to show the PR number/link/state, and a Repoint control calls `RepointPlannedPr`; the drawer keeps an orchestrator reachable while a child is live. Known limitation: Repoint availability derives from the stored stack `pr_status` (`StackNode::is_skipped`), not the live poll (per the PRD contract; reconciling is a follow-up). Tests: tddy-core `pr_stack_spawn_base_acceptance` 4, tddy-workflow-recipes `pr_stack_branch_link`/`pr_stack_repoint`/`pr_status_view` (2+2+4) + full crate suite, tddy-daemon `apply_session_list_status_populates_branch_from_the_changeset` + `resolve_chain_base_ref` tests, web `resolveNodeSession` 3 + Cypress `PrStackLiveStatusAcceptance` 8; `cargo fmt --check` + `clippy -p tddy-core -p tddy-workflow-recipes -p tddy-daemon --all-targets -D warnings` clean.
