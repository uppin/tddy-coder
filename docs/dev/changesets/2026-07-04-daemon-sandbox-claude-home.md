# 2026-07-04 — **daemon-sandbox-claude-home

**Type:** Fix

real claude binary resolution + persistent jail `$HOME` for sandboxed sessions** — sandboxed claude-cli sessions passed a bare `claude` as `--claude-binary`; `Path::parent("claude") == Some("")` made `binary_exec_reads` emit `(subpath "")`, which macOS `sandbox-exec` rejects (`empty subpath pattern`, exit 65) → child dies before the ready marker → `deadline_exceeded`. Fixes: `binary_exec_reads` skips empty parents (tddy-sandbox); `SandboxBuilder::build` drops empty-host reads so `(subpath "")` can neither reach a rendered profile nor shadow the whole read allow-list. `config::resolve_claude_binary_path` resolves the real host `claude` to an absolute path (prefers `~/.local/bin/claude`, skips Superset `*/.superset*/bin` wrapper shims), overridable via `TDDY_CLAUDE_BINARY` env or `claude_cli.binary_path`; the `dev.daemon.yaml` `claude_cli` block is commented out (absent → auto-resolve). Persistent daemon-wide jail `$HOME` (auth/history reuse, parity with `./claude-sandbox`): `seed_claude_credentials`/`seed_claude_local_install` relocated into `tddy-sandbox-recipes`; `config::resolve_claude_home_dir` (`TDDY_SANDBOX_CLAUDE_HOME` > `claude_cli.claude_home_dir` > `$HOME/.tddy/sandbox-claude-home`); both sandbox sites mount the home read-write and pass `host_home: None` (new `SandboxRunnerSpawn` field) so a jail-refreshed OAuth token is never clobbered. Per-OS shared-config **discovery only**: `config::resolve_sandbox_config_path` (`TDDY_SANDBOX_CONFIG` > per-OS `claude-sandbox.<os>.yaml`, OS token `darwin`/`linux` > generic `claude-sandbox.yaml`) — **the loader / `SandboxAppConfig` extraction is a follow-up**. `cargo test` green (tddy-sandbox 22, tddy-sandbox-recipes 15, tddy-daemon 249, tddy-sandbox-app); clippy `--all-targets -D warnings` clean; only the pre-existing flaky `spawner::daemon_data_dir_passthrough_tests` (fails on clean master too) is intermittent.
