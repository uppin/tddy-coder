# 2026-07-30 — **session-branch-conflict

**Type:** Feature

creating a session on a branch another session already owns prompts the operator instead of silently creating `<branch>-1`** — the `-1` came from `tddy_core::worktree::create_worktree_with_retry`, reached from the `NewBranchFromBase` arm that skips the existing-worktree reuse check the `WorkOnSelectedBranch` arm does; `StartSessionResponse` carried no branch, so an operator who asked for `feat/auth` and got `feat/auth-1` was never told. **tddy-service**: `StartSessionRequest.on_branch_conflict` (field 30, `""` = suffix as before / `"reject"`) and `StartSessionResponse.branch_conflict` (field 5) → new `BranchConflict { branch, BranchSession owner, suggested_branch_name }`, reusing `QueryBranch`'s `BranchSession`; six existing `StartSessionResponse` literals gained `branch_conflict: None`. A **populated response field, not an RPC error**, because `tddy_rpc::Status` is `{code, message}` with no details channel (`status_to_error_body` hardcodes `details: vec![]`, and nothing in the repo uses error details) and `StartSession` is forwarded host-to-host over LiveKit where only the response message is guaranteed intact. **tddy-daemon**: new `branch_owner::find_session_owning_branch` holds the one ownership rule (prefer active, tie-break `updated_at`, skip unreadable changesets), lifted out of `query_branch`'s inline closure so the RPC guard, `QueryBranch` and Telegram cannot drift; `owned_branch_conflict` runs in `start_session` after peer routing (so a cross-host request is checked on the daemon owning the sessions root) and before the session-type dispatch, creating nothing when it fires. **tddy-core**: read-only `first_free_suffixed_branch_name` supplies `suggested_branch_name`; `create_worktree_with_retry` untouched. **tddy-web**: `CreateSessionPane` sends `"reject"` (peer spawns send `""`) and a `branchConflict` response opens the new `BranchConflictDialog` — switch to the owning session / add a second agent on that branch (`work_on_selected_branch`, sharing the owner's worktree) / rename (editable, pre-filled with the suggestion); pure mapping in `lib/branchConflict.ts`. **Telegram** carries the same check in `handle_telegram_branch_callback` with a `tbc:` three-button keyboard (branch name re-derived server-side — `callback_data` caps at 64 bytes). Opt-in by design: only surfaces that can prompt ask to be rejected, so recipe hooks, PR-stack chain spawns and `RestoreSessionWorktree` keep suffixing; scope is **session-owned branches only** — a bare git branch still suffixes, since there is nothing to switch to. `tddy-coder`'s TUI/plain paths are not session-creation surfaces (they bootstrap a worktree inside a running session) and are unchanged. Tests: `session_branch_conflict_acceptance` 9, `telegram_branch_conflict_acceptance` 7, `branch_owner_unit` 5, `worktree_acceptance` 9 (+3), Cypress `CreateSessionBranchConflictAcceptance` 9 + peer-spawn negative, `branchConflict.test.ts` 3; `clippy --all-targets -- -D warnings` + `vite build` clean.
