# 2026-07-24 — **terminal-file-drop-insecure-origin

**Type:** Fix

the dropped file's path actually reaches the terminal** — two independent bugs both presented as "drag a file onto the web terminal, nothing happens". **tddy-web**: (1) the per-drop `upload_id` came from `crypto.randomUUID()`, a **secure-context-only** API, so on the usual plain-`http://` LAN origin `uploadFiles` threw (`crypto.randomUUID is not a function`) before a single chunk was sent — no progress, no error, no path; new `lib/randomId.ts` `randomUuid()` (native → `crypto.getRandomValues` → `Math.random`, keeping the v4 shape because the daemon validates `upload_id` as a single path segment) fixes it for the drop zone and the mobile Attach button alike. (2) `UPLOAD_CHUNK_SIZE` 256 KiB made every upload request ~5 LiveKit chunk frames; one dropped frame leaves the peer's `ChunkReassembler` permanently incomplete (no timeout, no eviction), so the RPC was never answered and the upload stalled mid-file, silently — chunk size drops to **48 KiB** with `UPLOAD_REQUEST_ENVELOPE_HEADROOM` (8 KiB), pinned in test against `MAX_CHUNK_FRAME_BYTES`, and `useDaemonUploadChunk` sends each chunk with `{ timeoutMs }` (`UPLOAD_CHUNK_TIMEOUT_MS` = 20 s) so a stalled chunk fails that one file through the existing skip-and-report path. **tddy-livekit-web**: `LiveKitTransport.unary` stops ignoring the `timeoutMs` call option (deadline timer → `ConnectError(Code.DeadlineExceeded)`, cleared on response/error/abort; opt-in per call so slow RPCs like `StartSession` are unaffected) and exports `MAX_CHUNK_FRAME_BYTES`. Verified end-to-end over a live LiveKit data channel (LAN browser → dev daemon, claude-cli session, 2 MB PNG: 41 chunk RPCs, `write_upload_chunk: completed`, `SendTerminalInput` with the quoted path, and the session's PTY capture buffer showing the path in Claude Code's prompt). Tests: `randomId` 6, `fileUploadChunks` 5, `transport` 8 (+3 deadline), whole tddy-web + tddy-livekit-web unit suite 550, Cypress upload specs 10. Known gaps carried forward: `publishRequest` still doesn't await `publishData` per frame (no SCTP backpressure for still-oversized payloads), and a drop is round-trip bound (~40 s for 2 MB) with feedback only in the footer — a write-at-`offset` upload RPC and terminal-local progress are the tracked follow-ups.
