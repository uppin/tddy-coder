# 2026-11-16 — SSH hosts as hosts derived from a daemon

**Type:** Feature · `#remote-shell` 5/7, PR [#919](https://github.com/uppin/tddy-coder/pull/919), base `feature/remote-shell/coder-shell`, wave 3 of 4

The machines a daemon can reach through a remote shell appear as hosts of their own: in the Host field when starting a session, and on the Hosts screen under the daemon that reaches them. SSH config aliases are the first kind. Choosing one starts a session whose agent runs there.

## What changed

- **tddy-service**: `proto/host.proto`: `rpc ListDerivedHosts`, `DerivedHost { id, label, kind, parent_instance_id, session.SessionTarget target }`, `DerivedHostKind { UNSPECIFIED, SSH }`; the host prost/tonic passes take `.session` / `.types` as `extern_path` so the import writes no second `session.rs`. TypeScript regenerated in both gen directories.
- **tddy-host-service**: `src/derived_hosts.rs`: `trait DerivedHostSource`, `SshConfigDerivedHosts` (id `<parent_instance_id>/ssh/<alias>`); the handler in `src/service/derived_hosts.rs` asks every registered source and answers `FAILED` with the first reason while still carrying the hosts that listed; extra kinds register with `with_derived_host_source`.
- **tddy-client-web**: `hostDirectory/derivedSource.ts` (`listDerivedHosts`, `derivedHostDescriptorOf`); `HostDescriptor.parent` / `.target`, carried through `DaemonHost` and the clients port.
- **tddy-hosts-web**: `DerivedHostRows` under each daemon's row, marked with the kind, with no daemon-only cells; a listing failure shows on the parent's row.
- **tddy-session-create-web**: the Host field groups derived hosts under their parent; choosing one sends the parent as `daemon_instance_id` with the derived host's target, and says prompts are answered in the terminal.
- **tddy-session-web**: the drawer item names the derived host a session runs on, from `SessionEntry.target`.
- **tddy-web**: `DerivedHostDirectorySources` (`app/rpc/hostDirectory/derivedSource.tsx`) registered inside `ConnectionProviders` in `SelectedDaemonProvider`, asking each parent over its own `HostConnection`.
