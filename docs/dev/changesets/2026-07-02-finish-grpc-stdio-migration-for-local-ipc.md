# 2026-07-02 — Finish gRPC→stdio migration for local IPC

**Type:** Feature

closes the three items PR #253 deferred. `tddy-daemon`'s real sandboxed-session lifecycle (`connection_service.rs` spawn/dial orchestration, `sandbox_session::dial_and_bridge`) now dials `tddy-sandbox-runner` exclusively over its stdio-served `SessionChannel` (`bridge_sandbox_stdio` → `StdioSandboxClient` → `run_host_relay`) — `--grpc-socket`/`--grpc-listen-port`/`--grpc-uds` and the port/ready-marker handshake deleted outright for this call site (no dual-path fallback); `tddy-sandbox-runner`'s vestigial `grpc_socket` arg is now `Option<PathBuf>`. `tddy-sandbox-cgroups::spawn_plan` gains the matching `--stdio` stdin/stdout piping `tddy-sandbox-darwin::spawn_plan` already had (compile-checked only — no Linux dev box; needs a real-jail CI run). `tddy-core`'s toolcall relay (`tddy-tools` ↔ session-owning process) moved from a bespoke newline-delimited-JSON protocol to a new `ToolcallRpcService` served over `tddy-rpc`/`tddy-stdio` (`StdioEndpoint::from_duplex`), dispatching `Submit`/`Ask`/`Approve`/`ListActions`/`InvokeAction`/`Build`/`BuildList` by RPC method name — wire payloads unchanged, only framing moved; new `tddy_tools::toolcall_client::dispatch_toolcall` mirrors the sandbox tool-IPC client precedent. The sandbox-runner's own gRPC server is retained (serves `tddy-sandbox-app`'s standalone demo and `sandbox_action.rs`'s separate generic-action-execution flow, both out of scope). Fixed one real regression along the way: `cli_integration.rs`'s fake relay server still spoke the old raw-line protocol and hung forever against the new framed client — rewritten to host a fixed-response `RpcService`.
