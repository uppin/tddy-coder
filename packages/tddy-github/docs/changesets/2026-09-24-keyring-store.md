# 2026-09-24 — Logins retain their GitHub token in the credential vault; UnlockVault and ResetVault

**Type:** Feature

`#keyring` 3/9, PR [#510](https://github.com/uppin/tddy-coder/pull/510). Cross-package entry: [`docs/dev/changesets/2026-09-24-keyring-store.md`](../../../../docs/dev/changesets/2026-09-24-keyring-store.md)

`token_store.rs` (`GitHubTokenStore`) is **deleted**. `AuthServiceImpl::with_credential_vaults(Arc<SessionVaults>)` replaces `with_token_store`: `complete_login` retains a `github` `CredentialRecord` (`GITHUB_ID_METADATA`, `AVATAR_URL_METADATA`) through `SessionVaults::retain` after admission, and every login, refresh and status response carries `vault_state` and, when there is one, `vault_unlock_key`. `RefreshSession` reopens and rotates through the presented key (a key that no longer opens refreshes with `""`; an unreadable vault hands the presented key back); `Logout` removes the slot or, with no key, discards the pending token. New handlers `UnlockVault` and `ResetVault`: access-token caller only, a fresh sign-in's pending token required to create or reset (`NoFreshLogin`), reset refused while open (`AlreadyOpen`), passphrase 8–1024 chars, Argon2 on `spawn_blocking` behind a semaphore of 2, per-login backoff (3 free, 2 s doubling to 15 min, `resource_exhausted`). A clock before the epoch is an explicit error. The vault half lives in `src/auth_service/vault.rs` (and `vault/backoff.rs`), split out in its own commit: `auth_service.rs` 621 → 379 production lines (384 after the wrap's fixes), `vault.rs` 290 (433 after). Detail: [device-flow.md](../device-flow.md#the-credential-vaults-half-of-authserviceimpl).
