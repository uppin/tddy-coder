# 2026-08-29 — `subagent_status`, and the same-rev frame that makes it work

**Type:** Feature

a new MCP tool reports the live roster: id, label, model, host, status, clone state, `replaces`, this process's conversations with each agent, and `lastActivity`. Distinct from `subagent_list`, which enumerates conversations and their token cost — an attached agent nothing has been asked of appears in one and not the other. `UNSPECIFIED` is reported as `"unknown"`, never `"idle"`, so the main agent does not dispatch work to a row the daemon cannot account for; a roster gone dark still answers, carrying `refusal`. ⚠️ Fixes a regression the status fields introduced: `LiveAgentRoster::apply_snapshot` discarded a frame at the revision already applied, on the once-true premise that one `rev` means one snapshot — but `rev` moves only on attach/detach while a status moves every turn, so the registry would have reported what each agent was doing when it was attached, forever. A same-rev frame now adopts `entries` and deliberately does not bump `tool_list_changes`. A jail-run conversation reports itself through `ReportAgentConversationState` at open / prompt / turn end / cancel, best-effort and only for a loop running here.
