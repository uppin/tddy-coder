# 2026-08-29 — a subagent turn that outruns its caller's patience hands back a `responseId` instead of holding the call open

**Type:** Feature

`subagent_prompt` blocks for at most `graceMs` (default 25 s, named **per call** because how long a caller can afford to wait is the caller's fact, not the host's): a turn that yields in time returns `{stopReason, content, usage}` byte-for-byte as before, and one still running returns `{responseId, pending: true}` **without being cancelled** — the turn continues in a background task and the new **`subagent_await`** `{responseId, timeoutMs?}` collects it, in the same outcome shape, or answers `pending` again so the agent retries. Collecting is non-destructive and repeatable: a tool result lost between this process and the main agent would otherwise make a computed answer permanently unreachable. The enabling change is to the locking: `subagent_prompt_tool` used to hold the **process-wide** session table across `session.prompt().await`, so a long turn blocked `subagent_list` and even the `subagent_cancel` that would have ended it. The table is now a registry the tools take and release, each conversation's session sits behind its own fair `tokio::sync::Mutex` — which *is* the queue, so a prompt arriving mid-turn runs after it and against the history it leaves — and `SubagentConversation` carries its own `model`/`usage`, refreshed at each turn's end, so a listing answers while a turn runs and reports the totals as of the last **completed** turn rather than a partially-billed one. `PendingTurns` holds the `watch::Sender`, so a turn publishes under the table lock it already needs for its accounting and any number of awaiters hold receivers without holding the table; `resolve` and `cancel_conversation` both publish only over a turn still running, so a cancel landing after an answer cannot replace it and vice versa. `subagent_cancel`, and a detach that cancels a conversation underneath a prompt, resolve every pending turn of it as cancelled — an await for a turn nobody will finish has to answer. A malformed `graceMs`/`timeoutMs` is refused naming the field rather than replaced by the default; `0` is a budget of its own ("hand me the id"), not an absence.
