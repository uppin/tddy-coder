# 2026-08-29 — `submit` routes on `--goal`, and refuses a goal it cannot resolve

**Type:** Bug Fix

`run_submit` read the routing goal only from the payload's `goal` field, defaulting to `unknown`, and used `--goal` solely to select a validation schema; `submit --goal write-stack-plan` therefore relayed as `unknown` and delivered to nobody while printing `{"goal":"unknown","status":"ok"}`. New `resolve_submit_goal` resolves the goal **once** — `--goal` first, payload `goal` as fallback — and that one value drives both validation and relay. ⚠️ A submission naming no goal in either place now exits **2** naming `--goal` as the remedy, and a `--goal` contradicting the payload exits **2** quoting both, where either previously succeeded. Goals with no registered schema still relay on `--goal` alone, which for them is the only routing signal. `write-stack-plan` also becomes a registered goal, so a wrong-shaped plan fails with the offending paths instead of passing validation that never ran. Covered by `tests/submit_goal_routing_acceptance.rs`, which drives the real binary.
