# 2026-07-30 — **session-branch-conflict

**Type:** Feature

read-only `first_free_suffixed_branch_name(repo_root, branch)`** — returns the first `<branch>-<n>` (`n` from 1) no local branch holds (one `git for-each-ref refs/heads` call via a private `local_branch_names`), i.e. the name the private `create_worktree_with_retry` suffixing loop would land on, **creating nothing**. Backs the `suggested_branch_name` a refused session creation reports, which pre-fills the operator's rename field. `create_worktree_with_retry` is deliberately untouched — it remains the path for `on_branch_conflict = ""`, still pinned by `worktree_acceptance::setup_worktree_retries_with_suffix_when_branch_name_conflicts`. Search is uncapped rather than mirroring `MAX_WORKTREE_RETRIES = 20` (the cap exists because the loop *creates*; a read-only search terminates after at most `taken.len() + 1` probes) and a repo whose refs cannot be listed reports nothing as taken, suggesting `<branch>-1`. Tests: `worktree_acceptance` 3 new (first free suffix, skips taken suffixes, creates nothing) — 9 total; `clippy -- -D warnings` + `cargo fmt --check` clean.
