# 2026-08-01 — **PR-stack panel

**Type:** Feature

persisted row order and a non-mutating base-sync probe** — `StackNode.display_order: Option<u32>` (additive, `Default` derived, ~60 exhaustive literals updated) separates the operator's reading order from the DAG, so a merge/repoint/re-parenting no longer moves a row; `Stack::display_order()` sorts on `(display_order, topo index, node_id)` and **never fails** (a cycle degrades to declaration order, nothing is dropped) because it is a render path. New `base_sync` module: `resolve_base_sync_refs` + `compare_base_sync_refs` (split so a poller can cache on the two SHAs) + `branch_base_sync`, using `git rev-list --left-right --count` and `git merge-tree --write-tree`, which touch no index, worktree, ref or network — the existing `pr_resolve_conflicts_action` runs a real `git merge --no-commit` and could never sit on a 5s poll against a live agent's worktree. Never fetches; every failure is `Err`, never a zeroed success, because a failed comparison is byte-identical to a healthy one. `worktree::checked_out_branch_name` added so a mutating caller can verify a resolved worktree really holds the branch. Tests: `branch_base_sync_acceptance` (12, incl. a probe proving working tree, index and `HEAD` are byte-identical across a *conflicting* run). (tddy-core)
