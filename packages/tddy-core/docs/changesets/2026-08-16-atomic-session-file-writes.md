# 2026-08-16 — **atomic session-file writes

**Type:** Bug Fix

swap file + rename** — new `atomic_file` module: `write_atomic` writes a **per-call** swap file beside the target (`.<basename>.<pid>.<uuid>.swap`), `write_all` + `sync_all`, carries over the target's permission bits, renames over it, then best-effort `fsync`s the directory; any failure is cleaned up with the target untouched. `write_atomic_labelled` folds the target path into the error, since a bare `ENOSPC` names no file. `std::fs::write` opens with `O_TRUNC`, so a write that failed part-way left a **truncated or empty** file where session state used to be — and a 0-byte `.session.yaml` reads as "not a session", not as "write failed", so the daemon and `tddy-web` dropped sessions whose agent process was healthy. `session_metadata.rs`, `changeset.rs`, `output/writer.rs`, `workflow/session.rs`, `workflow/action_cache.rs`, `session_action_jobs/runner.rs`, `session_actions/runtime.rs`, `backend/{codex,cursor}.rs` and `presenter/presenter_impl.rs` all route through it; two folded-in hand-rolled implementations used a **fixed** temp name (`.changeset.yaml.tmp`, `job.json.tmp`), so two concurrent writers shared one scratch file and either could publish the other's half-written bytes. Deliberately excluded: `/proc`, `/sys` and cgroup control files, ready/completion markers, `tddy-build`'s standalone action cache, and `tddy-tool-engine`'s arbitrary repository-file writes.
