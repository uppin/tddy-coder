# 2026-07-27 — **remove-origin-hardcode

**Type:** Bug Fix

no `worktree`/`session_chain` code path assumes the `origin` remote** — `validate_integration_base_ref` / `validate_chain_pr_integration_base_ref` accept any safe `<remote>/<path>` (pure string rules, no git probe; error strings drop `origin/`). New `detect_default_remote_name(repo_root) -> Option<String>` runs `git rev-parse --abbrev-ref @{upstream}` and splits on the first `/` (returns `None` on detached HEAD / missing upstream / git error). New `resolve_default_integration_base_ref_with_remote(repo_root, preferred)` chooses `preferred` → detected → `origin` (last resort), then `git fetch <remote>` and probes `<remote>/master` → `<remote>/main` → `refs/remotes/<remote>/HEAD` (bare `resolve_default_integration_base_ref` delegates with `None`). `fetch_integration_base` / `fetch_chain_pr_integration_base` split the validated ref on the first `/` into `(remote, path)` and run `git fetch <remote> <path>`. `push_new_branch_to_origin` → `push_new_branch_to_remote(dir, branch, remote)` (legacy `origin` wrapper retained); `list_recent_remote_branches*` take a `remote` and filter `<remote>/`; `local_branch_name_for_remote(ref, remote)` strips one leading `<remote>/` (legacy `local_branch_name` strips `origin/`); `DOCUMENTED_DEFAULT_INTEGRATION_BASE_REF` → `FALLBACK_DEFAULT_INTEGRATION_BASE_REF`. `session_chain::resolve_chain_integration_base_ref_from_parent_session` builds `<remote>/<trimmed>` from the child project's resolved default remote. Tests: `worktree.rs` unit (validators, detection, resolution, `local_branch_name_for_remote`, `list_recent_remote_branches` for non-origin) + acceptance (`remote_branch_ref_acceptance`, `resume_selected_branch_acceptance`); `clippy -- -D warnings` + `cargo fmt --check` clean.
