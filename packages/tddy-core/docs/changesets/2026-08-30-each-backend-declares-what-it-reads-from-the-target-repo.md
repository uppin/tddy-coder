# 2026-08-30 — each backend declares what it reads from the target repo

**Type:** Feature

`context_globs_for_agent` sits beside `curated_models_for_agent` and answers the same shape of question for files: worktree-root-relative globs naming the agent configuration a backend reads from the **target** repo, never from this project's own layout. `CodingBackend::context_globs` defaults through it, so a caller holding a backend and one holding only an agent name read one table. An unrecognised name yields the shared base (`AGENTS.md`, `.agents/**`) alone — a deliberate *narrowing*, because a default returning the union of every row would hand `.claude/` and its permissions to an agent nobody vetted, which is the widening a compiled-in allow-list exists to prevent. `docs/**` and `skills/**` are deliberately absent: they are this repository's documentation conventions, not agent-tool ones, and in an arbitrary target repo they are a thousand files of unrelated prose that would cross the peer link on every split start. `.claude/settings.local.json` is withheld by an exclusion list in `tddy-sandbox`, because the daemon replaces that file wholesale on a managed session.
