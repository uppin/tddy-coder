# 2026-08-30 — the jail denies writes to the context dir, which it never actually did

**Type:** Bug Fix

the agent-context-sync changeset removed the `chmod 0444` on the context directory, justified by the claim that the sandbox already mounted it read-only. That claim was false and load-bearing: `context_dir` is `sandbox_root/context`, `project_root` is `sandbox_root`, and `render_plan` emits `(allow file-write* (subpath project_root))`, so the directory sat *inside* the writable subpath and the file mode was the only thing holding it. `render_plan` now emits `(deny file-write* (subpath <context_dir>))` **after** the project-root allow — seatbelt is last-match-wins, verified by experiment in both orders — so the jailed agent cannot overwrite its own `CLAUDE.md` and delete the managed-codebase preamble, while the host-side syncer, which is not confined by the profile, still writes freely. The path is read from the runner argv's `--context-dir`, the only channel that already carries it, which also protects the daemon's Claude, Cursor and split-session paths without touching them. Stricter than the mode it replaces: 0444 left directory modes alone, so an agent could still create new files. Pinned by two real `sandbox-exec` acceptance tests, whose project tree is deliberately outside `TMPDIR` (the profile grants `/var/folders` wholesale, so a tempdir-rooted fixture would prove nothing).
