# 2026-08-30 — a jail no longer holds any part of the host's per-user temp base

**Type:** Fix

every rendered profile granted `/var/folders` read *and* write three times over: the grandparent of whatever `TMPDIR` the daemon inherited (a hashed bucket shared with other sessions), a blanket `(subpath "/var/folders")` in each of the write and read blocks, and — reachable only through `plan.reads` — `system_baseline_reads()`'s own `/private/var/folders` entry, so removing the profile rules alone left the hole open. On a stock macOS host that is where `tempfile` and every application's caches live, and a confinement test demonstrated a jailed `Shell` reading a host file outside its worktree. All three are gone and `darwin_user_temp_base` with them; nothing needed a replacement grant, since a confined process keeps `HOME` and `TMPDIR` inside the plan's own scratch dir. Note the two rules spelled `/var/folders` were dead all along — Seatbelt matches fully symlink-resolved paths, so only the canonicalized `/private/var/folders` grants were ever live, which is why an absolute-path probe was refused while a relative climb got through. A regression test asserts no rendered profile names the tree at all. ⚠️ The sandboxed `claude-cli` and `cursor-cli` jails share this profile and are **unverified end-to-end** here (pre-existing `self_arc` panic in their suites); the rendered-profile delta for both recipes is exactly these rules and nothing else. (tddy-sandbox-darwin)
