# 2026-09-24 — The credential vaults replace the plaintext GitHub token file

**Type:** Architecture

`#keyring` 3/9, PR [#510](https://github.com/uppin/tddy-coder/pull/510). Cross-package entry: [`docs/dev/changesets/2026-09-24-keyring-store.md`](../../../../docs/dev/changesets/2026-09-24-keyring-store.md)

`github_token_store.rs` (`FileGitHubTokenStore`, `github-tokens.json`) is **deleted**. `build_auth_entries_admitting` probes `auth_storage` with a free `probe_writable` and builds one `SessionVaults` through the new `vault_lifetimes::credential_vaults_in(dir, &lifetimes)` (named `pending_logins` until the idle-vault follow-up) after `VaultLifetimes::of(github)?` has applied both settings' defaults, `0` = never and the `REFRESH_TOKEN_TTL` ceiling — a value past it stops the daemon, naming the setting, returned as `AuthBuildResult::credential_vaults`, holding a pending token for `github.pending_login_ttl_seconds` and an unused open vault for `github.open_vault_idle_ttl_seconds`; `vault_lifetimes::spawn_credential_sweep` drops both every `min(pending, idle, 60 s)`, skipping a kind at `0` (no task when both are). `retained_github_token`'s read is a use (`SessionVaults::use_open`). `github_pr_credentials::retained_github_token` reads a caller's token by vault state and names the remedy while it is closed. `SessionVaults` is re-exported. New suites: `login_opens_the_credential_store_acceptance`, `vault_unlock_across_restart_acceptance`, `credential_vault_guard_acceptance`, `pending_login_expiry_acceptance`, `open_vault_idle_expiry_acceptance`, `vault_lifetime_config_acceptance`, with a per-exchange-token fake GitHub in `tests/support/mod.rs`.

Code issues: `oversized-file-auth` opened at this wrap (`auth.rs` 576 → 622 production lines, split deferred with consent); `complexity-auth-build-auth-entries-admitting` regressed 106 → 110 lines, deferred with consent; the idle-vault follow-up leaves them at 622 and 110. Detail: [auth-service.md](../auth-service.md#credential-vaults).
