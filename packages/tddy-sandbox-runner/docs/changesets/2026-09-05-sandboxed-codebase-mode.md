# 2026-09-05 — in-jail tool dispatch, and a workspace jail that can build

**Type:** Feature

`InJailToolDispatcher` sends tool calls *into* a jail over a running host relay — the mirror of `HostToolHandler`, and the half a `--workspace-tools` jail needs. It lives on the relay rather than beside it because a jail that runs a build needs its CONNECT tunnels on the same `SessionChannel` as its tool calls. `in_jail_tool_response` carries no request id, so exactly one call is outstanding at a time, held by a turnstile across send-and-await and bounded by `IN_JAIL_TOOL_TIMEOUT` — now defined here, `pub`, and imported by `tddy-daemon` rather than declared twice. A channel that misses an answer is declared lost: later calls fail fast naming the restart, because a late answer would be misattributed to the next caller. `--workspace-tools` is served over `--stdio` or `--grpc-listen-port` (`resolve_workspace_tools_transport`; neither is refused naming both), and starts the CONNECT egress shim only when `--egress-shim-port` asks for one — whose proxy environment reaches the tool engine's subprocesses, which is what lets a jailed `cargo` or `bun` fetch at all. `serve_over_loopback_grpc` is extracted from the agent path so both modes share one server.
