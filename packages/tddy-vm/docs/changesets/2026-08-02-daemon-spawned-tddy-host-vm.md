# 2026-08-02 — **Daemon-spawned tddy host VM

**Type:** Feature

`BuildTddyHostImage` + `CreateVmFromPreparedBase`, and the launcher corrections they stand on** — the crate could not boot a guest on an Apple Silicon host at all: `QemuVmArgs::build` hard-coded `qemu-system-x86_64`, `-m 512M`, no `-smp`, no accelerator and no firmware, so `RunPolicy`'s persisted memory/cpus were ignored and the aarch64 `virt` machine (which has no BIOS) had nothing to boot through. `vm.rs` gains `VmArch`/`VmAccel` (with explicit `host()`/`host_default()` constructors — the launcher itself never guesses), `UefiFirmware`, `VmLogin`; `qemu.rs` gains `qemu_binary`, `machine_arg`/`cpu_arg` (`-cpu host` under HVF/KVM, `cortex-a72`/`max` under TCG), a two-`pflash` UEFI pair, `-cdrom`, virtio-9p `-fsdev`/`-device`, `resolve_uefi_code_path` (env `TDDY_VM_UEFI_CODE`, else derived from the emulator's own installation — **an unresolvable image is an error, never a silent BIOS fallback**), `ensure_uefi_vars_file` (64 MiB, idempotent), a shared `spawn_emulator`, and SSH as `LoginPolicy.username` with `-i <key>`/`IdentitiesOnly=yes` in place of unconditional `root@` + the ambient agent key. New `serial_shell.rs`: a UART driver ported from `~/Code/makers-lt`'s `@wix/shell-utils` but restructured so the parsing core is **pure** (`SerialShell::feed` returns events; 21 unit tests, no VM) — a shell prompt is believed only *after* a login/password prompt, because cloud-init frames its host-key banner in rows of `#` and mistaking one for a prompt makes the driver type commands at a getty; command completion comes from a per-command exit-code marker, not a prompt regex, so output containing prompt- or login-shaped lines is harmless. New `tddy_host.rs`: the cloud-init recipe (9p mount → rsync → Nix → `./release` → `bun run build` → `./install --systemd`) plus `build_tddy_host_image`, and `ninep_capable_kernel_command` — Debian's *cloud* kernel ships **no 9p modules at all**, and installing the generic flavour is not enough because GRUB keeps preferring cloud, so the step also purges it, `update-grub`s and reboots, guarded on `uname -r` to bound it to one reboot. `cloud_init.rs` gains `NinePShare`, `owner`/`defer` and `plain_text_passwd`/`lock_passwd` on its document types, `render_user_data_without_completion` (a long-lived guest must not inherit the bake's self-halt), `promote_prepared_base_pair`, and **drops `-no-reboot`** so a mid-bake guest reset restarts the guest instead of ending the emulator. `library.rs` generates the per-VM ed25519 keypair `create_vm` had always documented but never written. `registry.rs`: `run_manifest_for` propagates instead of silently substituting a root/no-key/host-arch manifest, `start` resolves firmware *before* the `Booting` transition, and a boot failure records `Error` instead of wedging the VM. Tests: **167** in `tddy-vm` (0 ignored in a default run) plus **6/6 real-boot acceptance tests** against `debian-12-genericcloud-arm64` (~327 s).
