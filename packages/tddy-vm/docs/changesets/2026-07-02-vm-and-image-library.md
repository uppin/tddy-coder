# 2026-07-02 — VM & Image Library

**Type:** Feature

new `library.rs`: `VmLibrary` organizes `images/01-base/` (immutable, downloaded bases), `images/02-prepared-base/` (cloud-init-baked prepared bases, both chmod `0o444` via `set_readonly_file`), and `vm/<name>/` (per-VM `manifest.yaml` + mutable overlay + SSH keys) under the existing tddy data dir — no new env var; `init`/`import_base_image`/`write_manifest`/`read_manifest`/`list_manifests`/`remove_vm`/`create_vm` (async, real `qemu-img create` via an **absolute**-backing-path `vm_overlay_create_argv`, contrast `cloud_init::overlay_create_argv`'s co-located relative basename). New `vm_manifest.rs`: `VmManifest`/`RunPolicy`/`LoginPolicy` (YAML). `cloud_init.rs` gains `cloud_init_library_paths`, a pure path-mapping helper routing a cloud-init build's downloaded input base and its flattened-base+overlay pair into the library. `registry.rs`: `VmManager` gains a `Storage` enum and `from_library` constructor — per-VM manifests become the source of truth for library-backed managers (the pre-existing JSON-backed `VmManager::new` path is untouched, byte-for-byte). Design mirrors `~/Code/makers-lt`'s `maker-vm` qcow2-backing-file chaining; no image ever downloaded by this feature — tests reuse an already-built base supplied via `TDDY_CLOUDINIT_BASE_IMAGE`. 65 unit/acceptance tests pass (3 correctly-gated `#[ignore]`d, one run for real against makers-lt's `debian-12-base.qcow2`), `clippy -D warnings` clean.
