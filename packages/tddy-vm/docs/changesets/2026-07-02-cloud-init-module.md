# 2026-07-02 — **`cloud_init` module

**Type:** Feature

cloud-init image build with image-chaining** — new `packages/tddy-vm/src/cloud_init.rs`: pure argv/document builders (`base_convert_argv`, `overlay_create_argv`, `render_user_data`, `render_meta_data`, `completion_token`, `seed_iso_argv`, `iso_tool_command`, `cloud_init_boot_argv`, `classify_serial_line`) plus the async `build_cloud_init_image` orchestrator (copy base → convert to immutable qcow2 → resolve/generate SSH keypair → render+write NoCloud seed → build cidata ISO via `xorriso`/`mkisofs`/`genisoimage` → create the chained delta overlay → boot QEMU and watch the serial console for a `sha256`-derived completion token, with a durable `<name>-boot.log` transcript and a monitor-socket graceful-shutdown timeout fallback). Reuses `QemuVmArgs::monitor_socket_path`/`send_monitor_command` and mirrors `build.rs`'s progress-reporting and `tokio::select!` line-draining idioms. 22 unit tests pass; the real-boot tests are production tests — `#[ignore]`+`#[serial]` and additionally gated on `TDDY_CLOUDINIT_BASE_IMAGE` (no bundled/auto-discovered image; never run, even with `--ignored`, unless a developer explicitly supplies that env var) — verified to succeed end-to-end multiple times in a nested-virtualization sandbox when supplied (found+fixed a real `set_hostname`-misclassification bug and a `ds=nocloud` boot-speed fix along the way), though still timing-sensitive under that sandbox's fixed budgets.
