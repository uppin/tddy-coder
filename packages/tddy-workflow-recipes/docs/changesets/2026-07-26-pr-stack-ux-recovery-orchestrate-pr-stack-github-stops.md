# 2026-07-26 — pr-stack-ux-recovery: `orchestrate_pr_stack::github` stops reading the process environment for credentials and stops lying about failed lookups. New `RealGithubPrApi::with_token(owner_repo, token)` authenticates with an explicitly supplied token and **never** falls back to `github_token_from_env`

**Type:** Fix

an explicit-token instance quietly authenticating as the host's ambient token would be a silent credential swap. New `qualified_head` renders `head` as `owner:branch` and is applied in **both** `get_open_pr` and `get_pr_by_head`: GitHub *ignores* an unqualified `head` rather than rejecting it (verified live — 30 PRs returned for a bare branch name vs 1 for `owner:branch`), so `arr.first()` yielded an arbitrary PR, latent in the display path but live in `get_open_pr`, which the orchestrator uses to repoint and merge. New `PrLookupOutcome { Found(PrView) | NotFound | Unavailable(reason) }` replaces the `Ok(None)` that made "no GitHub credential" indistinguishable from "no PR exists", and `get_pr_by_head` **drops its `Result` entirely** — with no error channel, no caller can re-raise a failed lookup as `Status::internal` and discard the whole branch resolution; `get_open_pr` and the mutating methods keep `Result` to fail closed. Tests: `tests/github_qualified_head_acceptance.rs` 5 (`owner:branch` qualification, idempotent on an already-qualified head, no-owner passthrough).
