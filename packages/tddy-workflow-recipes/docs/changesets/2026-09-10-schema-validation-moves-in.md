# 2026-09-10 — Schema validation and the GitHub PR client move in

**Type:** Architecture

Node 5 of the `#unbundle` stack ([#474](https://github.com/uppin/tddy-coder/pull/474)). Full story in
the cross-package entry:
[2026-09-10-unbundle-tools-thinning.md](../../../../docs/dev/changesets/2026-09-10-unbundle-tools-thinning.md).

`schema`, `schema_manifest` and `github_pr` arrive from `tddy-tools` — roughly 940 production lines.
The registry the first two read is now generated by **this** package's `build.rs` into
`generated/goal_registry.rs`, so `tddy-tools`' own build script and its cross-package `include_dir!`
/ `include_str!` reach into this directory are both deleted. `review_persist.rs` — 15 lines
delegating to `review::persist_review_md_to_session_dir` — is deleted outright rather than moved.

Documented in [json-schema.md](../json-schema.md), which moved here with the code.

**Three production dependencies gained**: `include_dir` and `jsonschema` with `schema.rs`, `tempfile`
with `github_pr.rs`. Nothing new entered the workspace — all three were `tddy-tools` dependencies and
left it in the same change — but **ten crates depend on this one** against `tddy-tools`' four, so
in-jail binaries that reach the recipes crate now build `jsonschema`. Worth stating plainly, because
the same node then refused to move the `pr_*` MCP tools here *specifically* to avoid adding `rmcp`
and `schemars` on that reasoning's other side. Both calls stand on their merits — `jsonschema` is a
smaller build, and `schema.rs` cannot be split from the data it validates the way the PR-stack
adapters split from `pr_stack` — but the asymmetry is real.

The `pr_*` and `github_*` MCP tools' **advertisement** stayed in `tddy-tools`: all 16 bodies were
already thin adapters over `pr_stack` functions here, so the only thing available to move was the
`rmcp` surface.

⚠ **The moved modules still log under `tddy_tools::` targets** — `tddy_tools::schema` (6 sites),
`tddy_tools::schema_manifest` (3), `tddy_tools::github_pr` (13). Those are the strings an operator's
`RUST_LOG` filter needs today. Whether to rename them is
[an open question](../../../../docs/dev/todo/2026-09-10-schema-validation-still-logs-under-the-tddy-tools-target-after-moving-crates.md),
because the same stack recorded the opposite policy one node earlier.

Tests: 559 / 1. The one failure predates this node and is macOS-only (`/tmp` vs `/private/tmp` in
`pr_stack_artifact_paths_acceptance`). **Run this crate with `--no-fail-fast`** — `cargo test` stops
after the first failing *target*, so a plain run reports 363 of the 559 and hides four whole targets.
