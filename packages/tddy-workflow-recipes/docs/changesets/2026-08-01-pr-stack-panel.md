# 2026-08-01 — **PR-stack panel

**Type:** Feature

row order assignment, reorder, and pull-from-base** — `assign_missing_display_order` runs as the first statement of every `update_stack_atomic` closure (all seven mutators + `bridge.rs` seeding), numbering legacy nodes on the next write in topological order with a **declaration-order** tie-break so the daemon numbers rows in the order the web displayed them; `planned_prs_into_stack_nodes` numbers from the plan array, appends take `max+1`, deletes never renumber, and reseeding takes the new plan's order. `move_planned_pr_node(dir, node_id, "up"|"down")` swaps neighbours (past an end is a no-op success; unknown id refused without writing). `pull_base_into_node_branch` merges (default) or rebases the base into a node's own worktree then pushes, with the ordering as the safety design: refuse a node with no branch/worktree, verify the worktree actually has that branch checked out (the resolver also answers with one merely sharing the tip commit — which would land the base on a sibling and then report a push of a branch that never moved), check cleanliness **before** the fetch, base-ref-scoped fetch, apply, push. A conflict aborts and is refused with its paths; a failed **abort** is itself reported rather than read as clean; `commit_all_tracked` snapshots the index with `write-tree` and restores with `read-tree` so a refused commit leaves deliberately-staged work intact; a failed **push** is a success reporting `pushed = false` + reason, since the local work landed. New git primitives `fetch_ref`, `worktree_is_clean`, `commit_all_tracked`, `merge_ref_into_worktree`, `rebase_branch_onto_ref`, `SyncOutcome`; `force_push_with_lease` gained a `remote` parameter (it hardcoded `origin` while callers resolved the project's own remote). Tests: `pr_stack_display_order_acceptance` (14), `pr_stack_pull_base_acceptance` (15). (tddy-workflow-recipes)
