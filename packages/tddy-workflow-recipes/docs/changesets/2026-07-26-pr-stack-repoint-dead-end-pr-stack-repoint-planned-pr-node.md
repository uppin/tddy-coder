# 2026-07-26 — pr-stack-repoint-dead-end: `pr_stack::repoint_planned_pr_node` takes **`target_base_branch: Option<&str>`**. `Some(target)` retains exactly the parents owning that branch

**Type:** Fix

**collapsing the node to a single parent by intent**, since repointing is a decision to stack on one predecessor — while `None` keeps the original drop-merged-parents rule, written as "not known-merged" so an unresolvable parent id survives exactly as the drop-list form did. A node with `branch = None` is now a **plan-only** repoint (parents persisted; no rebase, no force-push, no `patch_pr_base`) instead of erroring `node '<id>' has no branch to repoint` — which had rejected precisely the never-started node this recovery exists for. The retain filter runs **inside** the `update_stack_atomic` closure: it re-reads the file before applying, and the orchestrator agent writes the same file, so a keep-list computed from the earlier snapshot dropped any parent added between the two reads (a drop-list would have kept it). Tests: `tests/pr_stack_repoint_dead_end_acceptance.rs` 7 (incl. no GitHub call at all on the plan-only path, and the multi-parent collapse), `pr_stack_repoint_acceptance.rs` 2 unchanged in behaviour.
