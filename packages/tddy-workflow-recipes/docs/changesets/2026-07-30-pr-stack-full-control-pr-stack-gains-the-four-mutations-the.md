# 2026-07-30 — pr-stack-full-control: `pr_stack` gains the four mutations the orchestrator was missing

**Type:** Feature

`update_planned_pr_node` (title/description any time, `branch_suggestion` only while the node owns no branch, an all-empty input rejected), `delete_planned_pr_node` (children inherit the removed node's parents, deduplicated and with the removed id filtered out so a self-parent cannot propagate a dangling reference that `Stack::topo_order` would silently ignore; refuses `phase == "open"` because closing a PR is externally visible and the agent must ask via `pr_close`; reports the orphaned branch/session instead of deleting them), `set_stack_node_parents` (the plan-level move and the only reorder primitive, since order is derived from `parents` — rejects unknown/self/repeated/cyclic **before** any write and re-reads the node's `branch` **after** the write so a concurrently-spawned node is still realigned), and `adopt_pr_as_stack_node` / `adopt_pr_into_stack` (refused when the head branch is bound *or* the pull number is already recorded, since `pr_status.url` is the system's identity for "which PR is this node"), plus `sync_node_to_github_pr` taking title/body explicitly so an unchanged body is never restated over a GitHub edit. The git+GitHub tail of `repoint_planned_pr_node` is extracted to `realign_node_to_effective_base(op, …)` and shared with `set_stack_node_parents` — repoint lost 66 lines with its 9 tests as the behaviour guard, and its three known silent-failure paths are now fixable in one place instead of two. Four shared validators (`validate_parents`, `reject_if_cyclic`) replace three copies of the dangling-parent loop and two token-identical cycle checks; `add_planned_pr_node`'s messages stay deliberately unprefixed (`PrStackAddPlannedPrAcceptance.cy.tsx` reads `"dangling parent ref"` verbatim). New **sibling** trait `GithubPrInsightApi` — 7 reads + `patch_pr_title_body` — rather than widening `GithubPrApi`, whose eight hand-written fakes care only about lifecycle; new `orchestrate_pr_stack::pr_insight` owns the shaping (`read_pr` folds reviews to one latest state per reviewer and does not even *fetch* files unless asked; `read_pr_comments` rebuilds reply-chain threads with a bounded walk so a malformed remote response cannot hang the tool, and emits no `resolved` field because that is GraphQL-only; `search_repository_prs` injects the repo scope and refuses `text`/`author`/`base` carrying `:` or whitespace, since GitHub ORs repeated `repo:` qualifiers). `pr_number_from_status_url` → `pub`; `github_rest_common` gains `curl_github_get_json_absolute_path` + `GITHUB_API_BASE`. `PR_STACK_TOOL_NAMES` 8 → 15, prompt extended, agreement pinned by a test that parses the prompt. Tests: 417 (+76) — incl. `pr_stack_realign_failure_acceptance` (real `git init`, conflicting rebase, asserts `phase = "error"` and that the PR was **not** re-targeted) and 14 `search_qualifiers` cases pinning every injection shape.
