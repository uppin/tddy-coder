# 2026-07-02 — `cloud-init` subcommand + `build`/`cloud-init` `Cli` restructure (breaking CLI shape change)

**Type:** Feature

`tddy-vm-build` gains a `Cli { #[command(subcommand)] Build(BuildImageArgs) | CloudInit(CloudInitBuildArgs) }` wrapper; the previous flat `tddy-vm-build --spec … --output … --format …` invocation becomes `tddy-vm-build build --spec … --output … --format …`. New `CloudInitBuildArgs`/`run_cloud_init_build` parse a `--user-data` YAML file into `tddy_vm::cloud_init::CloudInitUserData` and call `tddy_vm::cloud_init::build_cloud_init_image`, printing progress to stderr like `run_build_image`. `--base-image` takes `env = "TDDY_CLOUDINIT_BASE_IMAGE"` (no hardcoded default) so no user-machine-specific path is baked into the shared CLI. The CLI-level test is a production test — `#[ignore]`+`#[serial(cloud_init_qemu_vm)]` and additionally gated on `TDDY_CLOUDINIT_BASE_IMAGE` (never runs, even with `--ignored`, unless a developer explicitly supplies that env var) — verified to succeed against a real QEMU boot when supplied.
