# 2026-09-05 — sandboxed codebase mode

**Type:** Feature

A third `--codebase-mode`, **`sandboxed`**, inverts the placement the other two share: the agent runs on this host as an ordinary child with inherited stdio — so it holds the real controlling terminal, and Ctrl-C, resize and `$TERM` are the terminal's own business — while the checkout and its build live in a `--workspace-tools` jail. `sandboxed_session::provision` lays out the session tree, spawns the jail, attaches `run_host_relay_with_in_jail_tools`, and binds a host Unix socket serving `connection.ConnectionService/ExecuteTool` that forwards each call inward; `host_agent` builds the agent's argv, whose MCP config names that socket in `TDDY_SANDBOX_TOOL_IPC` and whose `--strict-mcp-config` + `--setting-sources user` keep the untrusted checkout's `.mcp.json` and `.claude/settings.json` hooks off this host. The MCP config is written to `<session_dir>/host/`, a sibling of every jail grant, because the jail can write its own scratch tree and that file's `command`/`env` are executed unconfined. Each repository gets a persistent jail `$HOME` under `~/.tddy/sandbox-codebase-home/`, keyed by repository so one build cannot leave a `~/.cargo/config.toml` for the next. Ctrl-C is handled inside `provision`, where the jail's handle is owned — `SandboxHandle` has no killing `Drop`, so racing the interrupt from the caller orphaned a confined process holding the checkout. The crate gained a `[lib]` target so the Seatbelt acceptance suite can drive the real provisioner. Refused by name rather than silently dropped: `--agent-kind cursor`, specialized agents, `--cwd`, `--codebase-home-dir` in any other mode, and Linux.
