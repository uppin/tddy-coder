# 2026-07-23 — Wire chunking codec into the RPC transport

**Type:** Feature

the `chunking.rs` codec shipped unwired in PR #322, so oversized LiveKit data-channel frames (>64,000-byte SCTP max) still wedged `publish_data` (`SharedPublisher` retried 30× forever), starving small RPCs. Now wired end-to-end: send frames via `frame_for_transport`/`next_message_id` (`client.rs::publish_request`, both `participant.rs` response drains), receive reassembles per sender via `ChunkReassembler` (`client.rs`, `client_factory.rs`, `participant.rs`). Small payloads stay raw (byte-for-byte); only oversized ones split, each chunk frame prefixed with a `0x00` magic byte a valid prost `RpcRequest`/`RpcResponse` can never begin with, so peers disambiguate raw vs chunk on the first byte (`is_chunk_frame`). TS mirror in `tddy-livekit-web/src/chunking.ts`. Verified by a real-LiveKit `rpc_scenarios` 370 KB oversized-echo round-trip.
