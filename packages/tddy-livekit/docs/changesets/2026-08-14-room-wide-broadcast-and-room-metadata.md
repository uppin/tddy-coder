# 2026-08-14 — room-wide broadcast and room metadata

**Type:** Feature

`BroadcastChannel` / `BroadcastPublisher` publish one reliable `DataPacket` with an **empty** `destination_identities` on a caller-chosen topic, the first non-`tddy-rpc` topic in the system; subscribers take their own `room.subscribe()` so they never race the RPC loops, and drop every other topic. Oversized payloads are **refused, not chunk-framed** (`MAX_BROADCAST_PAYLOAD_BYTES` = 8 KiB): chunking is only safe when a lost frame surfaces as a failed call, and a fire-and-forget broadcast has no reply to time out. `JoinedParticipant::broadcast_on` returns a publisher bound to the connection's `SharedPublisher` rather than a `LocalParticipant` snapshot, because `serve` consumes the `Room` and a second connection would put a second identity in a room whose claim is that only one daemon is in it. `RoomMetadataClient` writes room metadata over the Twirp server API — `RoomClient` signs its own room-admin token, so `token.rs` needs no new grant — and `create_with_metadata` is create-then-set because `create_room` against an existing room silently ignores its options.
