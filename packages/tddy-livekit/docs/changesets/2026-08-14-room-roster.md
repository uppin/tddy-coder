# 2026-08-14 — **room roster

**Type:** Feature

reading LiveKit's server API** — `LiveKitRoomRoster` lists rooms and their participants via `livekit_api::services::room::RoomClient` — the read half of the same server API `RoomMetadataClient` writes a session room's snapshot through. Timestamps read `creation_time`/`joined_at` in seconds rather than the newer `*_ms` fields: only recent servers populate those and proto3 cannot tell `0` from unset, so using them would need an "`ms` if non-zero else seconds" fallback — one source that reads correctly against any server version costs only precision nothing renders. `joined_at == 0` stays 0 as the "no join time recorded" sentinel rather than becoming 1970, and state is named by `state().as_str_name()` so there is no mapping table to drift. The whole read (`ListRooms` plus every per-room `ListParticipants`) is bounded at 5 s, because a server that accepts and never answers would otherwise leave a UI on a stale roster looking healthy. `http_base_from_ws_url` derives the HTTP base from `livekit.url` — the test-only converter it replaces required an explicit port, so a portless `wss://host` would not have survived it. `livekit-protocol` promoted transitive → direct so the participant mapping is an extracted, tested function; no new package, no version change.
