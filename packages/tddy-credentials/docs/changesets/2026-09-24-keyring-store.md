# 2026-09-24 — A session-gated encrypted credential store (new crate)

**Type:** Feature

`#keyring` 3/9, PR [#510](https://github.com/uppin/tddy-coder/pull/510). Cross-package entry: [`docs/dev/changesets/2026-09-24-keyring-store.md`](../../../../docs/dev/changesets/2026-09-24-keyring-store.md)

New crate. `(provider, account)`-keyed `CredentialRecord`s whose label, metadata and secret are one ChaCha20-Poly1305 unit (the record's identity as associated data), in one file per user, `credentials-<hex subject>.vault` (`CredentialStore::path_in`), format version 2 with a versioned KDF header. A random data key is wrapped under a KEK that Argon2id (m=19456 KiB, t=2, p=1, 16-byte salt) + HKDF-Expand derive from the user's **vault passphrase**, and under up to `MAX_UNLOCK_SLOTS` (16, LRU-evicted) browser unlock slots (HKDF-SHA256 over an `UnlockKey`). `CredentialStore::{create, open_with_passphrase, open_with_unlock_key, reset}` (reset renames the old file aside, never deletes, at most `MAX_SET_ASIDE_VAULTS` = 5); `SessionVault::{put, get, list, remove, add_unlock_slot, rotate_unlock_slot, remove_unlock_slot, unlock_slot_ids}`; `SessionVaults` — the registry of open vaults with `VaultState { Open, Locked, Uninitialized }`, pending sign-ins (`sessions/pending.rs`, `PendingSignIns`) that expire after an injectable lifetime (`with_pending_lifetime`, `expire_pending`), `ROTATION_GRACE` (30 s) and one `transitions` lock. `SecretString` (redacted, wiped, no serde), `SecretBytes`, `MIN_PASSPHRASE_CHARS` = 8, `MAX_PASSPHRASE_CHARS` = 1024. An owner-only swap-then-rename writer (`atomic.rs`) is inlined so the crate does not depend on `tddy-core`. Depends on neither `tddy-daemon-auth` nor `tddy-livekit`. No new external dependency (`argon2 0.5` was already in the workspace; neither `hkdf` nor `zeroize` taken).

Known limitations (a lapsed lineage keeps the vault open; cipher key schedules are not wiped; the set-aside TOCTOU across processes; `reopen` holding the rotations lock across I/O; two tabs unlocking by passphrase orphaning a slot) and the two retention rules the deleted `GitHubTokenStore` carried are in [credential-store.md](../credential-store.md).
