# 2026-11-26 — The credential vault persists through the filesystem port

**Type:** Architecture · PR [#1045](https://github.com/uppin/tddy-coder/pull/1045)
Cross-package entry: [`docs/dev/changesets/2026-11-26-fs-port-crate.md`](../../../../docs/dev/changesets/2026-11-26-fs-port-crate.md)

The vault's private atomic-write copy (`atomic.rs`, deleted) is replaced by the port's
`write_atomic` at fixed mode `0600`; every vault read, write, rename and directory listing goes
through an injected `Arc<dyn tddy_fs::Fs>`. `SessionVault` keeps writing through the port it was
opened with; `CredentialStore::create` / `open_with_passphrase` delegate to `create_on` /
`open_with_passphrase_on` with `DiskFs`. `tests/fs_port.rs` pins vault creation, reopening,
owner-only mode and failure atomicity on `MemFs`, and runs the port guard over `src/`. Resolves
`docs/dev/todo/2026-09-23-atomic-file-leaf-crate.md`
("Two copies of \"replace a secret without truncating it\"") together with the `tddy-fs` entry.
