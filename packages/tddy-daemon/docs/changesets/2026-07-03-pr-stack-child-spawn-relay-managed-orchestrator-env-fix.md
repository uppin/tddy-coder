# 2026-07-03 — PR-stack child-spawn relay + managed-orchestrator env fix

**Type:** Feature

`pr_spawn_child` is served by a per-session `StackChildSpawnHandler` (bound in `start_claude_cli_session` only when `managed_recipe.name() == "pr-stack"`, so an orchestrator can spawn only its own stack's children) that reads the orchestrator changeset for the planned node and calls the shared `spawn_claude_cli_session_inner` — extracted verbatim from `start_claude_cli_session` (the RPC path is now a thin wrapper, behavior unchanged) — with `stack_parent` set, `managed_recipe = None`, `new_branch_from_base`, inheriting the orchestrator's `SessionMetadata.model`. `session_toolcall.rs` threads the handler to the toolcall listener (`with_child_spawn_handler`). Also fixes a latent runtime bug: `prepare_managed_workflow` now exports `TDDY_SESSION_DIR` + `TDDY_REPO_DIR` (previously only `TDDY_SOCKET` + `PATH`), without which the PR-management tools had no session/repo in scope.
