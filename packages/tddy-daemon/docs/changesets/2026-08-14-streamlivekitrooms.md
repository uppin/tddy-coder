# 2026-08-14 — **StreamLiveKitRooms

**Type:** Feature

the LiveKit server's rooms and their participants** — a server-streaming `ConnectionService` RPC whose first message is a full room snapshot and whose every later message is one delta; `pump_rooms` polls the server API every 3 s and `diff_rosters` compares against the roster last sent **on that stream**, since a shared baseline would let one watcher's tick consume a delta another had not been sent. A tick with no delta emits nothing, so an idle server yields an idle stream — which is exactly why the loop must select on `tx.closed()` rather than infer departure from a failed send that is never attempted; without it every subscription leaked a permanent 3 s poll of an external server. Ticks are `MissedTickBehavior::Skip` so a slow read cannot queue up the ticks it outlasted and fire another `1 + rooms` calls when the API is already struggling. A read failure or missing credentials terminates the stream with the reason (`FAILED_PRECONDITION` vs `INTERNAL`) — never an empty room list, which would read as "the server has no rooms". `RoomRoster` is injected via `with_room_roster` and built from `DaemonConfig.livekit` inside `ConnectionServiceImpl::new`, not at the `main.rs` call site, so a second construction site cannot forget it.
