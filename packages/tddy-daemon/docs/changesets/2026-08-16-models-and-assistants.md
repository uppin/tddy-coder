# 2026-08-16 — models-and-assistants

**Type:** Feature

`model_registry/` adds a per-daemon SQLite registry of model providers, their models and assistants, served as `models.ModelRegistryService`: `sqlx` runtime API on the `session_catalog` pattern, `0600` created *before* sqlx opens it so `-wal`/`-shm` inherit, `BEGIN IMMEDIATE` around every check-then-act, and provider ids retired rather than reused so a refresh racing a delete cannot hand the next provider an orphaned catalog. Reads are unscoped, writes and `credential_for` are owner-only — refused whether or not a key is stored, since a presence-dependent rule breaks the day the owner adds one. `ProviderClientFactory` matches every kind by name and returns a `Result`: the former catch-all handed the stored credential to any endpoint it could not classify. Provider errors are truncated to 400 bytes (an unbounded body in `enumeration_error` is chunk-framed over LiveKit, where a lost frame wedges the call silently) and `base_url` is validated, closing a daemon-side SSRF that echoed the response back. `ModelAcpService` serves a model-addressed ACP surface, confining an assistant's `cwd` by canonicalising it against the caller's own sessions base and `projects.yaml` repo paths — path confinement only; the engine still runs as the daemon uid. The registry becomes a third `SpecializedAgentDef` source, and the resolved def reaches the child as `--agent-def-path` (a `0600` file, chowned) because `/proc/<pid>/cmdline` is world-readable.
