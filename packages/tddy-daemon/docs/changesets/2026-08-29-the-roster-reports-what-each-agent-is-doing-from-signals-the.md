# 2026-08-29 — the roster reports what each agent is doing, from signals the daemon already had

**Type:** Feature

new `session_agent_status` holds the mapping (`agent_status`) and the memory-only `SessionAgentActivityStore` keyed by `(session_id, agent_id)`; `session_agent_roster` reads it beside the clone store through `SnapshotSources` so an entry cannot carry a fresh `clone_state` with a stale `status`. The clone wins outright — a provisioning checkout refuses prompts, so IDLE would offer an agent that cannot answer — and nothing is persisted, so a restarted daemon reports UNSPECIFIED rather than claiming a turn in flight in a process that never started one. `connection_service` records at open / prompt / managed tool dispatch / turn end / cancel / detach and republishes on each (a status does not move `rev`, so `rev`-only subscribers would never see it), through `republish` alone rather than the room broadcast because a status ticks on every tool call. A turn's end is guarded so a cancel or detach that already landed is not overwritten; `relay_watching_for_the_turn_to_end` passes a forwarded turn's frames through verbatim so a remote agent's badge comes back down. Serves `ReportAgentConversationState` on all three surfaces, refusing an unattached `agent_id` and clamping what a reporter may claim. (tddy-service, tddy-daemon, tddy-tools, tddy-web, tddy-sandbox-runner)
