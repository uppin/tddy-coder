# 2026-08-29 — the session room publishes enough to rebuild the checkout

**Type:** Feature

the poll loop gains three things beyond measuring. It stages a WIP tree per tick through a scratch index inside the git dir (seeded from the agent's index so git's stat cache means only what moved is hashed, and placed there because under the worktree it would stage itself and in the temp dir it would usually cross a filesystem), publishes it as `refs/tddy/session/{id}/wip` — a commit parented on the measured `HEAD`, fixed `tddy-daemon@tddy.invalid` authorship, under `refs/tddy/` so it is never a branch an agent sees — and keeps a ring of `git diff --binary` patches bounded on both ticks (64) and bytes (16 MiB), since neither bound alone holds a busy session. `tick_delta` returns `None`, never an empty delta, when a tick cannot be described: an empty patch lets a client record the tick and move past it, so one standing in for a failure is a change the mirror never learns about. Activity records are stamped with the commit and the paths a call declared and broadcast on `session.activity`; the coder pushes nothing, the loop tails the `agent-activity.jsonl` the daemon already owns. `StreamAgentActivityDelta` and `StreamReadWorktreeFile` serve the ring and byte-exact file reads. The ref is dropped in `close` (not `Drop`) under an interlock, so a tick already measuring either published before it or finds the ref released — what is left behind otherwise is a worktree of blobs pinned in a repository shared by every checkout of the project.
