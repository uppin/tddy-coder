# 2026-07-28 — **session-attachment-start-materialization

**Type:** Feature

`StartSession` materializes both attachment sources into `{session_dir}/artifacts/attachments/` before the agent spawns; the staging RPCs and `ReadHostDocument` are live and forward across hosts** — new `session_attachment_staging` (per-OS-user root `{tddy_data_dir}/staging/{os_user}/{staging_id}/{file_name}`, ordered chunked writer mirroring `session_file_upload`, list newest-first, delete — `validate_segment` + `contained_canonical_dir` guards) and `host_documents::read_host_document_bytes` (resolves `HostDocumentScope` roots under the owning daemon's own `os_user`; POSIX `relative_path` no `.`/`..`/absolute, canonicalize-and-contained; binary read capped at `MAX_HOST_DOCUMENT_BYTES` = 4 MiB, refused over-cap not truncated). The three staging handlers + `read_host_document` replace the `TODO(start-session-attachments)` stubs and route by `daemon_instance_id` (empty/local = local, else forwarded over the LiveKit common room); four `forward_*_via_livekit` wrappers in `livekit_peer_discovery`. `materialize_session_attachments` runs in every `StartSession` session-type path after `session_dir` exists and before spawn: a `StagedAttachmentRef` naming a foreign `daemon_instance_id` is `INVALID_ARGUMENT` (no cross-host fetch, no silent empty attachment), `HostDocumentRef` is the only source that forwards (via `ReadHostDocument`), duplicate `basename`s within one request are rejected before any write, and a partial-materialization failure cleans up the request's `artifacts/attachments/` writes. The tool (tddy-coder) branch pre-creates `session_dir` so attachments land before the child spawns (the child's `create_session_dir_with_id` is idempotent on the existing dir). Tests: `tests/staging_rpc_acceptance.rs` 7 + `tests/staging_forwarding_acceptance.rs` 2 (two-daemon LiveKit testkit) + unit tests in `session_attachment_staging` (7) / `host_documents` (9) = 25; review hardening — `ReadHostDocument` canonicalizes the full file path (symlink-escape refusal) and checks file size before reading, forwarded bytes are re-capped on the session host, and staged materialization requires the `.staged-complete` marker; `cargo fmt --check` + `clippy --tests -D warnings` clean.
