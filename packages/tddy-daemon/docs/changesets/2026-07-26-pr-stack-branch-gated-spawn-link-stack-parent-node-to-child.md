# 2026-07-26 — pr-stack-branch-gated-spawn: `link_stack_parent_node_to_child` → **`link_stack_node_to_spawned_branch`**

**Type:** Fix

its subject is the branch a spawn created, with the session recorded only as a fallback, and a new session claiming a branch a node already owns now **repoints** it (last writer wins) instead of failing `FAILED_PRECONDITION`, since restart and re-attach are normal. `pr_stack_node_for_spawn` matches by exact `branch`, else by `branch_suggestion` on a not-yet-materialized node, and reads the stack through `read_stack_with_resolved_branches` so the child-session fallback reaches the spawn gate itself (the hydrated copy is read-only; the forward link writes through the orchestrator's own session dir).
