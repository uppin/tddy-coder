# 2026-08-13 — timing constants become operator config; resume finally warms up its subagents

**Type:** Fix

three hardcoded values that only tests wanted to change became `DaemonConfig` knobs whose defaults *are* today's production values, so no test-only branch was added to production code: `spawn_startup_grace_period_ms` (500) and `spawn_startup_poll_interval_ms` (25) replace the `spawner` constants, and the `agent_warmup` section (`timeout_secs` 120, `retry_interval_ms` 1000, `request_timeout_secs` 120) replaces `WarmupOptions::default()` at both sandboxed start paths — each overridable by a `TDDY_*` env var applied in the existing post-load pass (`defaults ← daemon.yaml ← TDDY_*`), a unit test pinning `agent_warmup_options() == WarmupOptions::default()` so the config path changed no behaviour. The two startup values reach `spawn_as_user` as `spawner::StartupWatch { grace, poll }`, and because that also runs inside the spawn worker — forked *before* env overrides and holding no `DaemonConfig` — they travel per request as `SpawnRequest.startup_grace_period_ms`/`startup_poll_interval_ms` (`#[serde(default)]`, the `child_log_level` precedent). Separately: **`relaunch_sandboxed_runner` never called `warm_up_agents` at all**, so a resumed session handed the agent subagents whose first call could stall on a cold model while both start paths gated on exactly that; the gate is now applied there too, same `failed_precondition`, no fallback, and `connection-service.md`'s "resume reuses this start path, so it is gated too" is corrected — it never did. Test side: the two specialized-agent binaries went from **121 s each, failing without an SGLang server on `localhost:30000`** to **12.1 s and 6.8 s, passing hermetically** (each writes a `fastcontext` def into `<tddyhome>/agents` pointing at an in-repo stub endpoint — a user def fully replaces the same-named builtin — and picks a 10 s budget through the new config); argv files are read through `eventually_blocking` instead of not being waited for at all; one `PTY_STUB_OUTPUT: Duration = 10s` in a new `tests/common/mod.rs` replaces six near-identical copies and a 2000/10000 ms split; and `a_port_no_one_is_listening_on()` probes outside the kernel's ephemeral range so a concurrent test cannot be handed the port out from under the fixture. Tests: 1007 across 107 binaries. See [connection-service.md](../connection-service.md), [testing.md § Determinism under load](../../../../docs/dev/guides/testing.md).
