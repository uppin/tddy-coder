# 2026-08-29 — a tick attributes only the calls its measurement could have seen

**Type:** Bug Fix

`session_room_livekit_acceptance::a_call_recorded_during_a_tick_is_served_the_patch_that_tick_produced` failed in CI at the `git apply` assert in its `applying()` helper, which fires because **`git apply` answers an *empty* patch with `No valid patches in input`** (exit 128, reproduced directly) — the delta served for the call was empty. `SessionRoomPoll::run` measured the checkout first and read `agent-activity.jsonl` last, so any row appended during the measure-and-announce span — two git shell-outs plus a LiveKit metadata write, a large fraction of a poll interval — was stamped with the seq of a delta cut **before** the write it describes existed: a tool writes its file and *then* records the completed call, so that row's `DELTA_SCOPE_CALL` slice selects no section of the tick's patch and answers empty forever, the bytes surfacing in the residual instead (nothing lost on the wire, but AC6 unmet and a client trusting a call's own delta never sees the edit). The loop now **cuts the log before the measurement** — new `read_activity_log`, whose two failure paths are unchanged, hands the cut to `broadcast_new_activity` — and attributes only that cut; rows appended later wait for the next tick, whose measurement is later than the write they describe. A tick boundary falling *between* a write and its record still mis-attributes that one call (microseconds against a 2 s poll, where this was a large fraction of every interval); closing it needs attribution to search the ring for the tick whose patch names the declared paths, which changes what `activity_seq` means on the wire — see [TODO](../../../../docs/dev/TODO.md). `applying()` now names an empty patch itself rather than leaving git's message to be decoded.
