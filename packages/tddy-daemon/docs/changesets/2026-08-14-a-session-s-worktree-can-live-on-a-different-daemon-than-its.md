# 2026-08-14 — a session's worktree can live on a different daemon than its agent

**Type:** Feature

`StartSessionRequest.codebase_daemon_instance_id` is a second host axis beside `daemon_instance_id`; `classify_codebase_placement` (pure, mirroring `classify_peer_route`) returns `CoLocated`/`Split` and refuses `recipe`/`semantic_index`/`sandbox` by name, each needing a worktree on the daemon running the agent. Atomicity needed two halves, not one: the B-side session id is caller-chosen (`requested_session_id`, workspace-only, `already_exists` if taken) so a timed-out forward can still name what to tear down, **and** the split forward waits `spawn_worker_request_timeout + PEER_FORWARD_TIMEOUT`, because the peer's 300 s worktree budget outlasts the 30 s forward — with only the id, this daemon tore down while the peer went on building. Teardown is paired and idempotent: "the peer has no such session" is success, unreachable refuses, and the common room is checked to be *connected* first because a local no-room fault returns the same code the peer uses for a missing session. New `StreamExecuteTool` carries results in `HOST_DOCUMENT_FRAME_BYTES` frames (one shared headroom, one compile-time assert); a stream ending without `last` errors and discards the prefix. Also fixes worktree removal on delete, which covered only `claude-cli` so every `workspace` session leaked its checkout and its `git worktree` registration; `split-agent-` becomes a reserved discovery prefix so an agent cannot advertise itself as a host; five copies of the branch-intent match collapse into `branch_intent`.
