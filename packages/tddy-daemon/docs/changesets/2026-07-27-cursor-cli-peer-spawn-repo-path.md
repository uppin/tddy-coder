# 2026-07-27 — **cursor-cli-peer-spawn-repo-path

**Type:** Fix

non-sandboxed cursor-cli "Add agent" peer spawn reuses the orchestrator's worktree and records the orchestrator link** — `spawn_cursor_cli_session_inner` (in `cursor_cli_spawn.rs`) now accepts `repo_path`/`stack_parent` and resolves the worktree via `session_worktree_source`, mirroring the contract the sandboxed claude-cli path already honors: a non-empty `repo_path` is canonicalized + `is_dir`-validated and used directly as the session worktree (no git worktree, no `cursor-cli/*` branch, not removed on session end), and `stack_parent` is recorded as `Changeset.orchestrator_session_id` (empty wire string → `None`). The call site in `connection_service.rs` forwards both fields; the sandboxed cursor-cli path is left unchanged with a `TODO` (tracked separately). Before this, a peer cursor-cli child became a standalone session on a fresh branch off `origin/master` with no orchestrator link — the daemon-side counterpart to the web "Add agent" feature (PR #357, which fixed a latent `cursor-cli` `stackParent` hardcode on the web side). `.cursor/hooks.json` is now gitignored (mirrors `**/.cursor/mcp.json`); it embeds a per-session `hook_token` secret written by `install_cursor_hooks_in_worktree`. Tests: 5 new fluent-style acceptance tests in `tests/cursor_cli_session_acceptance.rs` (worktree reuse, orchestrator link with/without `repo_path`, no new branch, invalid `repo_path` errors) + 2 helpers; `clippy -p tddy-daemon --tests -- -D warnings` clean; `./test -- cursor_cli` 9/10 (the 1 failure is pre-existing, environment-blocked: `cursor_cli_sandbox_start_succeeds_when_sandbox_backend_available` hits a host cgroups/userns EPERM, unmodified by this diff). Deferred: `os_user` impersonation for non-sandbox cursor-cli (`start_cursor` hardcodes `os_user: None`), and the sandboxed cursor-cli `repo_path`/`stack_parent` path.
