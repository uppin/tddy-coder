# 2026-08-02 — VM service gains the tddy-host bake; `StartDemoVm` pinned back to its original launcher settings

**Type:** Feature

`vm.VmService`'s two new methods are served by the already-registered `VmServiceImpl`, so no `main.rs` change was required. `connection_service.rs`: the `StartDemoVm` `VmConfig` now pins `VmArch::X86_64` + `VmAccel::Tcg` explicitly. Widening `VmConfig` had briefly switched that path to *host* arch and accel, which is a regression rather than a feature — nothing on the demo path knows the image's architecture (`demo-plan.md` names a `tddy-build-qemu` target, which produces x86_64), so on an Apple Silicon host it ran an aarch64 emulator with `-machine virt` and no firmware against an x86_64 image, and on Linux it newly depended on the daemon user's access to `/dev/kvm`. New `tests/tddy_host_vm_rpc.rs` (9 tests) drives both methods through `RpcBridge`: the auth boundary, path-traversal rejection on RPC-supplied library names, the streaming terminal stage, and the create success path.
