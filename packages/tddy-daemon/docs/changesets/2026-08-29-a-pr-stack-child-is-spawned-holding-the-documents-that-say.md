# 2026-08-29 — a pr-stack child is spawned holding the documents that say where its PR stops

**Type:** Feature

`stack_doc_attachments` builds a node's four `SessionAttachment`s (its `PRD.md` and `changeset.md`, then the shared `pr-stack-plan.md` and `exploration.md`) as `SESSION_ARTIFACT` `HostDocumentRef`s naming the **orchestrator's** session and host, so a cross-host stack works without copying and a nested source resolves to a flat destination; a document that does not exist is skipped, never fatal, since starting a node before the docs pass is sometimes correct. Both spawn paths use it — `StackChildSpawnHandler::spawn_child` and `start_session_core` — and one rule, `prompt_with_attached_changeset`, appends the line telling the child to read its changeset at every seam that launches an agent, derived from what **materialized** rather than what was offered and matching on the attachment's *source* (`prs/<node_id>/changeset.md`), so an operator's own `changeset.md` gets no line. `context_docs_for_session` gains per-PR rows scanned from `artifacts/prs/*/` and a `relative_path` on every row, since a client could never derive `prs/n1/PRD.md` from `kind` + basename.
