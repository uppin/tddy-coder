# 2026-07-27 — **unified-worktree-base-resolution

**Type:** Architecture

chain base resolution moves to tddy-core; cursor-cli PR-stack children base off the planned node, not origin/master** — the cursor-cli spawn paths no longer fall back to `origin/master` for a PR-stack child. `cursor_cli_spawn.rs::spawn_cursor_cli_session_inner` and `connection_service.rs::start_sandboxed_cursor_cli_session` now accept `stack_parent`, set `Changeset.orchestrator_session_id`, and resolve the chain base via `tddy_core::resolve_chain_base_ref` instead of hardcoding `None`; the dispatch site forwards `req.stack_parent`. The moved `resolve_chain_base_ref` / `parent_is_pr_stack_orchestrator` / `pr_stack_node_for_spawn` methods and their inline `chain_base_resolution_tests` are removed (now in tddy-core); a thin `resolve_chain_base_ref_status` wrapper maps `String` → `Status::failed_precondition`. Telegram spawn paths route through `tddy_core::resolve_chain_base_for_session_spawn`, reading the persisted `worktree_integration_base_ref` the branch callback wrote (the prior `None` pass ignored it and always used the default base). Tests: `tests/unified_worktree_base_acceptance.rs` 3 (cursor-cli + claude-cli PR-stack child + no-stack default).
