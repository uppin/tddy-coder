# 2026-07-06 — `ListAgentModels` handler + tool-session `--model` threading

**Type:** Feature

`connection_service.rs` adds a `list_agent_models` handler that shells out to `tddy-tools list-models --agent <agent>` (via the configured tool path / spawn worker), parses the JSON with `parse_agent_models_json`, and returns `ListAgentModelsResponse`; results cached per (agent, daemon, **OS user**) with a short TTL (cursor/ACP catalogs are account-specific — keying by OS user prevents cross-user leakage on a multi-tenant daemon), the probe run via `run_capture_as_user` with `current_dir` = the user's **home** (daemon cwd may be unreadable after setuid; the ACP probe opens a session against the cwd). The `StartSession` tool branch threads `req.model` → `SpawnOptions.model` (`spawner.rs` appends `--model <m>` when non-empty) → `spawn_worker.rs` `SpawnOptions`/`SpawnRequest.model` + `build_spawn_request` passthrough. Tests: `build_spawn_request` carries `model` 1, `parse_agent_models_json` reads models/default + errors on malformed probe 2 (a failed probe is never an empty catalog).
