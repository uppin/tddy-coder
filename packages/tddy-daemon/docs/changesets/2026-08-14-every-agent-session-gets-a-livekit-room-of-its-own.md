# 2026-08-14 — every agent session gets a LiveKit room of its own

**Type:** Feature

new `session_room` module: `session-{session_id}`, hosted by the session's *facilitating* daemon (the one running the agent), opened and joined **before** the agent is spawned so first-participant is ordering rather than a race. The room belongs to the session, not the checkout — a session has one agent-running daemon but its repo may live elsewhere, so keying on the worktree leaves it homeless under split placement; a `workspace` session runs no agent and gets no room. The daemon serves its full RPC surface there, answering from disk when the repo is local and forwarding to the codebase daemon when it is not, so participants never learn which case they are in. Activity is measured every `session_room.poll_interval_ms` and broadcast once on `worktree.activity` — a changed HEAD is a `commit`, a changed tracked diff a `files_changed`, an untracked-only change neither (its only possible event would be `files=0 +0 -0`, and every write is untracked for the moment before `git add`). New `GetWorktreeSnapshot` RPC measures a checkout this daemon does not hold in one round trip, routed by the same `classify_exec_tool_route` a tool call uses; an unreachable peer yields *unavailable*, never an empty snapshot, because an empty `head_commit` would broadcast a commit to the empty sha on every hiccup. Room metadata carries the summary (paths capped at 200 with `changed_paths_truncated`, else a persistent failure retries an oversized write every tick forever) and is written **before** the event announcing it. `git_diff_numstat` extracted from `worktrees` so a room and the Worktrees screen read one measurement. Rooms close on `DeleteSession`, the Telegram delete and `RemoveWorktree`. Config `session_room.{poll_interval_ms,git_timeout_ms}` (+`TDDY_SESSION_ROOM_*`), rejected rather than clamped when out of range, with the git timeout enforced on the child so a wedged repo cannot leak blocking-pool threads.
