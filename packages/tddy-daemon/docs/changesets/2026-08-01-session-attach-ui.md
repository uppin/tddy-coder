# 2026-08-01 — **session-attach-ui

**Type:** Feature

restart-cleared staging root, cross-host staged attachments, streaming peer-forward, and two latent forwarding bugs fixed** — the host half of the attach UI, plus two defects found while building it. **Bug 1, silent hang:** `forward_to_peer` addressed a peer by its **bare** instance id, but a daemon serves `connection.ConnectionService` on **`daemon-{instance_id}`** (`main.rs`); the bare identity belongs to the *discovery* participant, which runs no `ServerEngine` — and with no deadline on the forward the symptom was a call that never returned **and never errored**. Every fixture peer in the suite had served under the bare id, which is exactly what hid it; four fixtures (`forward_to_peer_shared_registry`, `staging_forwarding_acceptance`, `relay_e2e_acceptance`, `multi_host_acceptance`) now stand a peer up the way `main.rs` does — a discovery participant on the bare id plus a separate RPC participant on `daemon-{id}` — and `forward_to_peer` carries `PEER_FORWARD_TIMEOUT`. **Bug 2, silent 4 MiB ceiling:** a cross-host staged attachment routed through the *unary* forwarded `ReadHostDocument` while the same file staged locally had no such limit, so a large document attached on one host and failed across two; it now goes through `forward_stream_read_host_document_via_livekit`, re-checking `max_attachment_bytes` **while** accumulating. New `forward_server_stream_to_peer` (built on the pre-existing `RpcClient::call_server_stream`, so no transport change) relays decoded frames into `MpscResultStream<T>` with a per-frame idle deadline, so a peer-side error terminates the local stream as an error and a stream that stops can never surface as a clean end; its channel is **deliberately unbounded** because the transport's bounded channel is filled by the room's *shared* response loop, and a relay that stopped draining would head-of-line-block every other in-flight forwarded RPC. Staging moved from `{tddy_data_dir}/staging/` to `std::env::temp_dir()/tddy-staging` (`default_staging_base_dir`, injected via `ConnectionServiceImpl::with_staging_base_dir`), retiring the abandoned-batch leak; `host_documents` split into `resolve_host_document` (all guards, no bytes) / `read_host_document_bytes` so the unary read, the streaming read and materialization share one `.staged-complete` gate — which is what replaced the old same-host staged rule, since the marker checked on the *owning* host is what actually prevents a truncated attachment; `start_session`'s body extracted verbatim into `start_session_core(req, progress)` with an `AttachmentProgressSink` (discarding on the unary path, so its behaviour is unchanged) and `AttachmentMaterialization` grouping six carried args to remove two `#[allow(clippy::too_many_arguments)]`; `stream_start_session` resolves the caller **before** classifying the route, so an unauthenticated request cannot drive an outbound forward; a cross-host fetch reports progress **per frame**, not per completed attachment, because the relay's deadline is per frame and whole-file reporting made an ordinary PDF fail with `DEADLINE_EXCEEDED` mid-creation; `max_attachment_bytes` config key (64 MiB default) enforced host-side and published on `DaemonAdvertisement` (omitted when zero, so unadvertised stays distinguishable from a cap of none); `WorktreeDirEntry.size_bytes` populated from a real `stat`; a compile-time `const _: () = assert!(...)` pins `HOST_DOCUMENT_FRAME_BYTES` + 8 KiB headroom <= `MAX_CHUNK_FRAME_BYTES`, verified to fail the build at 64 KiB, because a lost chunk frame wedges a call permanently with no error. Tests: `session_attach_cross_host_acceptance` 8 (two daemons over the LiveKit testkit, including a 4.5 MiB transfer that crosses hosts *inside* a forwarded stream — the combination no earlier test covered), `session_attach_staging_scope_acceptance` 11, `staged_attachment_path_validation` 8, `daemon_advertisement_attachment_cap` 4, `staging_rpc_acceptance` 7, `worktree_files_rpc` 8 (incl. a test pinning that `ListWorktreeDirectory` lists a project's **primary** worktree, previously assumed), `--lib` 424; hermeticity re-verified under `TMPDIR=/tmp` across two consecutive runs; `clippy --all-targets -- -D warnings` and `cargo fmt --check` clean.
