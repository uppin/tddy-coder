# 2026-07-27 — **remove-origin-hardcode

**Type:** Bug Fix

`project_storage` and `connection_service` resolve the effective remote instead of assuming `origin`** — `ProjectData` gains optional `remote_name: Option<String>` (serde, skip-if-none). New `project_storage::effective_remote_name_for_project(projects_dir, project_id, repo_root)` resolves the remote as main-worktree upstream (`tddy_core::worktree::detect_default_remote_name`) → stored `remote_name` → `origin` (last resort); `effective_integration_base_ref_for_project` calls `resolve_default_integration_base_ref_with_remote(repo_root, Some(&effective_remote_name_for_project(...)))` for legacy rows (stored `main_branch_ref` returned verbatim, validators now permissive). `connection_service.rs` threads the resolved remote through `push_new_branch_to_remote` (was `push_new_branch_to_origin`), `list_recent_remote_branches(repo_root, remote, limit)`, `validate_repoint_target` (compares via `local_branch_name_for_remote` on both sides), `effective_spawn_branch(..., remote)` (new `remote` parameter), and the telegram branch-list call. Tests: acceptance (`effective_spawn_branch`, `repoint_target_validation`, `project_default_branch_resolution`, `query_branch_resolution`, `set_project_default_branch`, `worktrees_rpc`, `unified_worktree_base`); `clippy -- -D warnings` + `cargo fmt --check` clean.
