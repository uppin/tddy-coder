# 2026-08-02 — **activities-tail-first-autoscroll

**Type:** Feature

the daemon serves the newest transcript page and the reverse cursor** — one `read_session_transcript` now feeds all three transcript modes through a `(first_seq, replayed_slice)` match: all of it (`SNAPSHOT_THEN_LIVE`), its newest page via `tail_page` (`TAIL_THEN_LIVE`), or none of it (`LIVE_ONLY`) — which still performs the read, because a live frame's `seq` is a position in the whole recording and claiming 0 against a transcript of hundreds is worse than one local file read; `COUNT_THEN_LIVE`, the mode billed as cheap, already pays exactly that read. New `get_acp_replay_page` handler mirrors `get_acp_tool_call_detail` for peer-forwarding, auth and the `strip_tool_body` seam, so a paged frame is not a back door to the tool bodies, with the passthrough wired in `connection_tonic_adapter`. **The live tail numbers by entry, not by delivery:** a tool call broadcasts twice (its `running` then its terminal record) but `latest_state_per_tool_call` coalesces both into one row, so incrementing per delivered record drifted one position ahead per completed call and gave a refinement a position of its own; the relay now carries a `tool_call_id → seq` map pre-seeded from the resolved transcript (positions, where the adjacent count relay's `seen_ids` needed only membership), so a refinement reuses the row's position and only a genuinely new entry advances the counter. One divergence is documented rather than papered over: coalescing keeps a call at its *last* record's slot, so a re-read orders tool rows by completion time while the live tail can only number by first-record time, and two interleaved calls get swapped positions — closing it would mean renumbering frames already sent, which the wire cannot express.
