# 2026-08-02 — **activities-tail-first-autoscroll

**Type:** Feature

the ACP replay wire gains a tail mode, absolute frame positions and a reverse cursor** — the transcript could only be replayed head-first and in full, so a client wanting the *end* of a large recording had to transfer all of it. `StreamMode.TAIL_THEN_LIVE = 3` (the proto3 zero value stays `SNAPSHOT_THEN_LIVE`, so every existing caller is untouched), `StreamAcpReplayRequest.page_size` (0 ⇒ server default), `AcpReplayFrame.seq` — the frame's absolute 0-based position in the *resolved* transcript, carried by every transcript frame and left 0 only by the payload-less `COUNT_THEN_LIVE` — and a new unary `GetAcpReplayPage`, unary specifically because a unary RPC peer-forwards and the replay streams still cannot (their idle deadline is sized for short-lived streams, so forwarding them needs a keepalive frame first). `at_oldest` is an explicit response field rather than `first_seq == 0`, because an **empty** page at the head would otherwise be indistinguishable from a one-frame page at the head. `acp_replay` gains `DEFAULT_REPLAY_PAGE_SIZE = 100`, `TranscriptPage`, `tail_page` and `page_before`, all over the already-coalesced `read_session_transcript` view so paging, counting and snapshot replay agree about what a frame *is*; `tail_page` delegates to `page_before(frames, len, size)` — the newest page *is* the page before the end — so clamping and defaulting exist once rather than twice. A `before_seq` past the transcript end clamps to its length, so a cursor held across a rewrite resolves to a real page instead of nothing; `before_seq == 0` and an empty transcript both page to an empty `at_oldest` page. `tool_call_id_of` became `pub` so a live relay can recognise the second record of a call it already numbered — `tool_call_ids()` returns only a set and cannot give positions. Tests: 8 new `acp_replay` unit tests; package 92/92. (tddy-service)
