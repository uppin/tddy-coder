# 2026-08-30 — the wire contract for agent context sync

**Type:** Feature

three server-streaming RPCs on `ConnectionService`. `StreamContextManifest` yields one `ContextManifestEntry` (`rel_path`, `sha256`, `size_bytes`) per allow-listed path, streaming rather than returning a repeated field so a large manifest never needs the transport's chunk codec. `StreamReadContextFile` returns raw `ContextFileChunk` bytes with no encoding applied, framed under `MAX_CHUNK_FRAME_BYTES` so a context read never engages chunking at all. `StreamReadContextFileBatch` reads several paths in one call — a split start costs 2 peer round trips rather than 1 + N, which on a 120-file skills tree was ~18 s and 121 chances to hit `PEER_FORWARD_TIMEOUT` before the agent process existed; its frames carry `rel_path` and `end_of_file`, so every file yields at least one frame and a zero-byte file stays distinguishable from a failure. The requests carry an `agent` **name**, never globs — a caller selects a compiled-in table row and can never name a path set — and the field is documented as advisory, because the serving daemon derives the row from the session it resolved rather than from what was asked.
