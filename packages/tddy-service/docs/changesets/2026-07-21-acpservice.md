# 2026-07-21 — **`AcpService`

**Type:** Feature

ACP as a protobuf RPC over the LiveKit session connection** — new `proto/tddy/acp/v1/acp.proto` mirrors the Agent Client Protocol 1:1 (`AcpService.Session(stream AcpClientMessage) returns (stream AcpAgentMessage)`, envelope `id` correlation, `SessionUpdate`/`ContentBlock`/`ToolCall`/`PermissionOption`/`StopReason`/`SessionModelState`), codegen via a `tddy_codegen` RpcService `build.rs` pass → `AcpServiceServer` (`NAME = "tddy.acp.v1.AcpService"`). `TddyAcpService` (`service_acp.rs`) is a Presenter view-adapter mounted beside `TddyRemoteServer` in `session_view_adapter_surface`: inbound ACP → `UserIntent`, outbound `PresenterEvent` → `AcpAgentMessage` via `convert_acp.rs` (stateless 1:1) + `OutboundState` (tool-call lifecycle with stable `tool-{n}` ids + `tool_call_update` completion/progress, synthesized `Plan`, agent-initiated `request_permission`, `PromptResponse(EndTurn)` at completion and the free-prompting turn boundary). Names mirror `agent-client-protocol` verbatim; `fs/*`/`terminal/*`/`agent_thought_chunk`/`available_commands_update`/`current_mode_update` are name-mirrored stubs, intentionally unhandled. Tests: `convert_acp` units + runtime `AcpService/Session` acceptance (`initialize` handshake, live `AgentOutput` → `AgentMessageChunk`, select → `request_permission`, free-prompting `EndTurn`).
