# 2026-08-02 — **`vm.proto`

**Type:** Feature

`BuildTddyHostImage` + `CreateVmFromPreparedBase`** — two additive methods on the existing `vm.VmService`: `BuildTddyHostImage` (server-streaming `BuildTddyHostImageProgress` with a nested `Stage` enum, so an hours-long bake reports serial-console output as it goes) and unary `CreateVmFromPreparedBase`. New messages `TddyHostLiveKit`, `VmRunPolicyProto` (`arch`/`accel` as strings, empty meaning host default), and the four request/response types. No `main.rs` or `build.rs` wiring needed — these are new *methods* on a service already registered and already covered by the RpcService and descriptor-set codegen passes. No field number is reused or renumbered and `VmPortForward` is unchanged, so the addition is wire-compatible. **`packages/tddy-web/src/gen/vm_pb.ts` is deliberately not regenerated** (`bun install` wedged on the development host); no web code consumes the new messages, so nothing is broken, but proto and TS client are out of sync until `bunx buf generate` is run.
