# Changesets Applied

Wrapped changeset history for tddy-supervisor.

**Merge hygiene:** [Changelog merge hygiene](../../../docs/dev/guides/changelog-merge-hygiene.md) — prepend one single-line bullet; do not rewrite shipped lines.

- **2026-08-13** [Fix] **the group list was truncated to the wrong number; the crate now compiles off Linux and refuses there** — `resolve_supplementary_groups` truncated to `getgrouplist`'s **return value**, which glibc sets to the number of groups found but Darwin's libc sets to `0` for "they fit"; both write the real count into `ngroups`, so on one of the two platforms the child was handed an **empty supplementary group list** — the same silent privilege downgrade the `bail` beside it exists to refuse, reached by another route. Truncating to `ngroups` is correct on both. Found by making the crate build on macOS, not by a test: `getgrouplist`/`setgroups` argument types differ between the two headers (`gid_t`/`size_t` vs `c_int`), now named as `GroupListId`/`GroupCount`. Off Linux each `pre_exec` step that needs a Linux facility returns `ErrorKind::Unsupported` ("will not spawn a session it cannot confine") rather than being skipped — nobody gets a reduced jail — and the six `policy` tests that assert what `openat2(2)` answers are `#[cfg(target_os = "linux")]`, since off Linux a mount source would be denied for want of a kernel rather than on its merits. Test fixtures replace `await_socket` with `await_ready`, which polls `SupervisorClient::connect` **and** `try_wait` for the whole window: dropping a `UnixListener` does not unlink the inode, so a supervisor that died after binding left the socket file behind and every later connect reported `ECONNREFUSED` with no mention of the exit. See [architecture.md](./architecture.md). PR [#385](https://github.com/uppin/tddy-coder/pull/385). (tddy-supervisor)
- **2026-08-03** [Feature] **tddy-supervisor — root privilege confined to a small brokered mini-init** — systemd starts one root unit which runs `tddy-daemon` as its unprivileged child and serves a `SO_PEERCRED`-gated socket for the four operations that need privilege; nothing is granted without a root-owned `spawn_policy`, and every refusal renders exactly `"request denied"` so an error cannot reveal what exists. Ordering is the security contract and it is *data*: `pre_exec_plan` returns an ordered `Vec<PreExecStep>` that `PreExecSteps` compiles and walks, so the order lives in one place and every edge is unit-pinned — root joins the cgroup scope, surrenders privilege, and only then may a namespace exist, because a user namespace created by uid 0 maps the child to *real* host root. Three things the unprivileged reference in `tddy-sandbox-cgroups` never faced: the uid map must come from the target uid and never `geteuid()` (pre-fork that is root, post-`unshare` the overflow uid the kernel refuses); `setuid` leaves a process non-dumpable so it gets `EACCES` on its own `/proc/self/uid_map` without a `PR_SET_DUMPABLE` re-arm; and a pre-fork descriptor belongs to the old mount namespace so `mount(2)` rejects it, which is why the `openat2(RESOLVE_NO_SYMLINKS)` that closes the mount-source symlink hole happens in the child immediately before the bind, making check and use the same object. `commit_creds()` zeroes `pdeath_signal` on any credential change, so `PR_SET_PDEATHSIG` is re-armed after *each* such step rather than once. The crate owns its own proto rather than using `tddy-service`, which linked 327 crates — a SQL engine, a TUI, an HTTP and TLS stack — into the uid-0 binary; it links 48. Config is validated at load and the file is `fstat`ed, refusing a policy that is not root-owned. Tests: 220 (187 unit + 33 acceptance). (tddy-supervisor)
