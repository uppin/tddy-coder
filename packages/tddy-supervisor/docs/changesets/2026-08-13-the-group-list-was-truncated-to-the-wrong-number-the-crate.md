# 2026-08-13 — the group list was truncated to the wrong number; the crate now compiles off Linux and refuses there

**Type:** Fix

`resolve_supplementary_groups` truncated to `getgrouplist`'s **return value**, which glibc sets to the number of groups found but Darwin's libc sets to `0` for "they fit"; both write the real count into `ngroups`, so on one of the two platforms the child was handed an **empty supplementary group list** — the same silent privilege downgrade the `bail` beside it exists to refuse, reached by another route. Truncating to `ngroups` is correct on both. Found by making the crate build on macOS, not by a test: `getgrouplist`/`setgroups` argument types differ between the two headers (`gid_t`/`size_t` vs `c_int`), now named as `GroupListId`/`GroupCount`. Off Linux each `pre_exec` step that needs a Linux facility returns `ErrorKind::Unsupported` ("will not spawn a session it cannot confine") rather than being skipped — nobody gets a reduced jail — and the six `policy` tests that assert what `openat2(2)` answers are `#[cfg(target_os = "linux")]`, since off Linux a mount source would be denied for want of a kernel rather than on its merits. Test fixtures replace `await_socket` with `await_ready`, which polls `SupervisorClient::connect` **and** `try_wait` for the whole window: dropping a `UnixListener` does not unlink the inode, so a supervisor that died after binding left the socket file behind and every later connect reported `ECONNREFUSED` with no mention of the exit. See [architecture.md](../architecture.md). PR [#385](https://github.com/uppin/tddy-coder/pull/385). (tddy-supervisor)
