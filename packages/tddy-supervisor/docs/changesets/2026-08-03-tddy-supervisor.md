# 2026-08-03 — **tddy-supervisor

**Type:** Feature

root privilege confined to a small brokered mini-init** — systemd starts one root unit which runs `tddy-daemon` as its unprivileged child and serves a `SO_PEERCRED`-gated socket for the four operations that need privilege; nothing is granted without a root-owned `spawn_policy`, and every refusal renders exactly `"request denied"` so an error cannot reveal what exists. Ordering is the security contract and it is *data*: `pre_exec_plan` returns an ordered `Vec<PreExecStep>` that `PreExecSteps` compiles and walks, so the order lives in one place and every edge is unit-pinned — root joins the cgroup scope, surrenders privilege, and only then may a namespace exist, because a user namespace created by uid 0 maps the child to *real* host root. Three things the unprivileged reference in `tddy-sandbox-cgroups` never faced: the uid map must come from the target uid and never `geteuid()` (pre-fork that is root, post-`unshare` the overflow uid the kernel refuses); `setuid` leaves a process non-dumpable so it gets `EACCES` on its own `/proc/self/uid_map` without a `PR_SET_DUMPABLE` re-arm; and a pre-fork descriptor belongs to the old mount namespace so `mount(2)` rejects it, which is why the `openat2(RESOLVE_NO_SYMLINKS)` that closes the mount-source symlink hole happens in the child immediately before the bind, making check and use the same object. `commit_creds()` zeroes `pdeath_signal` on any credential change, so `PR_SET_PDEATHSIG` is re-armed after *each* such step rather than once. The crate owns its own proto rather than using `tddy-service`, which linked 327 crates — a SQL engine, a TUI, an HTTP and TLS stack — into the uid-0 binary; it links 48. Config is validated at load and the file is `fstat`ed, refusing a policy that is not root-owned. Tests: 220 (187 unit + 33 acceptance). (tddy-supervisor)
