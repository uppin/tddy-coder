# 2026-08-29 — **the crate itself

**Type:** Feature

a managed mirror of a session's worktree** — `tddy-session-sync --session-id <id> --dest <dir>` watches a session's LiveKit room and keeps a local directory equal to its worktree, committed history over the git transport that already exists and uncommitted edits over the deltas this feature adds. Split pure-by-default like `tddy-remote-git-repo`: `credentials`, `attach`, `sync`, `mirror` and `apply`, with everything decidable without I/O a function over injected inputs. The mirror is parked with `HEAD` on the session's own commit and the agent's uncommitted edits in the working tree — the only state every delta applies onto — and deltas are fetched per **tick**, not per call, because several calls share a poll window and asking per call would apply the first and drop the rest along with the residual. Reconciling is a `git fetch` of `refs/tddy/session/{id}/wip` plus a reset, so a lost broadcast, a rejected patch or a hand-edited directory all recover by moving only the objects the clone lacks; each reason carries the values it saw (`SequenceGap`, `BaseCommitMismatch`, `PatchRejected`) because a divergence logged without numbers is one nobody can debug. The destination is owned — marker file, local edits discarded, and both an unmarked non-empty directory and one marked for another session refused rather than adopted. Module [mirroring.md](../mirroring.md); feature [session-worktree-sync.md](../../../../docs/ft/daemon/session-worktree-sync.md). ⚠️ Known: `StreamReadWorktreeFile` is served but not called, so a `.gitignore`'d path is absent rather than fetched; the first attach does not retry a WIP ref that has not been published yet; the client holds `LIVEKIT_API_SECRET`.
