# 2026-08-16 — models-and-assistants

**Type:** Feature

a Models & Agents screen at `#/models` listing every provider, model and assistant across every common-room daemon, merged by web-side fan-out with one client per daemon and per-row actions routed to the owning daemon. Reads degrade **per list** via `Promise.allSettled`, so one daemon's failed assistant read leaves its models visible and an unreachable daemon costs one row rather than the page; `registryReadStatus` keeps not-connected / loading / read-failed / empty distinct, so a first-run daemon does not look broken. Row keys and test ids are daemon-qualified because provider ids and assistant names are unique only per daemon. Chat reuses `useAcpSessionOverClient` over `AcpService` — no second transport — and a tool-bearing assistant first picks a workspace from `ListProjects(local_only)` on its owning daemon, the same file the daemon confines against, so every offered path is one it will accept. `toolCallUpdate` folds into the bubble its `toolCall` announced, sharing `toolCallPresentation.ts` with `acpReplayProjection` so live and recorded transcripts cannot drift. Chat needs a positive `llm` label, and an unrecognised enum renders its raw value with a skew message rather than "Unknown". Module [models-screen.md](../models-screen.md).
