# 2026-08-01 — **session-attach-ui

**Type:** Feature

attach documents to a session at creation time, from the local machine or from any connected host** — `CreateSessionPane` (shared by the drawer's New session flow and the PR-stack Start session dialog) gains an attachments section for **every** session type and in peer mode: a file picker, a drag-drop zone, one row per attachment with an editable basename, size and per-row progress, and a `HostDocumentPicker` covering all four `HostDocumentScope` values. New `hooks/useSessionAttachments.ts` owns the state, the cap and the streamed-start consumer (extracted so the pane came back from 1,347 to ~1,150 lines); `hooks/useStagedAttachmentUpload.ts` reuses `chunkFile`/`UPLOAD_CHUNK_SIZE` and `randomUuid()` unchanged (never `crypto.randomUUID` — tddy-web runs on an insecure origin); the two tree scopes reuse `WorktreeFileTree` + `worktreeFilesApi` rather than a new tree, and `worktreeFilesApi.listDir` now surfaces `WorktreeDirEntry.size_bytes` instead of discarding it, which is what lets the cap apply to all four scopes. **Nothing uploads until submit**, and staging is memoized per row keyed on **both** `File` identity and staging host — without the host key a resubmit after a daemon switch would stamp a `staging_id` onto a host that never received the bytes; without the memo, choosing "rename" at a branch conflict re-uploaded every attachment under a fresh id (~18 min for 50 MB at the ~47 KB/s this transport measures) and orphaned the first batch. `streamStartSession` is used **only** when attachments are present, so the no-attachment path is byte-identical to before (guarded by a spec whose streaming stub throws); the stream is consumed with the `cancelled`-flag idiom and **not** `AbortController`, because `tddy-livekit-web`'s `handleServerStreaming` accepts `_signal` and never reads it — the in-memory test router *does* honour it, so an `AbortController` implementation would pass its spec while the real stream ran on. `duplicateBasenames` folds case (`toLowerCase`, locale-independent), deliberately stricter than a Linux host: the host writes with `create_new(true)`, so on macOS's case-insensitive APFS a `Spec.md`/`spec.md` pair returns `FAILED_PRECONDITION` and fails the **whole** `StartSession` — a green test had previously asserted the opposite and named it "matching the host filesystem contract". `daemonHostsFromParticipants` now propagates `maxAttachmentBytes`, which had been dropped and left the advertised cap unreachable by the form. Picker traps pinned by spec: an `ATTACHMENT`-kind context doc needs the `attachments/` prefix while a `MANIFEST` one does not, a doc with `exists == false` is never offered, and `SESSION_WORKTREE` lists under the **session's own** `project_id` because `resolve_listed_worktree` checks the worktree against that project's main repo. Tests: Cypress `CreateSessionAttachmentsAcceptance` 12, `CreateSessionHostDocumentPicker` 8, `CreateSessionAttachmentProgress` 4, with mid-stream progress asserted on `data-attachment-percent` behind a gated stub generator and the re-upload test falsification-checked; 90 across the 13 existing `CreateSession*` specs and 28 across the `worktreeFilesApi` consumers unchanged; 563 bun units; `bun run build` clean. **Not covered anywhere: the browser->daemon leg** — every spec stubs the RPCs, so a manual two-daemon `./web-dev` run is outstanding ([TODO.md](../../../../docs/dev/TODO.md)).
