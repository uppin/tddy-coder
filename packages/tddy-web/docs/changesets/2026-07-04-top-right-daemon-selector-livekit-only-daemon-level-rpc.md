# 2026-07-04 — Top-right daemon selector + LiveKit-only daemon-level RPC

**Type:** Feature

a `DaemonSelector` (shadcn `Select`) on every daemon-mode screen's header lists the common-room daemon-role participants and re-targets all daemon-level RPC (`ConnectionService`, `TaskService`, `VmService`, etc.) at `daemon-{instanceId}` over LiveKit instead of same-origin HTTP, so an operator can route to a peer daemon without a page reload; new `SelectedDaemonProvider`/`useSelectedDaemon`/`useDaemons`/`useDaemonClient` (`src/rpc/selectedDaemon.tsx`) own the shared common-room connection and selection (defaults to the serving daemon via a new `daemon_instance_id` field on `/api/config`, persisted per-tab in `sessionStorage`). Migrated `ProjectsAppPage`, `WorktreesAppPage`, `VmsAppPage`, `TasksDrawerScreen`/`TaskDrawer`, `RpcPlaygroundAppPage`, `ConnectionScreen`, and `SessionsDrawerScreen` (+ `useTerminalControl`, `DemoVmControls`, `SessionWorkflowFilesModal`) off `useHttpClient` onto `useDaemonClient`; every call site null-guards the client, which is `null` until a daemon is selected and the shared room is connected. Per-session terminal/presenter communication is unchanged (stays on its own session room). Found and fixed two latent bugs surfaced by the migration: a zero-delay reconnect storm in `useTaskListStream.ts` (now floored at `MIN_RECONNECT_DELAY_MS`), and a missing test-injection seam for `App`'s internally-constructed `SelectedDaemonProvider` (new optional `testDaemonRoom`/`testDaemonHosts` props). `bun test` 422/422, Cypress component suite 400/400 (63 specs), `cargo test -p tddy-coder -p tddy-daemon` clean (one pre-existing, environment-flaky LiveKit peer-discovery test unrelated to this change).
