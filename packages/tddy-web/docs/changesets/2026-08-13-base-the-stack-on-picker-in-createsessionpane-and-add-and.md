# 2026-08-13 — "Base the stack on" picker in `CreateSessionPane`, and "Add & start session" on the New-planned-PR form

**Type:** Feature

`CreateSessionPane` renders a `create-session-pr-stack-base-session-select` when `sessionType === "tool" && recipe === "pr-stack" && !peerMode`, sending `StartSessionRequest.pr_stack_base_session_id` on the tool branch only and only while the recipe still owns a stack (the daemon *refuses* the id beside another recipe, so a value chosen before switching must not be submitted — same shape as `managedCodebase ? selectedSubagents : []`); the mount effect now stores the raw `ListSessions` list and derives both pickers with `useMemo` instead of discarding everything but `prStackOrchestrators`, and switching project or host clears the choice so the control always shows what submit would do. New pure `stackBaseSessionCandidates(sessions, { projectId, daemonInstanceId })` in `utils/stackParents.ts` narrows `sessionsWithBranch` to the form's effective project and host and drops sessions another orchestrator's stack already owns — an empty `projectId` offers **nothing**, since matching `""` would offer every session whose project is equally unknown. `AddPlannedPrForm` gains `startSession: boolean` and a second submit (`pr-stack-add-planned-pr-start-btn`); `PrStackScreen.handleAddPlannedPr` looks the appended node up by `AddPlannedPrResponse.node_id` and hands it to the existing `setStartSessionNode`, replacing a diff of the returned plan against a `stack` view that only refreshes on the next session-list refetch — the orchestrator agent appends to the same stack, so first-new and last-new could both open a dialog pre-filled with somebody else's branch and then spawn against it, and a malformed plan degrading to `{nodes: []}` selected the stack's bottom node. A response whose plan omits the node it named updates the list and withholds only the session start. Tests: 13 + 8 Cypress component specs and 7 `stackParents` unit cases; four assertions strengthened after mutation testing (a vacuous pre-fill check whose stub echoed the form input, a `contain.text` over a whole dialog, a `{ timeout: 0 }` absence check, and one spec that passed with the feature reverted).
