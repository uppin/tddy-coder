# 2026-07-27 — **planned-pr-base-branch-selection

**Type:** Feature

the Start-session dialog opened from a planned-PR row renders a "Base branch" `<select>` so the operator can choose which parent branch a diamond / multi-parent node bases its child worktree off** — `CreateSessionPane` gains the selector (test id `create-session-base-branch-select`), gated on `initialValues.stackParent && !peerMode && baseBranchOptions.length > 0`, sending the chosen value as `StartSessionRequest.selected_integration_base_ref` (empty in peer mode and when the list is empty, preserving the root → default-branch behavior). New pure helper `prioritiseBaseBranchOptions(node, nodes)` (in `components/sessions/prstack/`) orders the options: direct dependency branches first (non-merged parents that own a branch, ordered by the dependency's own DAG depth, deepest first, ties by `node.parents` order), then every other materialized stack branch excluding the node itself, its descendants, merged nodes, and duplicates. `CreateSessionInitialValues` gains `baseBranchOptions`/`selectedBaseBranch`; `PrStackScreen` computes them from the parsed stack. `baseBranchLabel` (the branch-intent caption) is unchanged and independent of the selector. Tests: `prioritiseBaseBranchOptions.test.ts` 9 (bun), `PrStackStartSessionBaseBranchSelectAcceptance.cy.tsx` 6 (Cypress component); `bun run build` clean.
