# 2026-08-29 — a full-screen TUI scrolls itself on a mobile drag

**Type:** Fix

touch had no equivalent of the desktop wheel gate: every one-finger drag called `scrollLines` on the pane it started in, so in the Claude CLI's TUI (alternate screen + mouse tracking) it scrolled the **live** pane of the lazy-history double buffer — `scrollback: 0` by design — and therefore did nothing at all: the TUI never learned the user tried to scroll, and the double buffer's "Load earlier output" was the only way back through the output. `GhosttyTerminal`'s drag effect now samples `hasMouseTracking()` and the wasm terminal's `isAlternateScreen()` **once, at `touchstart`** (so one gesture is never split between routes) and routes each line of finger travel, capped at `TOUCH_SCROLL_MAX_NOTCHES_PER_MOVE` per `touchmove` so a fling cannot flood the TUI: **`tui-mouse`** → an SGR wheel report (button 64 up / 65 down) at the touch point, through the new component-scope `sendWheelSgrAt` that the `sendWheelSgr` handle method (the desktop wheel path) now also calls — one implementation, two callers; **`tui-keys`** (alternate screen, no tracking — a pager like `less`) → the arrow key ghostty-web emulates the wheel with; **`viewport`** (normal screen) → `term.scrollLines`, unchanged, so the history page pane and ordinary shell scrollback behave exactly as before. **The first attempt re-dispatched a synthetic `wheel` on the grid canvas** and left the routing to the handlers that already gate the desktop wheel (ghostty-web's own, the SGR forwarding on the container, `GhosttyTerminalGrpc`'s capture-phase gate) — no second copy of the gate to drift; CI showed the event reached none of them, the mouse-tracking spec seeing only the tap's press/release (`\x1b[<0;28;5M` … `13m`) and the pager spec nothing at all while the normal-screen spec passed, which places the drag handler and the canvas rect (the tap coordinates come from it) beyond suspicion and the dispatch nowhere — so the two TUI routes are sent to the application directly, which is what a spec can pin. Tests: Cypress `TerminalTouchScrollRoutingAcceptance.cy.tsx` 3 (SGR wheel-up and no Up-arrow for a tracking TUI; `\x1b[A` for a pager; scrollback + no bytes in the normal screen), driver gains `expectInAlternateScreen()` / `expectSentToApp()` / `expectDidNotSendToApp()`.
