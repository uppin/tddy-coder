# 2026-07-24 — **terminal-file-drop-insecure-origin

**Type:** Fix

the dropped file's path actually reaches the terminal** — two independent bugs both ended in "drop a file, nothing happens". (1) `uploadFiles` minted the per-drop `upload_id` with `crypto.randomUUID()`, a **secure-context-only** API, so on a plain-http LAN origin the drop handler threw before any chunk was sent (mobile Attach shares the hook, so it failed identically) — new `lib/randomId.ts` `randomUuid()` prefers the native call, falls back to `crypto.getRandomValues` (available on insecure origins), then `Math.random`. (2) `UPLOAD_CHUNK_SIZE` 256 KiB made each request ~5 LiveKit chunk frames, and one lost frame leaves the daemon's `ChunkReassembler` permanently incomplete, so the RPC was never answered and the upload stalled mid-file with no error — chunk size drops to **48 KiB** with a new `UPLOAD_REQUEST_ENVELOPE_HEADROOM` (8 KiB), pinned against `MAX_CHUNK_FRAME_BYTES` imported from `tddy-livekit-web`, and `useDaemonUploadChunk` now sends every chunk with `{ timeoutMs }` (`UPLOAD_CHUNK_TIMEOUT_MS` = 20 s) so a stalled chunk fails that one file via the existing skip-and-report path. Verified end-to-end on a LAN browser → dev daemon claude-cli session (2 MB PNG, 41 chunk RPCs, path typed into Claude Code's prompt).
