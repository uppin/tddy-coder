# 2026-07-04 — Multi-daemon session host selection + reliable add-to-host + PR-stack create modal

**Type:** Feature

`CreateSessionPane` gains a Host `<select>` (from `useDaemons()`, shown only when the common room advertises a daemon) whose `daemonInstanceId` is threaded into `StartSession` and `ListProjectBranches`; no-provider/single-daemon usage unchanged. Projects "Add to host" now addresses the chosen target host **directly** (`useDaemonClientFor` → `daemon-{instanceId}` via the transport factory) instead of double-hopping through the selected daemon, and exposes an optional clone-location input (`user_relative_path`); each host shows its advertised base clone location (`DaemonHost.reposBasePath`, parsed from `repos_base_path`). PR-stack "Start session" opens the shared creation form pre-filled from the planned node (new `CreateSessionDialog` wrapping `CreateSessionPane` + `CreateSessionInitialValues`) instead of firing `StartSession` directly. Cypress `CreateSessionHostSelectionAcceptance` 3/3, `PrStackStartSessionModalAcceptance` 3/3 (replaces deleted `PrStackStartSessionAcceptance`), `ProjectsScreenAcceptance` +3, `CreateSessionPane` 28/28, `participantRole` +2.
