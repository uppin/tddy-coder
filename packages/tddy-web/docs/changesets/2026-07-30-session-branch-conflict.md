# 2026-07-30 — **session-branch-conflict

**Type:** Feature

creating a session on a branch another session owns opens a three-choice prompt instead of silently producing `<branch>-1`** — `CreateSessionPane` sends `onBranchConflict: "reject"` for every non-peer creation (peer spawns send `""`: they create no branch), and a response carrying `branchConflict` opens the new `BranchConflictDialog` **without** calling `onCreated`, so the form stays mounted with its values intact. New `lib/branchConflict.ts` is the pure choice→request mapping (`startSessionOverridesFor`): switch returns `null` (no request — the owning session id goes to `onCreated`, the existing select-and-attach path), add-agent sends `work_on_selected_branch` + `selectedBranchToWorkOn` with `newBranchName` cleared, rename sends `new_branch_from_base` with the typed name; the dialog's rename field is pre-filled with the daemon's `suggestedBranchName` and the form's own branch field is kept in sync. `handleSubmit`'s request building was extracted to `startSession(branchOverrides)` / `submitCreation(branchOverrides)` with the three per-session-type branches unchanged; resolving clears the conflict before re-submitting, so a second conflict remounts the dialog with a fresh suggestion. Hand-rolled overlay following `VncPassphraseDialog`/`CreateSessionDialog` (no new dependencies, theme tokens). Tests: Cypress `CreateSessionBranchConflictAcceptance` 9 + a peer-spawn negative in `SessionsDrawerPeerSpawn`; `branchConflict.test.ts` 3; `vite build` clean; `CreateSessionAcceptance`/`CreateSessionPane`/`CreateSessionAutoClosesDrawer`/`PrStackStartSessionModal` unchanged at 15/29/1/3.
