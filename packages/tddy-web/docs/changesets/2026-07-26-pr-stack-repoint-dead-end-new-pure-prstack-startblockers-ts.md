# 2026-07-26 — pr-stack-repoint-dead-end: new pure `prstack/startBlockers.ts`

**Type:** Fix

`startBlockers` returns **every** reason a node cannot be started, each carrying the operator-facing text (replacing a boolean + one branch name that could state a single reason and no message), and `resolveRepointTarget` returns the branch a repoint would land on, which both labels the control and is sent as `target_base_branch`. Both compose the existing `resolveStackBase` / `branchlessNonMergedParent` rather than re-walking the DAG, so the cycle and dangling-parent guards are inherited; `no-ancestor-branch` is reported only when no direct parent is the blocker, or the warning would state one fact twice. `PlannedPrRow` renders the planned PR's full information whatever its startability — plus a new `pr-stack-base-branch-<id>` line — with Start-session **disabled** (blockers joined into its `title`) beside `pr-stack-start-warning-<id>`; the `pr-stack-missing-branch-<id>` replacement indicator is **gone** (D16). `PrStackScreen` gains `defaultBranch` (threaded from `SessionMainPane`'s already-loaded `projects` via `WorkflowViewContext`, which also gives a root node's dialog a named base for the first time), sends `targetBaseBranch`, **catches** repoint failures into a per-node `pr-stack-repoint-error-<id>` (it previously `await`ed with no `catch`, so the new `invalid_argument` refusal would have left the row looking untouched), and guards re-entrancy with `repointingNodeIds` — a double-click had run two rebase + force-push sequences against one branch. `baseBranch` → `baseBranchLabel` (it holds prose such as "no predecessor branch yet"). **`test:unit` is now invoked by the `test` scripts**; it was reachable by nothing, so every unit test under `src/components/` (477) ran only when someone typed it.
