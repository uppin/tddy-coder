an absent resolution is *unknown*, never orphaned, so the first render is deterministic) and, in `prstack/deriveStackBaseBranch.ts`, `resolveStackBase(node, nodes) -> StackBase` (`default-branch` | `ancestor-branch` | `no-ancestor-branch` — the discriminated form of the walk, because the flattened label collapses a root, an all-merged chain and a chain with no ancestor branch to the same string while only the last is unstartable; `deriveStackBaseBranch` is now a thin wrapper, unchanged in behaviour) plus `branchlessNonMergedParent(node, nodes)` (the flat direct-parent form of the daemon's own gate — `Stack::base_ref_for_spawn` refuses on **any** non-merged branchless parent while `resolveStackBase` walks past one to a sibling that owns a ref, so both are needed: the base names the dialog's label, this decides startability). `PlannedPrRow` renders the branch (`pr-stack-branch-<nodeId>`), the planned suggestion marked as planned (`pr-stack-planned-branch-<nodeId>`), `"Missing branch: <base>"` in place of the CTA (`pr-stack-missing-branch-<nodeId>`), and `"PR status unavailable"` with the reason as its tooltip (`pr-stack-pr-unavailable-<nodeId>`); the CTA slot is now mutually exclusive across button / blocked indicator / status chip.
