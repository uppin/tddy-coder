# 2026-08-19 — **session-creation agent catalog

**Type:** Feature

fleet fan-out with host labels** — the New-session **Agent** select now lists every common-room host's agents, each option captioned `{label} · {host}`, because `ListAgents` carries no routing field and a daemon answers only for itself: a browser pointed at one host could not offer — not merely could not find — an assistant created on another. `AgentInfo` has no host field, so `useSelectableAgents.ts` attributes each row to the identity its read was **addressed to** (exact, and no proto or daemon change); option values are qualified `{id}@{host}` while daemons are advertised and bare when none are, and a pick is resolved by looking the row up rather than parsing the value, since an agent id may itself contain `@`. The selection is **derived** from `(offered agents, host, agent id)` by `selectableAgentOptions.ts` rather than stored beside them — that is what makes picking an agent set the Host, a Host change re-point the agent to the same name on the new host (else its first, else none), and the opening selection the connected daemon's first agent, with no effect correcting state after the fact and nothing to lose a race against. The wire format is unchanged: `agent` stays bare, `.daemon_instance_id` carries the host. In the peer-spawn flow the catalog is scoped to the host the peer will run on, and `hostRunningSession` decodes the empty `daemon_instance_id` an orchestrator can carry — the protocol's other spelling for the connected daemon, decoded by name rather than by a `||` chain. `ListAgents` left the mount-time `Promise.all`, so one failing read no longer discards `ListProjects` and `ListTools` with it. The cross-daemon read itself was extracted to `src/rpc/useHostFanOut.ts` and `useAvailableAgents.ts` rebuilt on it (175 lines to 71, behaviour and specs unchanged), and the Agent control to `CreateSessionAgentSelect.tsx`; `useModelRegistryFanOut` deliberately keeps its own read — several RPCs per host, merged by provider identity, with writes back to the owner — and now shares only `noConnectionTo`. Tests: 14 Cypress acceptance (AC1–AC12) + 12 unit; seven existing fixture specs updated to qualified values, two of which needed a LiveKit-capable mount for their advertised peer host to answer at all.
