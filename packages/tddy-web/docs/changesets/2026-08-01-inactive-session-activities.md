# 2026-08-01 — **inactive-session-activities

**Type:** Feature

a dormant session's pane shows the transcript it recorded, the inspector stays shut, and Resume moves into the top bar** — selecting an inactive session used to auto-open the Inspector **docked as the full main pane** over a pane whose only content was the string *"Select Resume to reconnect"*, and the session's recorded ACP transcript was reachable only through a top-bar popover that **hides itself** when there is nothing counted yet — so the one surface worth reading for a dead session was the one you could not get to. The daemon already replays it from disk (`StreamAcpReplay` over `acp-transcript.jsonl`, no LiveKit), `useAcpReplay` already projects it, and `ResumeSession` was already routed to the owning daemon: nothing was wired together. New pure module **`sessionBaseView.ts`** (`sessionBaseViewMode(session, hasWorkflowView) → "workflow" | "activities" | "terminal"`, `canResumeSession`) makes the rule testable without React, and new **`SessionActivitiesPane`** renders the transcript as the pane — same `AgentChatView`/detail-dialog as the overlay, but pulling the snapshot **eagerly** (the overlay defers because it is a popover the operator may never open; this *is* the view, so deferring only adds a blank frame). A workflow view still wins outright: `PrStackScreen` renders planned PRs from persisted state and `WorkflowChatScreen` is already a transcript, so the Activities view replaces exactly one surface — the terminal. Resume is keyed on **liveness alone**, so a dormant pr-stack orchestrator gets the button in the same top-bar position as a dormant terminal session; the Inspector's own Resume stays. `defaultInspectorOpen()` returns `false` for every session and the idle-auto-open branch is deleted (an attach **error** still opens the drawer — that is a failure to surface, not a liveness state); **docking is removed entirely**, because it only ever existed to fill a pane that is no longer empty, and a full-pane drawer would bury the transcript. Runtime foreground suppression is rekeyed from "the inspector is docked" to "the session is dormant" — the same predicate by accident, now named for its real cause — and the runtime layer stays mounted *behind* the Activities view so background sessions keep streaming. Nothing new enters the URL: the view is derived from liveness, so a resumed session corrects itself with no state to migrate. Validation caught four defects the first implementation shipped with: an attach claim that was never released left a **second** Resume within one selection doing nothing (now a `{sessionId, listGeneration}` claim released by a *later* snapshot reporting the session dormant — an attachment-based guard deadlocks, since nothing resets a stale `connected-livekit` when a session dies); every Resume fired a **redundant `ConnectSession`** that minted a fresh browser identity and forced a terminal reconnect plus a second `ClaimTerminalControl`; the empty state asserted *"This session recorded no activity"* before the count feed had answered **and identically when it failed**, so `agentActivityRegistry` gained `countLoaded` (set on the first frame whatever it says) and the pane now claims nothing until the count is known; and two of the inverted inspector tests were tautologies asserting their own precondition. Also **`connectionStatusForSession` now requires `isActive && pendingElicitation` for `needs-input`** — a session that died mid-elicitation used to read as live, which under these rules left it with neither the Activities view *nor* a Resume button; this reaches the drawer dot, the live/remaining partition and sorting, and was taken deliberately rather than adding a second liveness predicate that would disagree with the first. Tests: Cypress `InactiveSessionActivitiesAcceptance` 18 (incl. three regressions pinning the claim strand, the duplicate attach and the premature empty state), `SessionInspectorDockedDisconnected` renamed to `SessionInactiveInspectorOverlay`, nine existing specs updated where they pinned the old defaults; bun `sessionBaseView.test.ts` 14; suite at **855 Cypress / 776 unit**, `vite build` clean. **Not pinned by any test: the removal of docking** — `data-docked` was its only harness-observable discriminator and the component harness loads no stylesheet, so every Tailwind width is inert and geometry assertions there would pass or fail for unrelated reasons ([TODO.md](../../../../docs/dev/TODO.md)).
