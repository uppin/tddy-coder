# 2026-07-12 — **Fast session change

**Type:** Feature

per-session runtimes, session-participant RPC routing, participant metadata overlay, live inspector bytes** — `SessionRuntimeRegistry` (keyed by `sessionId`) replaces the single `useSessionAttachment` for LiveKit sessions; each `SessionRuntimeState` holds its own `Room` (joined `browser-{sessionId}-{ts}`), `GhosttyTerminalLiveKit`, session-participant `ConnectionService` client, traffic meter, byte counters, `lastDataReceivedAt`, control state. One `<SessionRuntime>` per attached session; focus switch = CSS visibility, no unmount/reconnect/resize; background terminals keep streaming; explicit-disconnect eviction (no cap). Session-scoped RPCs (`ExecuteTool`/`ListExecTools`/`ListSessionToolCalls`/`ClaimTerminalControl`/`WatchTerminalControl`/VNC/screen-sharing) route to `daemon-{instanceId}-{sessionId}` via `sessionParticipantRpcClient` (`liveKitFactory(room, sessionServerIdentity)`); `DeleteSession`/`SignalSession` + bootstrap/directory stay daemon-direct on `daemon-{instanceId}`. `useRoomParticipants` parses a `session` metadata field (`sessionParticipantMetadata`); `SessionManager.mergeActiveAndFetchedSessions` overlays it onto synthesized + fetched rows (no `ListSessions` fan-out for active rows). Inspector Details tab shows bytes in/out + "last data received: Ns ago" (`lastDataReceivedFormat`); dual-source — live runtime for attached sessions, daemon `SessionEntry` (`bytes_in`/`bytes_out`/`last_data_received_at`) fallback for sessions with no LiveKit participant. Cypress `SessionRuntimeRegistryBackgroundTerminals`/`SessionParticipantRpcRouting`/`SessionInspectorByteCountAndLastReceived`/`SessionInspectorInactiveDaemonSourced`/`SessionsListParticipantMetadata`/`SessionStartResumeStillDaemonRouted` (6 new, all green) + 96 bun units.
