# 2026-08-30 — **agents-tab-subagent-tree

**Type:** Feature

the Inspector's Agents tab became a tree rooted at the session's main agent, holding both the roster agents attached to it and the subagent sessions it spawned** — the tab was a flat roster list, while the other half of "who is working for this agent?" sat in `SessionAgentsSection` in the detail pane, labelled with `SessionEntry.status` ("active") — the session's *lifecycle* string, which says nothing about the agent inside it — and neither surface expressed the relationship, so a subagent that spawned its own subagent rendered as its sibling. Both populations now hang off one root: a **managed** roster agent from `StreamSessionAgents` reporting `SessionAgentEntry.status`, and a **non-managed** subagent session from the drawer's `ListSessions` reporting the inferred `SessionEntry.agent_status` the daemon derives by tailing its conversation. The proto ships one `SessionAgentStatus` for both so one badge can render them alike; `agentStatusDisplay.ts` and a shared `AgentStatusBadge` are where that becomes one badge, since two renderers wording `EXECUTING_TOOL` differently is the failure worth designing out. `agentTree.ts` is the pure fold: one recursive `childrenOf(parentId, onBranch)` whose branch set is **seeded with the root**, collapsing root-exclusion, self-reference and cycle-termination into a single rule — `ListSessions` is assembled from several hosts' answers, so a cycle is a shape to survive, not one to assume away — and an orphan is dropped rather than promoted, where it would claim this agent spawned it. **A collapsed subagent costs nothing:** each session node is its own component holding its own `useSessionAgentRoster` gated on `expanded`, so "opens no stream" is an unmounted subscription rather than a flag, and `rosterHalfOf` applies **per node** because a subagent can be split independently of its parent. Detach is raised as a `RosterDetachRequest` carrying the entry, *its own* roster and the half holding it — "the last agent of a remote daemon" is a fact about that roster, not the root's; a subagent row offers Switch and no Detach. **Found in review and fixed:** an expanded subagent whose roster read failed rendered as a subagent with *no agents* — a silent fallback, and the conflation the pane already refuses at its own root, applied one level down; it now says why on the row that has it, behind a `rosterFailuresBySession` fixture so one node's host can fail while the rest of the tree reads fine. Removed: `SessionAgentsSection`, `sessionPeers` and their two specs — the tree is the one place subagents are listed, and `onSwitchPeer` now reaches it from the Agents tab. No proto, no Rust, no new RPC. Tests: 980 bun units, 28 new Cypress cases across two specs, 73 over eight regression suites, `bun run build` clean.
