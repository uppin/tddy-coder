# 2026-08-30 — **session-agent-conversation-tab

**Type:** Feature

the session header attaches a roster agent to the session on screen and opens a conversation tab with it, replacing the peer-session spawn** — "Add agent" called `StartSession` with an `orchestrator_session_id` through `#/sessions/:id/add-agent` and `CreateSessionPane`'s peer mode, spawning a whole second coding session on the same worktree; that predated the agent roster, which adds a specialized agent to the session that already exists. The button now runs picker → `AttachSessionAgent` → `OpenAgentConversation` → a fourth tab kind, whose body owns `Prompt`/`Cancel` for that conversation's life. `AgentPicker` is extracted from `SessionAgentRosterPane` so one fanned-out catalog serves both mounts, under an explicit `testIdPrefix` because both can be open at once. Two pure modules carry the logic: `agentConversationTranscript.ts` folds `AgentConversationChunk` frames into turns (an empty answer is still exactly one frame, so "said nothing" is a turn), and `agentConversationTabs.ts` keeps one tab per agent because a second `AttachSessionAgent` is a no-op on the roster. **Deliberately not built:** a replay of the *main* agent's sub-agent turns — a roster agent has no session dir, nothing appends an ACP frame for one, `SessionAgentEntry` carries no conversation id, and the answer is discarded after framing; the daemon work that would change that is in `docs/dev/TODO.md`. **Three defects found in review and fixed:** Enter bypassed the one-turn-at-a-time gate the Send button enforced, and since the projection extends *the open agent turn* a second prompt merged two answers into one; the tab's cleanup cancelled unconditionally and without awaiting the open, so a fast open-then-close could orphan a conversation and the agent session spawned for it; and a double-click on Attach could focus a conversation the list never kept. A fourth surfaced from the PRD's own NFR: `runtimeLayer` was swapped out for a workflow view, unmounting every conversation body — it now holds one stable slot in the element tree in every branch, because React unmounts a subtree that moves. Removed: the add-agent route helpers, `CreateSessionPane.peerMode` and its ~14 gates, and `SessionsDrawerPeerSpawn.cy.tsx`; `SessionAgentsSection`/`sessionPeers` stay, since peers still arrive from `spawn_conversation`. Tests: 341 bun units, 33 new Cypress cases across three specs, 89 over ten regression suites, `bun run build` clean.
