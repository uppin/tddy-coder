# 2026-08-01 — **web-url-state-routing

**Type:** Feature

every navigable selection round-trips through the URL, and the URL is the source of truth** — only the top-level screen was routed: `SessionsDrawerScreen` held `selectedSessionId` in state and never wrote the hash (navigating between sessions left the address bar at `#/sessions`), and it read `#/sessions/:id` **once, in a `useState` initializer**, so Back and an edited address bar moved nothing. Two new pure modules carry the grammar — **`routing/appLocation.ts`** (`AppLocation { path, params }`, `parseAppLocation`/`formatAppLocation`, `withParams` with `null` = delete, `withPath` distinguishing a *screen change* (drops screen-scoped params, keeps `host`) from a move *within* a screen (keeps them, so the inspector does not close because you clicked the next drawer row), `screenRootOf`, and the nine param-name constants) and **`routing/useAppLocation.ts`** (a **module-level** store over `window.location.hash` read through `useSyncExternalStore` — module-level, not a context, so a nested pane and a component test mounting one screen bare share one source of truth without prop-drilling; push assigns `location.hash`, replace uses `history.replaceState`, both notify synchronously). `appRoutes` gains `/sessions/new` (with `new` **reserved** — session ids are UUIDs), `/sessions/:id/add-agent`, `/tasks/:id`, `INSPECTOR_TAB_NAMES` + `isInspectorTabName` (declared here, not in `InspectorTabs.tsx`, so the param is validatable from a pure module), and two shared segment helpers replacing four hand-rolled prefix walks. **`routing/selectedHost.ts`** lifts `resolveSelectedDaemonInstanceId` out of the `.tsx` provider and puts `?host=` at the top of the precedence chain (rules 2–5 untouched, including "an empty daemon list is *no information yet*"); `selectDaemon` writes the param (push) **and** `sessionStorage`, a resolved default is written back (replace), and a host change navigates to the screen root because a session id from the old host names nothing on the new one. **`SessionsDrawerScreen`**: selection, create mode and inspector state all derive from the location, and the click handler + the one-shot deep-link effect collapse into **one** activation effect keyed on the session id — which is what makes Back re-attach. **`SessionMainPane`**: `?code=1`, and peer mode becomes a derivation over the add-agent path, deleting a `useState` and the two effects that used to clear it. Also `SessionInspectorDrawer` (`?inspector=`/`&full=1`), `TasksDrawerScreen`/`TaskOutputPane` (`#/tasks/:id`, `?channel=`), `WorktreesAppPage` (`?project=`), `RpcPlaygroundScreen`/`AppPage` (`?service=&method=&participant=`). Push for a click, **replace** for what the app does on your behalf (auto-open/close inspector, `#/`→`#/sessions`, written-back defaults, clearing session-pane params once nothing is selected) so Back never steps through states nobody chose; unresolvable values degrade (unknown tab → Details, unknown channel → first, unregistered project → first listed) and the resolved answer is written back. Deliberately excluded: draft form input and confirmation dialogs (a shared link must not re-arm a destructive confirm). Review fixes: session-pane params outliving their session, and the playground's draft request surviving a URL-driven method change (one method's body under another's name). Tests: bun `appLocation.test.ts` 23 + `appRoutes.test.ts` 47 (+16) + `selectedHost.test.ts` 14 = **84**; Cypress **38** new across 6 specs (`SessionUrlState`, `SessionInspectorUrlState`, `TaskUrlState`, `SelectedHostUrlState`, `WorktreesUrlState`, `RpcPlaygroundUrlState`) plus a new `appLocationPage` page object — the only place specs touch `window.location`/`history` — and a shared hash reset in `cypress/support/component.ts` so one spec's hash cannot pre-select state in the next; `vite build` clean. `src/rpc/selectedDaemon.test.ts` is **removed**, its 7 cases relocated to `routing/selectedHost.test.ts`: it imported a `.tsx` module, so it could not run under `bun test` and was in no `bun test` path — recorded with the wider `src/rpc` gap in [TODO.md](../../../../docs/dev/TODO.md). Cypress component suite 151/152 green; the outstanding one, `TerminalControlAcceptance`, passed **4/4 on this code** but its two re-runs died at module-load (`Failed to fetch dynamically imported module`) because a second worktree's Cypress held Vite's default 5173 — it has never failed on an assertion, so it is confirmed once rather than repeatedly.
